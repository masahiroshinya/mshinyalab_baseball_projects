# ソフト3：分析対象区間の選択

## 概要・目的・位置づけ

### このソフトは何をするのか

同期済み映像の中から、**実際にモーションキャプチャ（姿勢推定）を行いたい区間の「開始フレーム」と「終了フレーム」を決定し、CSV に保存する**ツールです。

映像ファイルそのものは作成しません。**フレーム番号だけを記録します。**

### なぜ「区間を絞る」のか

| 理由 | 詳細 |
|:---|:---|
| **計算コストの削減** | 全フレームを姿勢推定にかけると、240fps × 53秒 = 約12,700フレームになる。必要な区間（例: スイング前後の3秒）だけに絞ることで処理時間を大幅に短縮できる |
| **精度の向上** | 関係のないフレーム（待機中・準備中）を排除することで、解析結果が見やすくなる |
| **再現性の確保** | フレーム番号をCSVに保存しておくことで、後から同じ区間を確実に再現できる |

### ワークフロー上の位置づけ

```
ソフト1（音声同期）→ cam1_synced.mp4, cam2_synced.mp4
        ↓
ソフト2（キャリブレーション画像取得）→ calib_cam1_001.jpg ...
        ↓
【ソフト3（本ソフト）】← 今ここ
        入力: cam1_synced.mp4, cam2_synced.mp4（バッティング動作撮影回）
        出力: task_frame_numbers.csv
        ↓
Step01〜04（YOLOv8・マーカーレスモーションキャプチャ）
```

### 入出力の整理

| | 内容 |
|:---|:---|
| **入力** | ソフト1で同期済みの映像ファイル（バッティング動作撮影回） |
| **出力** | `task_frame_numbers.csv`（開始・終了フレーム番号のみ） |

## 🎓 初学者向け：なぜCSVにフレーム番号を保存するのか

### 「区間」をCSVで管理することのメリット

```
task_frame_numbers.csv の中身:
  type,frame_number
  start,3420
  end,4140

→ 「フレーム3420からフレーム4140まで」が分析対象
  = 3420 ÷ 239.76fps ≈ 14.3秒 〜 4140 ÷ 239.76fps ≈ 17.3秒
  = 約3秒間のバッティング動作
```

このCSVを後工程（YOLOv8・姿勢推定）に渡すことで、  
「どのフレームを処理するか」を人手で再入力する必要がなくなります。

### フレームと時刻の関係

```
フレーム番号 → 時刻変換:
  時刻（秒）= フレーム番号 ÷ FPS
  例: フレーム3420 ÷ 239.76fps = 14.26秒目

240fpsでの1フレームの長さ:
  1 ÷ 239.76 ≈ 0.00417秒 = 約4.17ミリ秒

→ 240fpsの精度で「バッターのスイング開始」を1フレーム単位で指定できる
```

## 各ステップの処理内容

### 3-1a：対象映像の読み込み

ソフト2と同じく `cv2.VideoCapture` で同期済み映像を開きます。  
ただしここで読み込む映像は**バッティング動作を撮影した回**のものです（チェスボード回とは別ファイル）。

```
入力: cam1_synced.mp4, cam2_synced.mp4（バッティング動作回）
変数: n_frames_analysis = min(cam1のフレーム数, cam2のフレーム数)
      ← この変数は後のセル（3-1c）でスライダーの上限として使われる
      ← 最初に実行しないと NameError になる（実行順序が重要な理由）
```

### 3-1b：表示処理と変数の準備

```
準備する変数:
  analysis_caps  = [cv2.VideoCapture(cam1_synced.mp4),
                    cv2.VideoCapture(cam2_synced.mp4)]
                ← スライダーを動かすたびに開閉しないよう、あらかじめ開いておく

  start_frame = None  ← 開始フレーム（ボタンを押すと値が入る）
  end_frame   = None  ← 終了フレーム（ボタンを押すと値が入る）

表示関数:
  get_analysis_combined(frame_no):
    両カメラの frame_no 番のフレームを取得
    → np.hstack で横並び結合
    → matplotlib で表示
```

### 3-1c：UI部品の作成

```
UI構成:
  [スライダー: 0 ─────────────────── n_frames_analysis-1]

  [◀◀ -10] [◀ -1] [+1 ▶] [+10 ▶▶]

  [🟢 開始フレームに設定]   [🔴 終了フレームに設定]

  開始: 3420 | 終了: 4140
  選択区間: 720 frames (3.00s)   ← 設定後に表示
```

### 3-1d：UIの連携と起動

スライダー操作のたびに `get_analysis_combined()` を呼び出し、両カメラの映像を更新表示します。

```
操作の流れ:
  1. スライダーでフレームを進める
  2. 「バットを構え始めた瞬間」または「投球が来る前」のフレームで
     [🟢 開始フレームに設定] を押す
  3. さらにスライダーを進める
  4. 「スイング完了・フォロースルー終了」のフレームで
     [🔴 終了フレームに設定] を押す
  5. 「選択区間: N frames (X.XXs)」が表示されれば設定完了
  6. 3-2 へ進む
```

**ポイント:**
- 開始・終了フレームは後から `global start_frame / end_frame` に格納されるため、  
  何度でも設定し直せます（最後に押した値が使われます）
- 終了 > 開始 になっているか確認してから保存してください

### 3-2：CSVの保存

```python
task_frame_numbers.csv の内容:
  type,frame_number
  start,3420
  end,4140

保存後のバリデーション:
  ✅ start < end になっているか
  ✅ 区間が0フレームになっていないか
  ✅ ファイルが正常に生成されているか
```

## 開始・終了フレームの選び方ガイド

### バッティング動作での選択基準（例）

| フレーム選択ポイント | 開始・終了の目安 |
|:---|:---|
| **開始フレーム** | バッターが「打撃準備姿勢（スタンス）」に入った瞬間。足が止まり、バットを構えた最初のフレーム |
| **終了フレーム** | スイング後、フォロースルーが完了し、動作が落ち着いたフレーム |

### 余裕を持たせる

```
厳密な開始より 10〜20フレーム前（≈ 0.04〜0.08秒前）
厳密な終了より 10〜20フレーム後（≈ 0.04〜0.08秒後）
```

少し余裕を持たせておくことで、後工程で「少し前後を確認したい」ときに対応できます。

## トラブルシューティング

| 症状 | 原因 | 対処 |
|:---|:---|:---|
| `NameError: n_frames_analysis` | 3-1c を 3-1a より前に実行した | 3-1a から順番に実行し直す |
| 開始・終了が `None` のまま保存しようとした | ボタンを押していない | 3-1d に戻ってボタンを押す |
| 終了 ≤ 開始になっている | 設定順序が逆になった | 開始 → 終了の順に設定し直す |
| スライダーが動かない | `n_frames_analysis` が 0 または未定義 | 動画ファイルのパスと 3-1a の実行を確認 |
| 映像が表示されない | `analysis_caps` が定義されていない | 3-1b を実行してから 3-1d を起動する |
