# ソフト2：キャリブレーション画像の取得

## 概要・目的・位置づけ

### このソフトは何をするのか

3Dモーションキャプチャの精度は「カメラキャリブレーション」の品質に直結します。
キャリブレーションとは、**「カメラが現実空間をどのように歪めて撮影しているか」を数値化する作業**です。
その数値（カメラ行列・歪み係数）を求めるために、**ChArUcoボード（チェスボードとARマーカーを組み合わせたボード）の画像を複数枚用意する**必要があります。

**このソフトは「同期済み映像の中から、ChArUcoボードが綺麗に映っているフレームを選んで保存する」ツールです。**

### ワークフロー上の位置づけ

```
ソフト1（音声同期）→ cam1_synced.mp4, cam2_synced.mp4
        ↓
【ソフト2（本ソフト）】← 今ここ
        入力: cam1_synced.mp4, cam2_synced.mp4（チェスボード撮影回）
        出力: calib_cam1_001.jpg ... / calib_frame_numbers.csv
        ↓
Step06〜07（キャリブレーション本番・3D再構成）
```

### 入出力の整理

|                  | 内容                                                                                |
| :--------------- | :---------------------------------------------------------------------------------- |
| **入力**   | ソフト1で同期済みの映像ファイル（チェスボード撮影回）                               |
| **出力①** | `calib_cam1_001.jpg`, `calib_cam2_001.jpg` ... （フル解像度のチェスボード画像） |
| **出力②** | `calib_frame_numbers.csv`（保存したフレーム番号の記録）                           |

## 🎓 初学者向け：なぜチェスボード画像が必要なのか

### カメラの「歪み」とは

カメラのレンズは完璧ではありません。特に広角レンズは、**画面の端にいくほど物体の位置や形が歪んで撮影**されます。
OSMO Action 3 のような広角カメラでは、この歪みが特に顕著です。

```
現実のチェスボード（完璧な正方形が並ぶ）:
┌─┬─┬─┬─┐
├─┼─┼─┼─┤
├─┼─┼─┼─┤
└─┴─┴─┴─┘

カメラが撮影した画像（歪んでいる）:
 ╭──╮──╮──╮
 ╰──╯──╯──╯──── ← 端が曲がって見える（樽型歪み）
```

### コーナー検出とは

ChArUcoボードの「白と黒のマス目の角（コーナー）」を画像認識で自動検出します。
従来のチェスボードと異なり、**各マス目の中に配置されたARマーカーのIDを識別することで、ボードの一部が隠れていたり、画面端にはみ出していても位置を正確に特定できる**という強力な利点があります。

コーナーの「現実での位置（3D座標）」と「画像上の位置（2D座標）」の対応関係を集めることで、カメラの歪みを逆算できます。

```
現実の3D座標 (X, Y, Z=0)   →   画像上の2D座標 (u, v)
マーカーID=5 の左上             (245, 312)
マーカーID=6 の左上             (289, 312)
...
```

**この対応ペアを、複数のフレーム（視点）・複数のカメラから集めるのがこのソフトの役割です。**

### なぜ「複数枚」必要なのか

| 枚数                                      | 理由                                                             |
| :---------------------------------------- | :--------------------------------------------------------------- |
| **最低10枚（`nRequiredFrames`）** | 1枚では視点が1つしかなく、歪みを正確に推定できない               |
| **上限30枚（`nMaxFrames`）**      | 多すぎると計算時間が増え、ノイズが混入するリスクも上がる         |
| **チェスボードの向きが多様なこと**  | 正面だけでなく、傾けた・回転させた画像が含まれるほど精度が上がる |

### RMS（再投影誤差）とは

キャリブレーションの精度指標です。単位は「ピクセル」。

```
RMS = 「推定した歪み係数で再計算した点」と「実際に検出した点」の平均距離（ピクセル）

例: RMS = 0.5px → 平均0.5ピクセルのズレ（良好）
    RMS = 1.0px → 平均1ピクセルのズレ（許容範囲の上限）
    RMS = 2.0px → 平均2ピクセルのズレ（不良・フレームを選び直し）
```

> **現在の状況（2026-05-01時点）:** 11枚のフレームで RMS = 0.789 px
> ぎりぎり許容範囲。より良い精度を目指す場合は、ぼやけたフレームや端が映っていないフレームを除外し、
> チェスボードが大きく・正面以外の角度から写っているフレームを優先的に選ぶと改善されます。

## 作業ステップ一覧

| ステップ | 内容                                             | 所要時間 |
| :------- | :----------------------------------------------- | :------- |
| 2-1      | 同期済み映像の読み込みとライブラリ準備           | 2分      |
| 2-2a     | パッケージ読み込みとパラメータ設定               | 1分      |
| 2-2b     | 横並び表示関数の作成                             | 1分      |
| 2-2c     | UI部品（スライダー・ボタン）の作成               | 1分      |
| 2-2d     | UIの連携と起動（フレームを選んで保存候補に追加） | 5〜10分  |
| 2-3      | チェスボードのコーナー検出と検証                 | 2〜5分   |
| 2-3b     | RMS事前確認（クイックキャリブレーション）        | 1〜2分   |
| 2-4      | キャリブレーション画像の保存                     | 1〜2分   |

**合計: 約15〜25分**

> ⚠️ **実行順序が重要**: 2-1 → 2-2a → 2-2b → 2-2c → 2-2d → 2-3 → 2-3b → 2-4 の順に実行してください。

## 各ステップの処理内容

### 2-1：同期済み映像の読み込み

`cv2.VideoCapture` で同期済み映像を開き、フレーム数・FPS・解像度を取得します。
**2台分が同じフレーム数であることを確認**（ソフト1の出力が正しければ一致しているはず）。

```
入力: cam1_synced.mp4, cam2_synced.mp4
処理: cv2.VideoCapture → n_frames, fps, width, height を取得
確認: 両カメラで n_frames が一致すること
```

### 2-2：フレームブラウザUIの構築と操作

**目的:** スライダーで映像を「コマ送り」しながら、チェスボードが映っているフレームを探す。

```
表示方式:
  Cam1の縮小画像 ─┐
                   np.hstack（横に結合） → 横並び1枚の画像として表示
  Cam2の縮小画像 ─┘

UI部品:
  [◀◀ -10] [◀ -1] [+1 ▶] [+10 ▶▶]  ← スライダー + コマ送りボタン
  [✅ このフレームを選択]  [↩ 最後の選択を取消]  ← 保存候補の追加/削除
  選択済み: 3 / 10〜30 フレーム  ← 現在の選択状況
```

**良いフレームの選び方:**

- チェスボード全体が両カメラに映っている
- ピントが合っている（ぼけていない）
- チェスボードが傾いていたり、正面以外の角度から写っている
- チェスボードが画面の端（隅）でなく中央〜周辺バランスよく配置されている
- 全10〜30枚で**様々な向き・位置**が揃っていること

### 2-3：コーナー検出と検証

選択した各フレームに対して `cv2.aruco.detectMarkers` と `cv2.aruco.interpolateCornersCharuco` を実行します。

```
処理フロー（フレームごと）:
  BGRフレーム → グレースケール変換 → detectMarkers()（マーカー検出）
                                              ↓
                                     成功 → interpolateCornersCharuco()（コーナー検出）
                                     失敗 → そのフレームをスキップ

出力:
  ✅ Frame  1234: Cam1:✅ | Cam2:✅  ← 両カメラで十分なコーナーを検出
  ⚠ Frame  5678: Cam1:✅ | Cam2:❌  ← Cam2で失敗 → このフレームは除外
```

失敗の主な原因:

- チェスボードの一部が画角の外に出ている
- 露出オーバー・アンダーで白黒の判別ができない
- ピントが合っていない

### 2-3b：RMS事前確認

検出に成功したフレームで即席のキャリブレーションを実行し、フレームごとの再投影誤差を棒グラフで表示します。

```
棒グラフの見方:
  赤色のバー（1.0px超）   → そのフレームがキャリブレーション精度を下げている → 差し替え推奨
  オレンジ横線            → 全体のRMS（全フレームの平均誤差）
  緑の点線（0.5px）       → 理想の目標値
  赤の点線（1.0px）       → 除外推奨の閾値

アクション:
  RMS ≤ 0.5px  → 優秀。このまま保存
  RMS ≤ 1.0px  → 許容範囲。条件が揃えば使用可能（現在: 1.016px）
  RMS > 1.0px  → 赤バーのフレームをフレームブラウザで差し替えて再確認
```

### 2-4：キャリブレーション画像の保存

コーナー検出に成功したフレームをフル解像度（1920×1080）のJPEGとして保存します。

```
出力ファイル構成:
  calib_cam1_001.jpg  ← Cam1の1枚目
  calib_cam1_002.jpg  ← Cam1の2枚目
  ...
  calib_cam2_001.jpg  ← Cam2の1枚目（Cam1と同じフレーム番号）
  calib_cam2_002.jpg
  ...
  calib_frame_numbers.csv ← 保存したフレーム番号の対応表

calib_frame_numbers.csv の中身:
  index,frame_number
  1,1423
  2,2891
  ...
```

## ChArUcoボード設定パラメータ

| パラメータ   | 変数名            | 説明                             | 本プロジェクトでの値       |
| :----------- | :---------------- | :------------------------------- | :------------------------- |
| 横のマス数   | `squares_x`     | ChArUcoボードの横方向のマス数    | 8                          |
| 縦のマス数   | `squares_y`     | ChArUcoボードの縦方向のマス数    | 6                          |
| マスの実寸   | `square_length` | チェスボードマスの1辺の長さ（m） | 0.060 (60mm)               |
| マーカー実寸 | `marker_length` | 内部のARマーカーの1辺の長さ（m） | 0.045 (45mm)               |
| 辞書         | `dictionary`    | 使用するマーカーの種類           | `cv2.aruco.DICT_4X4_250` |

> **注意**: 実物を印刷した際も、**定規で測って「マス目60mm」「マーカー45mm」にぴったり合っているか**確認してください。数ミリのずれが大きな誤差につながります。

## トラブルシューティング

| 症状                             | 原因                                               | 対処                                           |
| :------------------------------- | :------------------------------------------------- | :--------------------------------------------- |
| コーナー検出が全滅（❌ばかり）   | `chess_cols/rows` の設定が実際のボードと違う     | チェスボードの内部コーナー数を再確認           |
| 片カメラだけ検出失敗             | そのカメラの画角にチェスボードの一部が映っていない | 別フレームを選ぶ                               |
| RMSが常に1.5px以上               | 動画がぼやけている・フレームが偏っている           | チェスボードを傾けたフレームを意識的に追加する |
| `NameError: n_frames_analysis` | 実行順序を間違えた                                 | 2-1 → 2-2a → 2-2b ... の順に実行し直す       |
