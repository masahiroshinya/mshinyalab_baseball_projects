### 2. 3D座標が全て0の問題

**指示・質問：**
3D起こしの表示がおかしい（3D空間が空）。

**AIの対応：**
診断セルを実行してもらった結果、CSVの全座標が `-0.0` / `0.0` であることを確認。原因は `cv2.undistortPoints(..., P=mtx)` と `cv2.stereoRectify` の P1/P2 の組み合わせによる座標系の不一致（triangulation mismatch）と特定。

**決定事項・結果：**
`undistortPoints` から `P=` を削除し、P1_norm = [I|0]、P2_norm = [R|T] の正規化座標系で三角測量するよう `実装ステップ2` のコードを修正。

### 3. ステレオキャリブレーション RMS 422px の問題

**指示・質問：**
まだ3D起こしが想像と異なる。

**AIの対応：**
スケルトンが極端に小さく圧縮されていることを確認。段階的な診断を実施：
1. CSV統計 → 全座標がほぼ0（三角測量は機能しているが値がおかしい）
2. T ノルム診断 → T=1.28m, RMS=422px（完全失敗）
3. 有効ペア数診断 → 11ペア、各22〜33点（検出は正常）
4. 個別RMS診断 → Cam1/Cam2とも1.0px（一見正常）
5. dist1の値確認 → k1=93.4（発散した証拠）

**決定事項・結果：**
`calibrate_single_camera` 関数に `CALIB_USE_INTRINSIC_GUESS | CALIB_FIX_K3` フラグを設定する `calibrate_single_camera_constrained` 関数を提案。実行後 k1=0.285（正常）、ステレオRMS=1.89px（大幅改善）を達成。

### 4. SQUARE_LENGTH のコードミス発見

**指示・質問：**
黒ますが13.5cm、ランドマークが10.1cm（ボードの実寸測定結果）。

**AIの対応：**
ボードコーナーのサニティチェック（三角測量値 vs board_cornersの既知値）で triangulation のスケールは内部的に一致（0.0688 ≈ 0.069m）していることを確認。しかし実際の黒ます（1マス）= 135mm に対してコードの SQUARE_LENGTH = 0.069m（69mm）であることが判明。

**決定事項・結果：**
- 実寸確認：1マス = 135mm、マーカー = 101mm
- コードの `SQUARE_LENGTH = 0.069` → `0.135`、`MARKER_LENGTH = 0.051` → `0.101` に変更が必要
- この修正により全3D距離が 1.957倍（正しいスケール）になる見込み
- 次回セッション開始時に上記修正・再キャリブレーション・再三角測量を実施すること
