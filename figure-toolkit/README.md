# figure-toolkit：MATLAB と Affinity で論文用の図を作る

状態：試行中（2026-10-19 作成）。Windows 10・MATLAB R2025a・Affinity 3.3.1 で確認。Mac は未確認。
AI 向けの手順と規約は [AGENTS.md](AGENTS.md) にある。

## 1. 概要

MATLAB で描いた図の原案を、AI がこの toolkit を使って論文用の図に清書し、最後に Affinity で仕上げる。

AI エージェントは、利用量が多いので、有料プラン（Claude Pro 以上など）での利用を推奨する（目安は 5.5 節）。Opus より軽い Sonnet でも、清書と修正を最後まで行えた（2026-10 の試用）。

研究データの扱い：AI は原案のスクリプト、データ、図の画像を読むので、それらは AI のサービスに送られる。未発表のデータや個人情報を含むデータは、所属機関の規程に従って扱う。

想定ワークフロー：

- データを作り変えないために、データを描く部分は人が書いて確かめたスクリプトから始める。AI は原案のスクリプトとデータを変更しない。
- AI が書いた作図スクリプトはプロジェクトのフォルダに残る。AI は、原案と完成図のデータが一致することを確かめてから報告する。人間は、作図スクリプトを確認して、間違いないことを確認すること。
- 既定の体裁：図の幅は single column 90 mm または double column 190 mm、文字は Arial（パネル記号 9.75 pt、軸ラベル 9 pt、目盛り 7.5 pt）、線幅 1 pt。

必要なもの：

| もの              | 用途                                        | 確認した版                            |
| ----------------- | ------------------------------------------- | ------------------------------------- |
| MATLAB            | 分析・作図                                  | R2025a（追加の Toolbox は不要）       |
| Affinity（Canva） | 組み立てと仕上げ                            | 3.3.1                                 |
| AI エージェント   | 作図スクリプトの作成、Affinity の操作       | VSCode, Claude Code plugin (Opus 5.5) |
| Node.js           | AI が Affinity を操作するためのクライアント | 18 以上                               |
| Python 3 と pypdf | 組み立ての前の PDF の処理                   | pypdf 6.14                            |

## 2. 導入手順

### 2.1 以下の作業は人が行う

AI には行えない設定と、AI に権限を与える設定。上から順に行う。Affinity の設定は、メニューの 編集 > 設定（Ctrl+,）で開く（Windows。Mac は未確認）。

0. **ソフトウェアを用意する**：MATLAB と Affinity がなければインストールする。Claude Code（ほかの AI エージェントでもよいはずだが未検証）を導入し、toolkit を置いたプロジェクトのフォルダで起動できるようにする。
1. **ファイルを置く**：GitHub から取得し、研究用のプロジェクトのフォルダの中など、任意の場所に置く（以下 `<toolkit>`）。2 で、この中のフォルダを指定する。
2. **Affinity のスクリプトを有効にする**：設定 > スクリプト で、次の 2 つを行う。
   - 「Affinityスクリプティングを有効化」をオンにする。
   - 「ファイルシステムへのアクセス」の一覧に `<toolkit>/affinity/panel-tools` を加える。
3. **Affinity の MCP を有効にする**（AI が Affinity を操作するため）：設定 > モデルコンテキストプロトコル で次を行い、Affinity を再起動する。再起動するまで、AI は Affinity に接続できない。
   - 「Affinity MCPを有効にする」と「デスクトップ上のファイルへのアクセス」をオンにする。
   - 「Canva AIスタジオの機能を使う」はこのツールキットとは関係ない。オフのままでよい（オンにすると AI 利用枠を消費する）。
   - 使わないときは、「Affinity MCPを有効にする」と「デスクトップ上のファイルへのアクセス」をオフにしておく。MCP が有効な間は、ほかのプログラムや AI のセッションからも Affinity でスクリプトを実行できる仕様になっているため。オンに戻したら、Affinity を再起動する。
4. **パレットを読み込む**（任意）：Affinity のスウォッチパネルのメニューから、`<toolkit>/palettes/` の .ase を「アプリケーションパレットとして」読み込む。

Mac では、macOS の「プライバシーとセキュリティ」で、Affinity がデスクトップと `<toolkit>` を読めるようにする必要がある可能性がある（未確認）。

### 2.2 以下の作業は AI が代行可能

AI エージェントを、`<toolkit>` を置いたプロジェクトのフォルダで起動し、次のように頼む。

> `<toolkit>` を導入してください。

AI は次の作業を行い、結果を報告する。ソフトウェアのインストールや設定の変更の前には、了承を求める。

- 必要なソフトウェア：Node.js、Python と pypdf を確かめ、足りないものを入れる。
- MATLAB の設定：toolkit の関数を MATLAB で使えるようにする。
- Affinity との接続と例の図での確認：デスクトップに作業フォルダ（`affinity_mcp_work/`）を作り、例の図を組み立てて結果を確かめる。
- Panel style の登録：Affinity のスクリプトパネルに「Panel style」を登録する。

最後に AI が、人が確かめること（スクリプトパネルの Panel style が動くか）をチャットで案内する。確かめたら「確認しました」などと返す。AI が、確認に使った例の図を片付け、チュートリアルを始めるかを尋ねる。

## 3. 使い方

初めて使うときは、AI に「figure-toolkit のチュートリアルを始めてください」と頼むと、examples/ の原案を使って作業の流れを一通り案内する（[examples/tutorial.md](examples/tutorial.md)。20〜40 分）。作業の流れの詳細、プロンプトの例、試した結果は [examples/README.md](examples/README.md) にある。

作業の順番と図の保存：

- AI への清書と修正の依頼を先に済ませ、その後に Affinity で仕上げる。Panel style と手作業の変更は Affinity の中だけにあり、AI が図を作り直すと失われるため。
- Affinity で手を加える前に、図を保存先の `<図の名前>/` に別の名前（例：`<図の名前>_edited.af`）で保存する。AI が組み立てた .af（デスクトップの `affinity_mcp_work/panels/`）は、AI が図を作り直すと上書きされる。

各段階の要点：

- **清書の依頼**：原案のスクリプトの場所、使う figure、パネルの並べ方、成果物の保存先を伝える。情報が足りないときは AI が質問する。

  > analysis/draft_figures.m の figure 1〜4 を、2×2 のパネル（A〜D）に配置した図にしてください。figure-toolkit を使い、論文クオリティーで仕上げること。成果物は figures/ に保存すること。
  >
- **できあがるもの**：指定した保存先の `<図の名前>/` に、作図スクリプト（`make_<図の名前>.m`）と完成図（`output/` の PDF・PNG）ができる。Affinity では、組み立てた図（.af。デスクトップの `affinity_mcp_work/panels/` に保存されている）が開いたままになる。
- **修正の依頼**：同じチャットで続けて頼む（例：「A の横軸を -200〜50 ms に」「全パネルの目盛り線を内向きに」）。AI が作図スクリプトを直して図を作り直すので、修正は作り直しても残る。
- **Panel style**：Affinity で図を開き、スクリプトパネル（メニューの ウィンドウ > スクリプト）の「Panel style」を実行する。値を変えると画面に仮に反映され、OK で確定、キャンセルで元に戻る。確定した変更は 1 回の取り消しで戻せる。調整できる項目は [docs/adjustable-properties.md](docs/adjustable-properties.md)。
- **書き出し**：Affinity で仕上げたら、AI に「PDF と PNG で書き出して」のように頼む。短い依頼でも推奨の設定（PDF はベクターのまま文字を埋め込む、PNG・TIFF は 600 dpi、RGB）で書き出すので、多くの場合はそれで十分。投稿規程などで指定があれば、「TIFF の 1200 dpi で」「CMYK で」のように注文を付ける。別の名前で保存した図を書き出すときは、その名前を伝える。
- **.af の保存**：書き出されるのは PDF・PNG などで、.af は自動では保存先に保存されない。書き出しのとき、AI が「.af も同じフォルダに保存しましょうか」と尋ねるので、保存する場合は案内に沿って Affinity の ファイル > 名前を付けて保存 で保存する（AI は図を保存しない）。

原案なしで、図の種類の例（[figure-types/](figure-types/README.md)）から作図を始めることもできる。

## 4. FAQ

**Q. Affinity での変更が消えた。**
AI が図を作り直すと、Affinity で開いている同じ図は新しい図に置き換わる。Panel style や手作業の変更は、AI への修正の依頼をすべて済ませてから行う。前の図を残したいときは、別の名前で保存しておく。

**Q. AI が「保存していない変更があるため、閉じずに止めた」と言って止まった。**
作り直す図に、Affinity で加えた未保存の変更がある。残すなら別の名前で保存し、不要なら変更を破棄して閉じてから、もう一度頼む。

**Q. AI がデータを変えていないか、どう確かめるか。**
作図スクリプトの「データ」の段落を、原案の該当箇所（コメントに書いてある）と見比べる。AI は報告の前に、原案と完成図のデータを `compareFigureData` で比べている。軸範囲を狭めたときや点を横にずらしたときは、依頼どおりの差として報告される。

**Q. AI が Affinity に接続できない。**
Affinity が起動しているか、設定 > モデルコンテキストプロトコル で MCP が有効になっているかを確かめる。設定を変えた後は Affinity を再起動する。

**Q. AI の処理が PERMISSION_DENIED になる。**
設定 > モデルコンテキストプロトコル の「デスクトップ上のファイルへのアクセス」がオンか確かめる。Affinity が異常終了した後に、この設定がオフに戻ったことがある。

**Q. Panel style で「本体を読み込めませんでした」「仮の値のまま」と出る。**
「本体を読み込めませんでした」のときは、表示されたフォルダが、設定 > スクリプト の「ファイルシステムへのアクセス」の一覧（導入手順 2.1 の 2）に入っているかを確かめる。toolkit を別の場所に移した場合や、「仮の値のまま」と出た場合は、スクリプトパネルで Panel style を削除し、AI に登録し直してもらう。

**Q. Panel style を登録し直したいが、登録できない。**
同じ名前では登録し直せない。スクリプトパネルで古いものを削除してから登録する。本体（`panel_style_tool.js`）を更新しただけなら、登録し直す必要はない。

**Q. Panel style のフォントの一覧に目的のフォントがない。**
選択肢は学術論文でよく使うものに絞ってあり、入っているフォントだけが表示される。ほかのフォントは Affinity の標準の画面で変える。

**Q. 手を加えた図（.af）はどこにある？**
Affinity で保存した場所にある。AI が組み立てたままの .af は、デスクトップの `affinity_mcp_work/panels/<図の名前>.af` にあり、研究のフォルダ（保存先の `<図の名前>/`）には自動では入らない。この .af は AI が図を作り直すと上書きされるので、手を加えた図は、保存先の `<図の名前>/` に別の名前（例：`<図の名前>_edited.af`）で保存しておく。Affinity で開いている図の保存場所は、ウィンドウのタブにマウスを重ねるか、ファイル > 名前を付けて保存 で確かめられる。

**Q. .af に空のページが残っている。**
組み立ての前の PDF の処理（`tools/stack_component_pages.py`）が行われていない。AI に作り直しを頼むか、Affinity のページパネルで 2 ページ目以降を削除する。

**Q. 作業中に Affinity が異常終了した。**
2026-10-19 に 1 回、スウォッチの表示の処理で起きた（原因は Affinity 側と考えられる）。保存していない変更は失われるので、こまめに保存する。異常終了の後は、MCP の設定（「デスクトップ上のファイルへのアクセス」）がオフに戻っていないかも確かめる。

**Q. Mac で使えるか。**
Windows 専用の書き方は除いてあるが、Mac では動作を確かめていない。確認が必要な点は 5.4 節。

## 5. 仕様など

### 5.1 フォルダの構成

```
figure-toolkit/
├── README.md        本ファイル
├── AGENTS.md        AI 向けの手順と規約
├── CLAUDE.md        Claude 系のツール向けの入口（AGENTS.md を参照する）
├── docs/            作図の方針（入口は figure-style.md）
├── figure-types/    図の種類（時系列、棒グラフと個人の点、散布図）ごとの作成方針と既定値、ダミーデータの例
├── examples/        原案から図を作る手順の説明と例（examples/README.md）
├── matlab/          MATLAB の関数（パスを通すのはこのフォルダだけ）
├── affinity/
│   ├── compose/     組み立てと、組み立てた図の確認（AI が実行）
│   └── panel-tools/ スクリプトパネル用の Panel style
├── palettes/        スウォッチ用のパレット（.ase）
└── tools/           AI が Affinity を操作するクライアント、PDF の処理
```

AI と Affinity は、デスクトップの `affinity_mcp_work/` でファイルを受け渡す（Affinity が AI の操作で読み書きできるのはデスクトップの中だけのため）。作業の途中のファイルは、AI が作業の最後に削除する。デスクトップを OneDrive に移している場合など、場所が違うときは環境変数 `AFFINITY_WORK_DIR` で指定する。

スクリプトパネルに「Panel style」として登録するのは、本体（`affinity/panel-tools/panel_style_tool.js`）を読み込んで実行するだけの短いスクリプト（`panel_style_loader.js`）。登録のときに、AI がこの環境の本体の場所を入れる（toolkit のファイルは変えない）。本体を更新しても、登録し直す必要はない。

### 5.3 パレット

Okabe-Ito、Tol bright、Tol muted（論文用。色覚の多様性に配慮したもの）、Hiroshima Univ（ポスター用。広島大学の学章の指定色と、それに合わせて選んだ色）、Grey。各色に黒寄り・白寄りの段階と、灰色の段階が入っている。

好みのパレットがあれば、各自導入するとよい。AI にパレットファイルの情報収集や作成を依頼するのもよい。

### 5.4 Mac での利用

確かめていない点：

- MATLAB の文字の大きさ：Windows では 0.75 pt の倍数に切り捨てられるので、既定値はそれに合わせてある。Mac で同じになるかは未確認。導入の「例の図での確認」（導入手順 2.2）で、AI が文字の大きさを確かめる。
- Affinity の権限：macOS の「プライバシーとセキュリティ」で、Affinity がデスクトップと `<toolkit>` を読めるようにする必要がある可能性がある。
- フォント：Panel style の選択肢のうち、Yu Gothic・MS ゴシック・MS 明朝は Mac に標準では入っていない。

### 5.5 AI の利用量の目安

1 つの図の清書に、AI は会話の読み直しを含めて 100 万〜400 万トークンを使う（2026-10 の試用）。
