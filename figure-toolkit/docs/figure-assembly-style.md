最終確認、微調整、複数パネルの組み立て、ポスターの作成は Affinity で行う。

## 1. 図全体のレイヤー構成

図全体の構成（Affinity のレイヤーパネルと同じく、上ほど前面）。Panel の中は figure-panel-style.md の 4.1 節。

```
図（1 ページまたは 1 アートボード）
├── Labels                       パネル記号（Affinity で追加）
│   ├── A
│   ├── B
│   └── C
├── Annotations                  パネルをまたぐ注釈だけ（Affinity で追加）
│   └── A-B: zoom lines          Panel A の一部を拡大したものが Panel B であることを示す補助線
├── Panel A                      パネル 1 枚分（中は figure-panel-style.md の 4.1 節）
├── Panel B
├── Panel C
├── Notes                        作業用のメモ（非表示、書き出さない）
└── Figure area                  図全体の領域を示す矩形（段の幅 × 図の高さ、4 節）
```

1 つの図（1 ページまたは 1 アートボード）の最上位を、次のレイヤーで構成する（前面から順）。単一パネルの図も同じ構成にする（Labels・Annotations は必要なときだけ作る）。

| レイヤー名 | 中身 | 扱い |
|---|---|---|
| Labels | パネル記号（A, B, C …） | Affinity で追加する。Arial Bold、9.75 pt（figure-panel-style.md の 2 節） |
| Annotations | パネルをまたぐ注釈（拡大範囲を示す補助線、複数パネルにまたがる記号など） | Affinity で追加する。名前は関係するパネルが分かる形にする（例：`A-B: zoom lines`）。パネルを動かしたときは位置を確認し直す |
| Panel A, Panel B, … | 描画環境から取り込んだ図（1 パネル 1 レイヤー）と、そのグラフに付く注釈。中は成分ごとのサブレイヤー（figure-panel-style.md の 4.1 節） | 取り込んだ成分の中身は取り込んだ構造のまま保つ |
| Notes（任意） | 作業用のメモ・下書き | 非表示にし、書き出しに含めない |
| Figure area | 図全体の領域を示す矩形 1 つ（名前は `figure area (single column, 90 x 60 mm)` の形） | 最背面に置く。塗り・線なしで書き出しには写らない。誤操作を防ぐためロックする。ページの大きさをこの矩形に合わせる（4 節） |

注釈の置き場所の区別：1 つのパネルのグラフ（データや軸）に付くもの（有意差記号、スケールバー、データ点を指す矢印、グラフ内の追加の文字）は、そのパネルの `X: annotations` に置き、パネルと一緒に動くようにする。複数のパネルの関係を示すもの（拡大範囲の補助線など）は、最上位の Annotations に置く。

- レイヤー名は上の英語名で固定する。スクリプトはこの名前で対象を探す。

## 2. ルール

1. パネルは拡大縮小しない（figure-panel-style.md の 3 節）。
2. 整列・配置は軸の位置で揃う状態にする。figure-panel-style.md の 3 節の書き出し条件（ページの大きさと軸の位置を固定）を満たせば、各パネルを元のページの位置関係のまま、ページ単位の格子に並べれば軸が揃う。中身の外枠（目盛りラベルの幅で変わる）を基準にしない（Affinity での配置手順は未検証）。
3. 誤操作を防ぐため、Panel レイヤーはロックしてよい。ただし、ロックしてもスクリプトからは変更できる（開発時の試行 I7）。
4. 元の図を作り直したときは、Panel レイヤーの中の取り込んだサブレイヤー（axes、bars など）だけを差し替え、`X: annotations`、Labels、最上位の Annotations は残す。データ座標で位置が決まる注釈（有意差記号の高さ、矢印の先など）と、拡大範囲の補助線は、値と位置を確認して直す。
5. パネルを移動・並べ替えたときは、`X: annotations` はパネルと一緒に動く。Labels の記号と最上位の Annotations（パネルをまたぐ注釈）は一緒に動かないので、位置を確認して直す。

## 3. 投稿用の書き出し

- ベクターの図は `PDF(書き出し用)` で書き出す。フォントが埋め込まれ、文字は抽出可能な状態で残る。印刷用の規格が求められる場合は `PDF/X-4`。
- ラスターの図（TIFF・PNG）は、ドキュメントの dpi を投稿規程の値（例：600 dpi）に変えてから書き出す。`export` の画素数指定だけでは dpi の記録が変わらず、物理寸法が誤る（開発時の試行 G7）。TIFF の圧縮方式は Deflate 固定で、変更できない。
- CMYK が求められる場合は、ドキュメントの色形式を CMYK に変えてから書き出す（同 D5）。白黒印刷になる場合は、白黒調整レイヤーを一時的に重ねて判別できるか確認する（同 D4）。
- Arial にない文字（例：上付きマイナス「⁻」）は別のフォントで代替され、そのフォントも埋め込まれる（同 G1）。使用フォントは書き出した PDF で確認する。
- 書き出した PDF で、ページ寸法、フォントの埋め込み、最小の文字サイズ・線幅を確認する。
- 書き出しの範囲はページなので、ページの大きさを Figure area と同じにしておく（4 節）。
- AI に書き出しを頼む場合は、`affinity/compose/export_figure.js` を使う。推奨の設定は、PDF は「書き出し用」、PNG・TIFF は 600 dpi、色は RGB で、ユーザーの指定（dpi、CMYK、PDF/X-4 など）があれば従う。ラスターは、対象の図を PDF に書き出して開き直した文書の dpi を変えてから書き出すので、対象の図は変更されない（AGENTS.md の 4 節の 11）。

## 4. 図全体の大きさと Figure area

図は、原稿に拡大縮小せずに収める大きさで作る。文字サイズ・線幅が、設定した値のまま印刷されるようにするため。

- 幅：段の幅にする。既定は single column 90 mm、double column 190 mm（2026-10-18 決定）。ユーザーが明示的に幅を指定した場合（投稿先の規程など）は、それに従う。既定の値の変更は、ユーザーの指示があったときだけ行う。
- 高さ：図の内容に合わせる。目安として、single column で半ページ、double column で 1 ページを超えない。
- Figure area：最背面の Figure area レイヤーに、幅 × 高さの矩形を置く（1 節）。塗り・線なしで、ロックする。パネルの配置・整列の基準と、図全体の大きさの記録に使う。
- ページ：Figure area の矩形と同じ大きさにする（左上を基準に変えて、要素を動かさない）。PNG・PDF の書き出しの範囲はページで決まるため、書き出した図の寸法が Figure area と一致する。
- 単一パネルの図：MATLAB の図の幅は段の幅以下にする（超える場合は matlab/exportPanel.m が止まる）。幅と高さは MATLAB の図のスクリプトで指定し（段の種類 `spec.column`、既定は single）、JSON の `figureArea` を通して affinity/compose/compose_single_panels.js が Figure area とページを作る。
- 確認（2026-10-18、単一パネルの 4 図）：ページと矩形が 90.00 × 60.00 mm で一致し、書き出した PDF が 90.0 × 60.0 mm、PNG が 300 dpi で 1063 × 709 px（90.0 × 60.0 mm）になった。
