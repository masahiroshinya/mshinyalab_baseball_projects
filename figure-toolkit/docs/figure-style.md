# 作図方針（入口）

状態：試行中（2026-10-16 作成）。

## 適用範囲

この toolkit で作成・更新するグラフと、それを組み合わせた論文・発表・ポスター用の図に適用する。MATLAB・Pythonなどの描画環境、Affinity などの組み立て環境にかかわらず共通とする。個別の図について明示された指定を優先し、方針の追加だけを理由に既存図を一括変更しない。

## 作業の流れと読む文書

| 段階              | 作業                                                                        | 読む文書                                                 |
| ----------------- | --------------------------------------------------------------------------- | -------------------------------------------------------- |
| 1. パネルを作る   | 描画環境（MATLAB 等）で作図し、書き出す                                     | [figure-panel-style.md](figure-panel-style.md) の 1〜3 節 |
| 2. パネルを整える | Affinity で取り込み、パネル内をサブレイヤーに分け、グラフに付く注釈を加える | [figure-panel-style.md](figure-panel-style.md) の 4・5 節 |
| 3. 図にまとめる   | パネルを並べ、パネル記号・パネルをまたぐ注釈を加え、投稿用に書き出す        | [figure-assembly-style.md](figure-assembly-style.md)      |
| 特定の図の種類    | 図の種類ごとの作成方針・既定値、上の方針の例外                              | [figure-types/](../figure-types/README.md) の recipe.md   |

## 個別の注文の扱い

本文書群の方針、figure-types/ の作成方針（recipe.md）と既定値（defaults.json）、複数の図で共通に使う関数・スクリプト（matlab/、affinity/）を、まとめて「既定の作業の流れ」と呼ぶ。

- 図は、まず既定の作業の流れで作る（1 回目の出力）。ユーザーは 1 回目の出力を確認し、その図に固有の注文（例：この図の縦軸を [-500, 1500] にする）をコメントで出す。AI はその注文に対応する。
- 個別の注文は、その図だけに反映する。反映先は、その図の作図スクリプト（MATLAB 等）と、その図の Affinity のドキュメントとする。
- 個別の注文に対応するときも、明示的な指示がない限り、既定の作業の流れ（方針の文書、レシピ、共通の関数・スクリプトとその既定値）は変更しない。共通の関数の既定値と異なる指定が必要な場合は、その図のスクリプトの中で上書きする。
- 個別の注文が方針と異なる場合（例：符号付き量の縦軸を正負非対称にする）は、注文を優先する（「適用範囲」）。
- 個別の注文は、方針の文書・レシピに記載しない。セッションのまとめで方針の更新やレシピの作成を提案するときも、個別の注文は候補に含めない。ユーザーが既定にすると明示した場合に限り、「更新のしかた」に従って既定の作業の流れを変更する。

## 原案の作図スクリプトから図を作る

状態：原案（2026-10-19 作成）。3（作図スクリプトをプロジェクトに残す）と 5（途中のファイルの削除）はユーザーの指示で確定。1・2・4 はユーザーの確認待ち。

想定する依頼：ユーザーの研究用のプロジェクトのフォルダに toolkit が置かれ、AI はそのプロジェクトのフォルダで起動される。プロジェクトには図の原案を作るスクリプト（多くは学生が書いたもの。体裁は MATLAB の既定のまま）があり、「fig1 と fig2 をパネル A, B として横に並べて、ワークフローに従って論文用の図を作成して」のように頼まれる。AI が元データを加工していないことを、人が確かめられるようにする。手順とコマンドは [../AGENTS.md](../AGENTS.md) の 4 節。

1. 依頼の確認：
   - 成果物（作図スクリプトと完成図）の保存先は、ユーザーが指定する。依頼文に明示がなければ、作業の前に必ず尋ねる。尋ねるときは、保存先の案を示す（例：「図を作るフォルダを `<原案のフォルダ>/<図の名前>/` に作ってよいですか？」）。了承か指定の返事があるまで、ファイルを作らない。
   - 次の情報は、依頼文と原案から分からないときだけ、作業の前にチャットで聞く。
     - どの図（原案のどの figure）を、どのパネル記号にするか
     - 並べ方（行と列）
     - 図全体の幅（single / double column）。横に 2 つ以上並べるなら double とし、聞かない
   それ以外（凡例の位置、色、軸範囲、注釈の置き方など）は、既定と原案に従って作る。細かい点は、1 回目の出力を見た後のやり取りと、Affinity の Panel style での調整に回す。
2. 元データを変えない：
   - 原案のスクリプトとデータのファイルは変更しない（読むだけ）。
   - 論文用のスクリプトのデータの部分は、原案と同じ読み込み・計算にする（原案の行を写すか、原案の関数を呼ぶ）。AI は計算（集計、検定、平滑化、外れ値の除外、単位の変換など）を加えたり変えたりしない。原案にない計算が必要に見えるときは、作業を止めて聞く。
   - 原案に描かれた統計の結果（有意差記号、相関係数など）は、値と記号を変えずに Affinity の注釈にする。原案にない注釈は、依頼がなければ加えない。
3. 作図スクリプトをプロジェクトに残す：
   - 置き場所：ユーザーが指定した保存先（1）に図の名前のフォルダ（`<図の名前>/`）を作り、作図スクリプト `make_<図の名前>.m`、図を作り直すのに使うそのほかのスクリプト、完成図（`output/` に PDF・PNG）を置く。toolkit のフォルダの中には置かない（ユーザーが指定した場合を除く）。AI の作業用の場所（スクラッチパッドなど）に置いたスクリプトで図を作らない。
   - 構成：パネルごとに `%%` のセクションを作り、その中を次の段落に分ける。段落の見出しのコメントには、原案のどの figure・どの行に当たるかを書く（人が原案と見比べてデータを確かめられるように）。
     - データ：原案と同じ読み込み・計算
     - データを描く：原案と同じデータを描くオブジェクトだけ。色・線幅などの体裁は指定しない
     - 体裁：色・線幅・点・軸範囲・目盛り・軸ラベル・凡例（figure-types の recipe.md と defaults.json に従う。データの値は変えない）
     - 注釈：Affinity で加える注釈の指定（原案の値のまま）
     - 書き出し：exportPanel
4. 確認：作図の後、報告の前に次を行い、結果を報告に書く。NG があれば直してからやり直す。
   - データの一致（MATLAB）：`compareFigureData` で、原案の各 figure と論文用の各パネルのデータを比べる。注釈に置き換えたもの（ブラケット、文字）と、軸範囲の外の点も確かめる。
   - 組み立ての確認（Affinity）：`affinity/compose/check_figure.js` で、ページと Figure area、比較用の全体図との位置の差、文字のまとまりごとの大きさと大小関係、線幅、書き出した PDF を確かめる。
   - 目視：完成図の PNG を見て、原案と同じ内容か、重なり・はみ出しがないかを確かめる。
5. 途中のファイルの削除：作業の最後に、この作業で作った途中のファイルを削除し、削除したものを報告に書く。
   - 削除する：デスクトップの `affinity_mcp_work/input/` の中のこの図のファイル（MATLAB の書き出し、データの記録 `_data.mat`、まとめた PDF と JSON）、`affinity_mcp_work/check_<題名>.pdf`、確認のためだけに作った一時的なスクリプト。
   - 残す：原案のスクリプトとデータ、保存先の `<図の名前>/` の中のもの（作図スクリプト、図を作り直すのに使うスクリプト、完成図）、.af（`affinity_mcp_work/panels/`。Affinity で開いたまま残し、ユーザーが調整に使う）。
   - 仕上げた図の書き出しを頼まれたときは、.af も書き出し先と同じ `<図の名前>/` に保存するかを提案する（.af は自動では保存先に入らず、ユーザーが気づかないことがあるため。手順は AGENTS.md の 4 節の 11）。
   - ほかの作業のファイルや、この作業で作ったか分からないファイルは削除しない。

## MATLAB と Affinity の分担

基本の考え方：データの値に正確に合わせる必要があるもの、図を作り直すたびに同じ結果が必要なものは MATLAB（描画環境）で行う。手で位置を合わせればよいもの、パネル同士の関係・配置、投稿用の書き出しは Affinity で行う。詳細は右端の列の節を参照。

| 作業 | MATLAB | Affinity | 詳細 |
|---|---|---|---|
| 軸範囲・目盛り・軸ラベル・凡例 | 行う | 行わない（修正は MATLAB に戻る） | panel 1・2 節、4.2 節のルール 2 |
| 線の色・太さ、フォント・文字サイズ | 指定する | サブレイヤー単位の微修正、フォントの統一、下限の修正だけ | panel 2 節、4.2 節のルール 2 |
| データの値に正確に合わせる線（イベント線、基準線など） | 行う | 行わない | panel 2 節 |
| 有意差記号、スケールバー、説明の矢印などの注釈 | 行わない | パネルの `X: annotations` に加える。多少ずれても手で調整する | panel 2 節、4.1 節 |
| 図の大きさ・軸の位置 | 書き出しで固定する（`'Padding', 'figure'`、innerposition） | 拡大縮小しない | panel 3 節、assembly 2 節のルール 1 |
| 図全体の大きさ（段の幅：既定 single 90 mm・double 190 mm） | 段の種類を指定する（パネルの幅は段の幅以下） | Figure area の矩形を最背面に置き、ページの大きさを合わせる | assembly 1・4 節 |
| 背景の矩形・重複線 | 書き出しの設定で出さない | 削除・統合しない | panel 3・5 節 |
| 意味のまとまり（軸、系列ごとの棒・点・線、誤差棒、凡例） | 成分ごとにページを分けて書き出す | 重ねてサブレイヤーに分ける | panel 5 節 |
| パネルの配置・整列、パネル記号 | 行わない | 行う | assembly 1・2 節 |
| パネルをまたぐ注釈（拡大範囲の補助線など） | 行わない | 最上位の Annotations に加える | assembly 1 節 |
| 投稿用の書き出し（PDF、TIFF の dpi、CMYK） | 行わない | 行う | assembly 3 節 |
| 写真・模式図のパネル | 行わない | 行う（写真の加工は AI の作業対象外：AGENTS.md） | panel 4.1 節 |

（表中の panel は figure-panel-style.md、assembly は figure-assembly-style.md）

## レイヤー構成の全体像

Affinity のレイヤーパネルと同じく、上ほど前面。詳細は、最上位が figure-assembly-style.md の 1 節、Panel の中が figure-panel-style.md の 4.1 節。

```
図（1 ページまたは 1 アートボード）
├── Labels                       パネル記号（Affinity で追加）
├── Annotations                  パネルをまたぐ注釈だけ（Affinity で追加）
│   └── A-B: zoom lines          Panel A の一部を拡大したものが Panel B であることを示す補助線
├── Panel A                      描画環境の図 1 枚分
│   ├── A: annotations           このパネルのグラフに付く注釈（Affinity で追加）
│   │   ├── peak arrow           矢印
│   │   ├── scale bar            スケールバー
│   │   └── significance         有意差記号（ブラケットと *）
│   ├── A: axis labels           軸ラベル、タイトル（取り込み）
│   ├── A: tick labels           目盛りの文字（取り込み）
│   ├── A: axes lines            軸線、目盛り線（取り込み）
│   ├── A: error bars            誤差棒（取り込み）
│   ├── A: bars cond 2           条件 2 の棒（塗りと枠線、取り込み）
│   └── A: bars cond 1           条件 1 の棒（塗りと枠線、取り込み）
├── Panel B, Panel C …
├── Notes                        作業用のメモ（非表示、書き出さない）
└── Figure area                  図全体の領域を示す矩形（段の幅 × 図の高さ）。ページの大きさをこれに合わせる
```

## 用語

| 用語               | 意味                                                                                                        |
| ------------------ | ----------------------------------------------------------------------------------------------------------- |
| パネル             | 図の中の 1 つのまとまり（A、B、C …）。通常は描画環境の図 1 枚分                                            |
| Panel レイヤー     | Affinity で 1 つのパネルを入れる最上位のレイヤー（`Panel A` など）                                        |
| サブレイヤー       | Panel レイヤーの中で、色・線幅などをまとめて変える単位（`A: axes lines`、`A: bars cond 1` など）        |
| グラフに付く注釈   | 1 つのパネルのデータや軸に付く注釈（有意差記号、スケールバー、データを指す矢印）。`X: annotations` に置く |
| パネルをまたぐ注釈 | 複数のパネルの関係を示す注釈（拡大範囲の補助線など）。最上位の Annotations に置く                           |
| 作成方針（recipe.md） | 特定の図の種類の作業工程・既定値と、方針の例外を書いた文書（figure-types/<種類>/recipe.md）              |

## 更新のしかた

使いながら更新する前提の文書群である。更新するときは次のようにする。

- 更新のタイミング：まとまりのある単位の作業が終わった後に更新する。細かい注文が続くやり取りの途中では書き込まない。AI と作業したセッションでは、セッションをまとめるときに AI が作業を振り返り、新しいレシピの作成や方針の更新を提案し、ユーザーが了承してから書き込む。
- 方針を変えるとき：該当する文書（パネル単位なら figure-panel-style.md、統合なら figure-assembly-style.md）の該当節を直し、その文書の末尾の更新履歴に日付と理由を 1 行追記する。
- 個別の注文（特定の図の軸範囲など）：方針の文書・レシピには書かない（「個別の注文の扱い」）。
- 新しい種類の図・加工があったとき：その作業がまとまった後（上のタイミング）に、figure-types/README.md の手順で種類のフォルダを作り、雛形に沿って recipe.md を書き、一覧に追加する。
- レシピが方針の例外になるとき：レシピに「どの文書のどのルールの例外か」を書く。方針の文書には例外を書き込まない。
- 複数のレシピに共通する手順が出てきたとき：一般化して方針の文書へ移し、レシピからはその節を参照する。
- 未確認の事項：「（未確認）」と書く。確認したら、日付と根拠（スクリプト名、試行の記録の項目）を付けて書き換える。
- 参照の付け替え：節番号やファイル名を変えたときは、他の文書・スクリプトからの参照を検索して直す。toolkit を .gitignore の対象の場所に置いている場合は、ripgrep 等の通常の検索では除外されるため、`grep -rn` 等で検索する。
- MATLAB と Affinity の分担を変えたとき：本文書の分担表と、詳細の列に挙げた節の両方を直す。
- レイヤー構成を変えたとき：本文書の「レイヤー構成の全体像」、figure-assembly-style.md の 1 節、figure-panel-style.md の 4.1 節の 3 か所のツリー図を揃えて直す。
- 作業ログ（`log/`）には「どの文書を更新したか」だけを書き、手順の中身は文書に書く。
