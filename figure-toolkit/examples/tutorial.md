# チュートリアル（AI が案内する手順）

このファイルは、AI がユーザーに figure-toolkit の使い方を案内するための手順である。ユーザーが「figure-toolkit のチュートリアルを始めてください」などと頼んだとき、または導入（[../AGENTS.md](../AGENTS.md) の 3 節）の最後に AI が尋ね、ユーザーが始めると答えたときに、この手順で案内する。

流れは [README.md](README.md) の「作業の流れ」（1〜6）と同じ。ユーザーが自分のデータで原案を書けばそれを使い、手持ちのデータがなければ例の原案 `draft_figures.m` の figure 3 と figure 4 を横に並べた 2 パネルの図を作る（2 × 2 の図より短い時間で一通り試せるため）。

## 案内のしかた

- 段階ごとに、何をするか、ユーザーが何をするかを短く伝え、ユーザーの返事（「OK」「確認しました」など）を待ってから次の段階に進む。
- ユーザーに入力してもらう依頼文は、そのまま写せる形（引用の形）で示す。
- 実際の作図・組み立て・確認は、AGENTS.md の 4 節の手順で行う。チュートリアルだからといって、確認や途中のファイルの削除を省かない。
- toolkit の中のファイル（`examples/` の原案や例を含む）は変更しない。チュートリアルの作業は、ユーザーが了承した作業用のフォルダで行う（toolkit はユーザーのプロジェクトのフォルダに置かれ、AI はそのプロジェクトのフォルダで起動されている想定）。
- ユーザーが途中でやめたいと言ったら、そこで止め、作ったファイルの場所を伝える。

## 0. 準備

1. 導入（[../AGENTS.md](../AGENTS.md) の 3 節）が済んでいるかを、ユーザーに尋ねる。済んでいなければ、先に導入を行うかを尋ねる。同じセッションで導入を終えた直後なら、尋ねない。
2. 作業用のフォルダの場所をユーザーに尋ねる。案を示して尋ねる（例：「チュートリアル用のフォルダを `<プロジェクトのフォルダ>/figure-tutorial/` に作ってよいですか？」）。了承か指定の返事があるまで、フォルダを作らない。
3. `examples/draft_figures.m` と `examples/create_demo_data.m` を作業用のフォルダに写す。写したものが、このチュートリアルの「原案」になる。

## 1. 用意されているファイルと、できるようになること

手順の説明に入る前に、原案と、清書した後の図を見せて、このチュートリアルで何ができるようになるかを伝える。

1. 作業用のフォルダに写したファイルを紹介する。
   - `draft_figures.m`：手作業で書いた、ラフな作図スクリプト（原案）。figure(1)〜(4) を、体裁は MATLAB の既定のままで描く。
   - `create_demo_data.m`：原案が使うダミーデータと、統計解析（検定、相関、回帰）の結果を作る関数。
2. 清書の前と後の図を、画像のファイルへのリンク（フルパス）で示し、開いて見てもらう。
   - 清書の前（原案の図。MATLAB の既定のまま）：[images/draft_figure3.png](images/draft_figure3.png)、[images/draft_figure4.png](images/draft_figure4.png)
   - 清書の後（この 2 つを toolkit で横に並べた図）：[images/clean_figure3_figure4.png](images/clean_figure3_figure4.png)
   - ほかの例（任意）：原案の figure 1・2（[images/draft_figure1.png](images/draft_figure1.png)、[images/draft_figure2.png](images/draft_figure2.png)）と、4 つを 2 × 2 に並べた図（[draft_figures_2x2/output/draft_figures_2x2.png](draft_figures_2x2/output/draft_figures_2x2.png)）
3. 清書で変わる点と、変わらない点を伝える。
   - 変わる点：図の大きさ（論文の 2 段組の幅 190 mm）、文字の大きさとフォント、色、線幅、軸範囲と目盛り、パネル記号（A、B）、有意差記号と相関係数の文字の置き方。
   - 変わらない点：データの値。データを描く部分（`plot`、`fill`、`bar`、`errorbar` など）は、人が書いて確かめた原案から変えない。原案の体裁は、MATLAB の既定のままでよい。
4. この後の流れ（2 原案の用意、3 清書の依頼、4 確認、5 AI への修正の依頼、6 Panel style での調整、7 Affinity での仕上げと書き出し）と、かかる時間の目安（全体で 20〜40 分。自分のデータで原案を書く時間は含まない）を伝える。
5. 返事を待つ。

## 2. 原案を用意する

流れを把握してもらったら、清書の元になる原案（ラフな作図スクリプト）を用意してもらう。

1. 原案の用意を促す。
   - 自分のデータがある場合：そのデータを読み込んで図を描く、ラフな作図スクリプトを書いてもらう。
     - 体裁（軸範囲、文字の大きさ、線幅、色など）は MATLAB の既定のままでよい。
     - 図ごとに `figure(1)`、`figure(2)` … と番号を付けて描くと、清書の依頼で「figure 1 と 2 を」のように指定しやすい。
     - 原案はユーザーが書く。データを描く部分は、人が書いて確かめたものから始める原則のため（AI は書き方の質問には答えてよいが、データの読み込みと計算は書かない）。
   - 手持ちのデータがない場合：作業用のフォルダに写した `draft_figures.m` が、そのまま原案として使えることを伝える（ダミーデータで figure(1)〜(4) を描く。1 で見た図の元のスクリプト）。
2. 原案ができたら、スクリプトの場所と、清書に使う figure を教えてもらう。`draft_figures.m` を使う場合は、その旨の返事だけでよい。
3. 自分の原案のときは、図の種類が toolkit の図の種類（時系列、棒グラフと個人の点、散布図。[../figure-types/](../figure-types/README.md)）のどれに近いかを確かめて伝える。どれにも当たらない場合は、近い種類の作り方をもとに作ることを伝える。
4. 返事を待つ。

## 3. 清書を依頼する

1. Affinity の準備を頼む。チュートリアルの直前に導入をしていても、Affinity を閉じていることや、設定がオフに戻っていることがあるため。
   - Affinity を起動しておいてもらう（清書した図は Affinity で開くので、画面で見られるようにしておく）。
   - Affinity の設定（メニューの 編集 > 設定）の「モデルコンテキストプロトコル」で、「Affinity MCPを有効にする」と「デスクトップ上のファイルへのアクセス」がオンになっているかを確かめてもらう。オンにした場合は、Affinity を再起動してもらう（再起動するまで AI は接続できない）。
   - 「分からないところがあれば聞いてください」と伝える。聞かれたら、必要に応じて補足する（設定の項目の意味は README.md の導入手順 2.1 の 3。「デスクトップ上のファイルへのアクセス」は、Affinity が正常に終了しなかった後にオフに戻ったことがある）。
   - Affinity の起動と設定は、ユーザーに行ってもらう（設定は AI に権限を与えるものなので、AI は変えない）。
2. 準備ができたと返事があったら、接続と作業フォルダの読み込みを確かめる：`node tools/affinity-mcp.mjs run affinity/compose/check_connection.js`（figure-toolkit のフォルダで）。
   - 接続できない：Affinity が起動しているか、「Affinity MCPを有効にする」がオンか（オンにした後に再起動したか）を確かめてもらう。
   - `[NG] desktop`：「デスクトップ上のファイルへのアクセス」がオンかを確かめてもらう。作業フォルダ（デスクトップの `affinity_mcp_work/`）がまだないときは、了承を得て、`affinity_mcp_work/` と、その中の `panels/`・`export/` を作る。
3. 清書にかかる時間の見込みを伝える。目安は、2 パネルの図で 5〜10 分ほど（2026-10-20 の試用では 3〜7 分）、4 パネルの図で 15〜20 分ほど（2026-10 の試用。AI のモデルと図の内容で変わる）。作業の間は、チャットで経過を短く伝えることも伝える。
4. ユーザーに、次の依頼文をチャットに入力してもらう（`<作業用のフォルダ>` は実際の場所にする）。自分の原案のときは、原案の場所、使う figure、並べ方を、2 で聞いた内容に置き換えた依頼文を示す。

   > `<作業用のフォルダ>`/draft_figures.m の figure 3 と figure 4 を、横に並べた 2 パネル（A, B）の図にしてください。figure-toolkit を使い、論文クオリティーで仕上げること。成果物は `<作業用のフォルダ>` の中に保存すること。

5. 依頼文が入力されたら、AGENTS.md の 4 節の手順で図を作り、報告する。あわせて、自分の原案で頼むときに保存先を書かなければ、AI が保存先を尋ねることを伝える。
6. 報告では、次の 3 点を、このチュートリアルの説明として加える。
   - 作図スクリプトと完成図の場所
   - Affinity で図が開いたままになっていること
   - 原案とのデータの比較の結果

## 4. 図を確認する

1. ユーザーに、Affinity で組み立てた図を見てもらう。
   - AI が組み立てた図（文書の名前は `<図の名前>`）が、Affinity で開いたままになっている。閉じていたら、デスクトップの `affinity_mcp_work/panels/<図の名前>.af` を開いてもらう。
   - 見てもらう点：
     - 図全体：ページの大きさが論文の段の幅（2 段組なら 190 mm）になっていること、2 つのパネルとパネル記号（A、B）の配置。
     - レイヤーパネル：前面から Labels（パネル記号）、Panel B、Panel A、Notes（非表示）、Figure area（図全体の領域）の順に並んでいる。Panel の中は、成分ごとのサブレイヤー（`A: tick labels`、`A: bars SJ` など）に分かれていて、サブレイヤーを選ぶと、まとめて選択・変更できる。
     - 文字：文字のまま取り込まれていて、Affinity で書き換えられる。
     - Notes：MATLAB が書き出した図（比較用）が、非表示で入っている。
   - `output/` の PDF と PNG は、この図を書き出したもの（共有や確認用）であることも伝える。
2. 作図スクリプト（`make_<図の名前>.m`）の見方を伝える。
   - パネルごとに「データ」「データを描く」「体裁」「注釈」「書き出し」の段落に分かれている。
   - データの段落には、原案のどの figure・どの行に当たるかが書いてある。そこを原案と見比べれば、データが変わっていないことを確かめられる。
3. 分からないところがあれば聞くよう伝え、返事を待つ。

## 5. AI に修正を依頼する

1. ユーザーに、修正の依頼文の例を示し、入力してもらう。ユーザーが自分で考えた修正でもよい。下の例は `draft_figures.m` の figure 3・4 のときのもので、自分の原案のときは、その図に合う例を示す。

   > 次のように修正してください。
   > 1. B の縦軸を 28〜44 m/s にして、目盛りを 4 ごとに
   > 2. 両パネルの目盛り線を内向きに

2. 依頼に沿って作図スクリプトを直し、図を作り直して報告する（AGENTS.md の 2 節の、チャットでの修正の扱い）。
3. 次の点を伝える。
   - 修正は作図スクリプトに残るので、作り直しても消えない。
   - Affinity で開いている図は、新しい図に置き換わった。
4. 返事を待つ。

## 6. Panel style で調整する

1. ユーザーに、次の操作をしてもらう。
   - Affinity で、組み立てた図（.af）を表示する。
   - 図を、作業用のフォルダの `<図の名前>/` に別の名前（例：`<図の名前>_edited.af`）で保存する。AI が組み立てた .af（デスクトップの `affinity_mcp_work/panels/`）は、AI が図を作り直すと上書きされるため、Affinity で手を加える図は別の名前にしておく。
   - スクリプトパネル（メニューの ウィンドウ > スクリプト）の「Panel style」を実行する。
   - ダイアログで、パネル B の点の大きさを変える。画面に仮に反映されることを確かめて、OK を押す。
   - 操作が分かりにくいとき（スクリプトパネルが見つからない、ダイアログのどこを変えればよいか分からない など）は、Affinity の画面のスクリーンショットを撮ってチャット欄に貼り付けてもらうよう伝える。AI は Affinity の画面（パネルやダイアログ）を見られないため。貼り付けられたら、画面を見て、次に押す場所や変える欄を具体的に案内する。
2. 次の点を伝える。
   - 確定した変更は、1 回の取り消しで戻せる。
   - Panel style での変更は Affinity の中だけにあり、AI が図を作り直すと失われる。AI への修正の依頼を先に済ませてから使う。
3. 返事を待つ。

## 7. Affinity で仕上げて、書き出す

1. 細かい調整は、Affinity で手作業で行うことを伝える。操作が分かりにくいときは、6 と同じく、画面のスクリーンショットを貼り付けてもらう。
2. 仕上がったら、書き出しを AI に頼めることを伝え、依頼文の例を示す。

   > 仕上げた図を PDF と PNG で書き出してください。

   - 「PNG で」「PDF で」のような短い依頼でも、AI が推奨の設定で書き出すので、多くの場合はそれで十分であることを伝える。推奨の設定は、PDF はベクターのまま文字を埋め込む「書き出し用」、PNG・TIFF は 600 dpi、色は RGB（[../AGENTS.md](../AGENTS.md) の 4 節の 11）。
   - 投稿規程などで細かい指定があるときは、注文を付けられることを伝える（例：「TIFF の 1200 dpi で」「CMYK で」「PDF/X-4 で」）。
   - 書き出すのは、Affinity で今表示している状態（保存していない変更を含む）であることを伝える。
3. 依頼文が入力されたら、AGENTS.md の 4 節の 11 の手順で書き出し、書き出したファイルの場所、大きさ、解像度を報告する。対象の図は、6 で別の名前で保存した図（題名は `<図の名前>_edited` など）。
   - 報告と一緒に、AGENTS.md の 4 節の 11 の「.af の保存の提案」に沿って、.af も同じフォルダに保存するかを提案する。6 で保存先に別の名前で保存してあれば、その後の変更を上書き保存（Ctrl+S）するよう勧める。
4. チュートリアルはここまでであることを伝え、次を案内する。
   - 自分の原案で使うときは、3 と同じ形の依頼文で頼めばよい（原案のスクリプトの場所、使う figure、並べ方、成果物の保存先を伝える）。
   - 作業の流れとプロンプトの例は [README.md](README.md) にある。
5. 作業用のフォルダと Affinity の図を残すか削除するかをユーザーに尋ね、削除してよければ削除する（Affinity の図は、ユーザーに閉じてもらってから削除する）。
