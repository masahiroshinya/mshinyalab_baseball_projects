# 02_ポスター — 技術説明

## 1. トラブルシューティング：Word の数式を Affinity に貼ると文字化けする（2026-10-26、記録者：加藤 和太郎）

### 症状
Onset 算出式を Word の数式エディタ（LaTeX 入力）で作成し、コピーして Affinity に貼ると文字化けした。

### 原因
Word の数式は Cambria Math フォントで描かれる。このフォントは Word のアプリ内にだけ同梱されていて、
システムのフォントフォルダ（`/Library/Fonts`・`/System/Library/Fonts`・`~/Library/Fonts`）には無い。
数式をテキストのまま貼ると、Affinity からはフォントが見えないため、記号が別の文字に置き換わる。

### 切り分け
- 上記3か所のフォントフォルダに Cambria Math が無いことを確認した。

### 対処（数式を文字ではなく図として持ち込む）
- **方法A**：Word で数式をコピー → Affinity の「編集」→「形式を選択してペースト」→「PDF」。
- **方法B**：数式だけの Word を PDF で保存 → Affinity の「ファイル」→「配置」→ ツールバーで「パススルー」を選ぶ
  （「解釈」だとテキストとして読まれ、再び文字化けする）。

どちらもベクターのまま入る。ただし加藤の環境ではうまくいかなかった。

- **Pandoc は解決にならない**：Pandoc で docx にしても数式は Word 数式（Cambria Math）になり、同じ問題が起きる。
- **方法C（採用）**：MathJax で数式を **フォントを使わない SVG**（字形をパスにしたもの）に変換し、Affinity で
  「ファイル」→「配置」する。SVG 内に `<text>` が無い（0 個）ことを確認済みなので、フォント依存で文字化けしない。
  - 出力：`figure/数式/onset_01_Fx.svg` 〜 `onset_05_RT.svg`（Onset・RT）、
    `speed_01_vi.svg` 〜 `speed_03_vpeak.svg`（バット先端の合成速度、`m3_analyze_single_trial.m` の diff3p → ノルム → max に対応）、
    `mt_01_tpeak.svg`・`mt_02_MT.svg`（MT ＝ 合成速度ピーク時刻 − onset、同ファイルの MT 算出部に対応）、
    `fz_01_peak.svg`（踏み込み足 Fz2 のキュー後 2.0 s 内の最大値 ÷ 推定体重。m3 の PeakFz2 と x8 の PeakFz2_BW に対応）。
    24 pt 相当の文字サイズ、黒。
  - 再生成：`figure/数式/tex2svg.js`。Node.js と `npm install mathjax-full@3.2.2` を入れた作業フォルダで
    `node tex2svg.js <出力先>` を実行する。式を変えるときはスクリプト内の `eqs` を書き換える。
    MathJax 既定の `ex` 単位は Affinity で読めないため、スクリプト内で 24 pt 換算の pt に直している。

### 使用した数式（Word の LaTeX 入力用）
```
F_{\mathrm{thr}}=F_{\mathrm{base}}+0.20\times\left(\max_{t_{\mathrm{cue}}\le t\le t_{\mathrm{FC}}}F_x(t)-F_{\mathrm{base}}\right)
RT=t_{\mathrm{onset}}-t_{\mathrm{cue}}
```
