# AIへの指示書

このドキュメントは、AIアシスタントに対する基本設定および指示をまとめたものです。AIは以下のルールを遵守して動作してください。

## 1. 基本的な出力ルール

- **言語設定**: ユーザーへの出力は、必ず**日本語**で行うこと。たとえユーザーからの入力が**英語**であったと
  しても、出力は**日本語**で行うこと。
- **エラー対応**: エラーログが入力された場合やエラーに遭遇した場合は、以下の2点を含めてわかりやすく日本語で出力すること。

  1. エラーの詳しい説明（原因の分析）
  2. 具体的な修正案・解決策の提示
- **トラブルシューティングの記録**: エラー解決やトラブルシューティングを行った場合は、必ずその内容（原因、切り分けの手順、および解決策）をプロジェクト内の対応する技術ドキュメント（例: `技術説明.md`など）に明記・追記し、トラブルシューティングのナレッジを蓄積すること。

## ユーザー

このプロジェクトでは、Github で共有しながら複数のユーザー（学生と教員、など）が並行して開発します。
ログを取る際は、ユーザーが誰なのかを、userinfo.md から取得して、記載してください。
userinfo.md は git 管理していません。ローカルのプロジェクトフォルダ内に userinfo.md が存在しない場合は、作成を促してください。

ユーザーロールが、student の場合は、AIは、コードの修正の際に、修正案を提示するだけにして、ファイルの更新を行わないこと。
student の場合は、エラーの原因や、アルゴリズムについて、詳しく説明すること。

## Word（.docx）の作成

- docx を作成する場合は、**すべて `sandbox/6.1_Pandoc/技術説明.md` に記載の方法（Markdown → Pandoc → docx）で進めること。** docx を直接編集・生成（python-docx 等）しない。
- 成果物ごとのフォルダに、次の作業ファイルを置く（例：`Manuscript/修士論文/01_研究概要/`、`Manuscript/2026野球学会/01抄録/`）。
  - `draft.md`：原稿（**md を正とし、docx は生成物**として扱う）
  - `convert.sh`：変換コマンド（Pandoc・`--citeproc`・`.bib`・CSL・`--reference-doc` を指定）
  - `reference.docx`：書式テンプレート（Word のスタイル指定用）
  - `figure/`：図
- 文献は Zotero（Better BibTeX）が自動書き出しする `sandbox/6.1_Pandoc/reference/選択反応課題　参考文献.bib` を使う。
- PDF が必要な場合は、生成した docx を Word で開いて PDF に保存する。
- 変換で問題が起きた場合は、原因と対処を `sandbox/6.1_Pandoc/技術説明.md` に追記する。

## 2. ログ管理について

AIエージェントとユーザーとのやり取りのログは、00_logging_policy.md に従って記録・保存すること。

### セッションのまとめとコミット

- ユーザーから「セッションをまとめてください」等の**セッション終了の指示**があった場合は、次の手順を行うこと。
  1. 00_logging_policy.md に従い、当該セッションのログ（`log/YYYY-MM-DD_NN.md`）の「セッションの概要」「備考」欄を記載する。
  2. **そのうえで、プロジェクトフォルダ内の全ての変更（未追跡ファイルを含む）に適切なコミットメッセージを付けて `git commit` まで行う。**
- コミットの対象は、**プロジェクトフォルダ内の全ての変更**とする（プロジェクトフォルダで `git add -A .` を実行する）。ただし、`.DS_Store` などの OS が自動生成するファイルや、プロジェクトフォルダ外の変更は含めない。
- コミットメッセージは日本語で、セッションで何を行ったかが分かる要約とすること。
- student ロールの制約（コード .m は修正案の提示のみ・本体更新しない）は維持する。AI がファイルを更新するのは .md 等のドキュメント類に限るが、コミットはユーザー自身の変更も含めて全て行う。
