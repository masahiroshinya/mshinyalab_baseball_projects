### [2026-06-15] x2_import_data.m：Analog.Data 転置漏れバグ

**発見者：** 加藤 和太郎 (student) / AI (Claude)

**症状：**
- 被験者2（S02）で x4 を実行すると、全60試行で「配列インデックスは正の整数または logical 値でなければなりません」エラーが発生し、RT がすべて NaN になった。
- 被験者1（S01）はクラッシュしなかったが、反応時間が誤った値で算出されていた。

**原因：**
`x2_import_data.m` の LED データ抽出部で、`Analog.Data` の転置が実装されていなかった。
`Analog.Data` は `[チャンネル数 × サンプル数]`（例: 64×12000）で格納されているが、コードでは転置なしに `analogData(:, 1:2)` で列方向を取得していた。そのため、チャンネル番号（64）をサンプル番号として誤認識し、インデックスエラーまたは誤ったタイミング算出が発生した。

コメントには「転置する」と正しく記載されていたが、実装が漏れていた。

**切り分け手順：**
1. S02 の x4 エラーログを確認 → 全試行でインデックスエラー
2. `Data.LEDData` のサイズを診断 → `64×2`（正しくは `12000×2` になるべき）
3. `X.Analog.Data` のサイズを確認 → `64×12000`（転置前の生データ形式）
4. S01 でも同サイズであることを確認 → S01 も転置が必要と判明

**解決策：**
`x2_import_data.m` の `analogData = X.Analog.Data ;` を以下に置き換えた：

```matlab
rawAnalog = X.Analog.Data ;
if size(rawAnalog, 1) < size(rawAnalog, 2)
    rawAnalog = rawAnalog' ;
end
analogData = rawAnalog ;
```

`size` で行列の向きを判定してから転置することで、データ形式が変わっても安全に動作する。

**再処理：**
修正後、`subjects = [1, 2]` で x2 → x3 → x4 → x5 → x6 を再実行し、S01・S02 ともに正しい値に更新した。

### [2026-06-16] x6_analyze_multi_trial.m：保存パスが最終被験者のIDになる設計上の注意点

**発見者：** 加藤 和太郎 (student) / AI (Claude)

**症状：**
`subjects = [1, 2]` で x6 を実行すると、`x6_MultiTrialAnalysisResults/` に `MultiTrialResults02.mat` のみが保存され、`MultiTrialResults01.mat` は上書きされないか、または両被験者のデータが混合した `MultiTrialResults02.mat` が生成される。

**原因：**
`x6_analyze_multi_trial.m` では `ResultsTable` の初期化がループの外にあり、全被験者のデータが1つのテーブルに蓄積される。保存はループ終了後に `iSubject`（= 最後の被験者番号）で1回のみ行われる。

```matlab
ResultsTable = table() ;          % ← ループ外で初期化

for iSubject = subjects           % [1, 2]
    % S01・S02 のデータを ResultsTable に追記
end

% ループ終了後、iSubject = 2 になっている
save(savePath, 'ResultsTable')    % → MultiTrialResults02 に両被験者分が保存される
```

**解決策（当面の運用）：**
被験者ごとに x6 を個別に実行する（`subjects = [1]`、次に `subjects = [2]`）ことで、単一被験者のデータのみが含まれるファイルを生成する。
