## 1. なぜ 00 から切り出すのか

00 は現在、**① RT の検出信号をどこから取るか**で難航している。
S02（バットを常時揺らして構えるタイプ）でバット先端速度による動作開始の検出が破綻し、
RT 検出を ③ Fz へ移す方針転換を検討中で、**まだ決着していない**。

一方 ② は、00 の「重大な見直し」の中でもこう明記されている：

> ② バット先端並進速度は、指標としてはそのまま維持する（ピーク値の比較）。

つまり **② は「① がどの信号に移るか」に一切依存しない。**
RT が Fz に移ろうがバット速度に留まろうが、「スイングの速さをバット先端の並進速度のピークで測る」
という決定は変わらない。

→ **① の未決事項の決着を待たずに、② だけ独立して完成させられる。** これが 01 を切り出す理由。

## 3. 決めるべきこと

### 論点1：フィルタ遮断周波数 30 Hz に根拠はあるか ―― **決着：30 のままでよい（2026-07-16）**

> **結論：`Prm.Fc = 30` は変更しない。** ステップ1 の感度分析で、30 がプラトーの中に
> 十分な余裕をもって収まっていることを両被験者・全条件で確認した。
> 詳細は「6. 作業記録 ステップ1」を参照。
>
> **なお、下記で「01 の山場」としたのは過大評価だった。**
> 想定した危険（高い Fc でノイズが水増しされ SD が膨らむ）は**実際には起きなかった**。
> 判断の経緯として下記の記述は残すが、結論はステップ1 の作業記録が優先する。

`parameters.m` の `Prm.Fc = 30` は**角速度時代から引き継いだ値**で、
並進速度のピークを測る目的で検証されたことは一度もない。

**なぜ問題か：** 微分はノイズを増幅する。位置に乗った微小な高周波ノイズは、
微分すると `2πf` 倍されて速度に現れる。遮断周波数を上げるほど `PeakVelTop` は
**ノイズのぶんだけ過大**になる。②はピーク値そのものが指標なので、ここが直撃する。

**これは 00 のステップ2（閾値決め）と同じ構造の問題。**
00 では「閾値に根拠がない」→ 感度分析で決めた。01 では「遮断周波数に根拠がない」→ 同じ手口で決める。

**検証方法（案）：** 遮断周波数を振って `PeakVelTop` の動きを見る。

| 判断                 | 波形の見え方                                           |
| -------------------- | ------------------------------------------------------ |
| ノイズを拾っている   | Fc とともに`PeakVelTop` が**単調に増え続ける** |
| 真の信号が取れている | ある Fc から上で**プラトーになる**               |

→ **プラトーの入り口が適切な Fc。** そこより下げると本物の信号を削り、上げるとノイズを足すだけ。

> **注意：** 00 のステップ2 で得た教訓「1試行だけで決めてはいけない」「1人目で成立した基準が
> 2人目で成立するとは限らない」がそのまま効く。**最初から S01・S02 両方・全条件で見る。**

### 論点2：ピーク探索窓 ―― 試行全体のままでよいか

現行の `max(netVelTop)` は**試行全体**が対象。窓を切っていない。

00 ステップ1 では、探索範囲が試行終了までだったせいで NoGo の RT に 4728〜7020 ms という
偽陽性が出た（構えを解いてバットを下ろす動作を拾った）。**同じ構造の穴が ② にもある。**

ただし ② では実害が小さいと考えられる：

- x7_2 はすでに `CueText == "Go"` でフィルタしている → NoGo 試行の値は集計に入らない
- Go 試行では、バットを下ろす動作（数 m/s）はスイング（25 m/s）に**桁で負ける**ので、
  `max` が汚染されることはない
- S02 のワッグルも 1.5 m/s 程度で、同じく桁違い

→ **提案：試行全体のままでよい。** ①（動作開始の検出）と違って ② は最大値を取るだけなので、
ワッグルにも準備動作にも影響されない。**00 で ① を破綻させた S02 のワッグル問題は、② には及ばない。**

その代わり、NoGo 試行の `PeakVelTop` が無意味な値であることを明示するために、
00 で提案済みの「スイング有無判定」を入れる：

```matlab
% 00 のステップ3で提案済みの設計（マージン16倍）
% スイング 約25 m/s に対し、ワッグル・バット下ろしは 1〜3 m/s
if Result.PeakVelTop < 10        % [m/s]
    Result.HasSwing = false ;    % スイングなし
else
    Result.HasSwing = true ;
end
```

### 論点3：ピーク速度の**時刻**も出すか ―― 出しておくことを提案

`max` の第2出力でインデックスが取れる。コストはほぼゼロ。

```matlab
[Result.PeakVelTop, idxPeak] = max(netVelTop) ;
Result.TPeakVelTop           = idxPeak ;      % [frame]
```

**なぜ今のうちに入れるか：** 00 で RT 検出が ③ Fz に移る公算が大きい。そうなると

    MT（動作時間）= ピーク速度の時刻 − Fz の立ち上がり時刻

が**ほぼ追加コストなしで手に入る**。「反応の速さ（RT）」と「動作の速さ（MT）」を分けて
議論できるようになり、①③ と ② が繋がる。後から m3 を触り直すより今入れるほうが安い。

### 論点5：速度ベクトルの成分（Vx）を残すか ―― **決定：残す（2026-07-16）**

合成速度 `sqrt(vx^2+vy^2+vz^2)` は**向きを捨てたスカラー**である。
これを成分に展開し、**投手方向成分 Vx** を解析に加えるかどうか。

**加藤の判断：Vx を残す。理由は「Vx は打球に対して直接的に寄与する指標である」から。**

> **この理由づけは、本実験では検証できない仮説である。**
> 予備実験プロトコルにボール・ティー・的は存在せず、教示も
> 「タイミングや**打点はどこでも構いません**」（自由スイング）である。
> インパクトの瞬間が定義されないため、「投手方向成分が打球にどれだけ寄与するか」を
> 確かめる相手（初速・飛距離・打球方向）が1つもない。
> → **ボールを用いた実験で検証すべき仮説として書き残す。**
> 物理的な筋は通っている（投手方向から来るボールの初速に効くのは主に
> ボール進行方向に沿った速度成分）ので、将来の検証課題として有望。

**AI は当初「合成速度だけで十分、Vx は不要」と助言し、その後撤回した経緯がある。**
撤回の理由は「計算が安いから両方出す」という当初の助言が誤りだったこと
（問いに答えない指標を増やすと、解釈の手間と事後的な取捨選択の余地が増える）。
最終的な判断は加藤の上記の理由づけによる。

#### 出力する4指標

| フィールド        | 内容                                                            |
| ----------------- | --------------------------------------------------------------- |
| `VelTopX`       | Vx の波形。**符号を持つ**（正 = 投手方向、負 = 捕手方向） |
| `PeakVelTopX`   | Vx 自体のピーク値                                               |
| `TPeakVelTopX`  | そのフレーム番号                                                |
| `VelTopXAtPeak` | **合成速度がピークの瞬間の** Vx                           |

`PeakVelTopX` と `VelTopXAtPeak` は**別の時刻を指す**ので値が違う。
バット先端は回転しているため両者は一致しない。

> **検算に使える性質：** 合成速度は成分の二乗和の平方根なので、
> **`VelTopXAtPeak > PeakVelTop` は数学的にありえない。**
> x7_check にこの検算を入れた。0 以外なら列の対応かインデックスの受け渡しが誤っている。

### 論点4：角速度 `PeakOmegaDeg` を消すか ―― **決定：完全に削除する（2026-07-16）**

当初 AI は「単位検証に使えた実績がある」「従来結果との連続性が見られる」という理由で
当面残すことを提案したが、**加藤の判断により一旦すべて削除する。**

> **決定の位置づけ：** これは 00 §2 の決定
> 「従来の角速度 300 deg/s による検出は**廃止する**」を実行に移すもの。
> 新しい決定ではなく、**決定済みだが未実行だった掃除**である。
> 00 ステップ1 で「RT 検出がまだ角速度に依存しているため、ここで消すとパイプラインが
> 通らない」として暫定的に残したものを、ここで片付ける。

**残した場合のコスト（削除する理由）：**

- m3・x5 に**同じ角速度の計算式が二重に存在する**（x5 は m3 の式をコピーして再計算している）。
  廃止済みの指標のために、この重複を保守し続けることになる。
- 廃止した指標が `ResultsTable` の列に残り、x7 のグラフに描かれ続ける。
  「もう使わない値」が図に出ていると、後から見た人（自分を含む）が誤って解釈する。
- 単位検証（r = v/ω ≈ 0.83 m）は**すでに済んでおり、00 に記録が残っている**。
  検証のために計算を残し続ける必要はない。

### 論点4に付随する問題：RT の検出信号がなくなる

角速度を消すと、m3 のスイング開始検出（`THRESHOLD_OMEGA = 300`）が**信号を失う**。
そして 00 では**新しい RT 検出信号がまだ決着していない**（バット速度が S02 で破綻し、
Fz へ移すか検討中）。

**決定：RT は 00 が新しい信号を決めるまで NaN とする。**

- 消すのは「廃止済みの検出方法」であって、RT という項目そのものではない。
- `SwingOnset`・`RT` の**フィールドは残す**。消すと構造体配列のフィールド不一致で落ちる。
- ① は 00、② は 01 という分担どおり、01 は ② を x7 まで通すことに専念する。

> **これは 01 が 00 と独立して進められることの裏返しでもある。**
> RT が NaN でも、② の PeakVelTop は最後まで出せる（第1節を参照）。

## 8. 計算式のまとめ

論文の Methods を書くときの元ネタ。**予備実験（2026-06-04）で確立した手続き。**

### 8.1 処理の流れ

```
Qualisys の生座標 [mm]
   ↓ ① 欠損値を線形補間
   ↓ ② ローパスフィルタ（30 Hz）
   ↓ ③ mm → m に変換
   ↓ ④ 微分（3点差分法）
速度ベクトル v = (vx, vy, vz) [m/s]
   ├→ ⑤ ノルムを取る  → 合成速度 |v|（向きなし・常に正）
   └→ ⑥ X 成分を取る  → 投手方向速度 vx（符号あり）
```

**微分の前に必ずフィルタをかける。** 微分はノイズを増幅するため、順序を逆にすると
ノイズが速度に化ける。

### 8.2 前処理

| 段階 | 内容 |
|---|---|
| 欠損値 | 線形補間（`interp1` の `'linear'`, `'extrap'`） |
| フィルタ | **2次 Butterworth ローパス、遮断周波数 30 Hz** |
| フィルタの適用 | **順方向・逆方向に二重適用**（`filtfilt`）。位相ずれが生じない。実効次数は 4 次 |
| 単位変換 | mm → m（**微分の前に**行う。以降すべて m/s で統一される） |

> **なぜ `filtfilt` なのか：** 片道の `filter` だと波形が時間的に遅れる。
> タイミングを測る解析では致命的なので、往復させてズレを打ち消している。

> **なぜ 30 Hz なのか（論点1・ステップ1で検証済み）：**
> Fc を 5〜50 Hz で振ってピーク速度の変化を見たところ、**30 Hz 以上では変化が
> 0.04 m/s 未満（ピーク値の 0.15% 未満）** で一定になる領域に入っていた。
> 両被験者・全条件で確認。→ 30 Hz は「本物の信号を全部通し、ノイズを最小にする」点。

### 8.3 速度ベクトル（3点差分法・中心差分）

位置ベクトルを **p**(t) = (x(t), y(t), z(t)) [m] とすると、

```
v(tᵢ) = ( p(tᵢ₊₁) − p(tᵢ₋₁) ) / (2Δt)
```

Δt = サンプリング間隔 = **1/250 s**（予備実験のマーカー計測は **250 Hz**）

前後1フレームずつを使って傾きを求める方法。前進差分（次の点との差）より誤差が小さい。

実装：`velTop = diff3p(posTop, 1/fs)`
**第2引数はサンプリング間隔 Δt であって周波数ではない。** `fs` ではなく `1/fs` を渡す。

### 8.4 合成速度（速さ・スカラー）

```
|v(t)| = √( vx(t)² + vy(t)² + vz(t)² )
```

速度ベクトルの**ノルム**。バイオメカニクスでは「合成速度」と呼ぶ慣習があるが、
数学的には**速さ（speed）＝スカラー**である。

- **常に正**。向きの情報はここで失われる
- どちらへ動いていても「速さ」として計上される

実装：`netVelTop = sum(velTop.^2, 2).^0.5`
（`2` は「2次元目＝列方向に足す」の意味。各行ごとに vx²+vy²+vz² を作る）

### 8.5 投手方向速度成分（ベクトル成分）

```
vx(t) = v(t) の X 成分
```

- **符号を持つ。正 = 投手方向、負 = 捕手方向**
- テイクバック（バットを引く）は**負**、スイング本体は**正**として現れる
- 合成速度では区別できない2つの動きを、**符号で分離できる**

実装：`velTopX = velTop(:, 1)`

**座標系（s3b で実測確認、両被験者 40/40）：**

| 軸 | 向き |
|---|---|
| **X** | 投手–捕手方向。**正が投手方向** |
| Y | 左右方向 |
| Z | 鉛直方向 |

### 8.6 代表値（各試行から取り出す6つ）

| フィールド | 定義 | 単位 |
|---|---|---|
| `PeakVelTop` | max \|v\| ―― 合成速度のピーク | m/s |
| `TPeakVelTop` | そのフレーム番号 | frame |
| `PeakVelTopX` | max vx ―― Vx のピーク | m/s |
| `TPeakVelTopX` | そのフレーム番号 | frame |
| `VelTopXAtPeak` | **合成速度がピークの瞬間の** vx | m/s |
| `NetVelTop` / `VelTopX` | 波形そのもの | m/s |

> **`PeakVelTopX` と `VelTopXAtPeak` は別物。** バット先端は回転しているので、
> 「Vx が最大の瞬間」と「合成速度が最大の瞬間」は一致しない。
> 実測では `TPeakVelTopX` が `TPeakVelTop` より **1〜5 フレーム早い**（Go 試行で例外なし）。

> **時刻はフレーム番号で保存している。** 秒に直すには
> `(TPeakVelTop − TCueMarker) / fs`。キュー基準の時刻にする換算は x8 の仕事。

> **検算に使える性質：** 合成速度は成分の二乗和の平方根なので
> **`VelTopXAtPeak > PeakVelTop` は数学的にありえない。** x7_check で確認している。

### 8.7 実測値の目安（Go 試行）

| | S01 | S02 |
|---|---|---|
| 合成速度ピーク | 26.5〜27.7 m/s | 24.0〜27.5 m/s |
| Vx / \|v\| の比 | 約 0.9 | 0.90〜0.93 |

**X 成分だけでスイング速度の約9割を説明できる。**
先行研究（Nasu et al.）が X軸1次元速度を用いる根拠が、データで裏づけられた形。

**単位の妥当性（角速度との突き合わせ、00 ステップ1）：**

r ≈ 26 ÷ 31.4 ≈ **0.83 m** ―― バット長として妥当。

## 9. なぜ「3点差分法（中心差分）」なのか

8.3 で使っている `diff3p` の根拠。**聞かれたときに答えられるように**まとめておく。

より数式寄りの説明は `解析項目学習/バット先端並進速度算出.md` の5章にある。
ここではその要点を、直感で分かる形に置き直す。

### 9.1 やりたいこと ― 位置から速度を求める

速度とは「位置がどれだけ速く変わるか」なので、本来は微分で求める。
しかし計測で得られるのは**飛び飛びの点**（250 Hz なら 0.004 秒ごと）なので、
数式で微分できない。**近くの点との差を使って傾きを近似する。**

### 9.2 やり方は2通りある

いま知りたいのが「点②の速度」だとする。

```
       ①        ②        ③
       ●--------●--------●
     t-h        t       t+h
```

| 方法 | 使う点 | 式 |
|---|---|---|
| **前進差分** | ② と ③ | (p③ − p②) / h |
| **中心差分（3点差分）** | ① と ③ | (p③ − p①) / 2h |

**前進差分は「これから先」だけを見る。中心差分は「前と後ろを対称に」見る。**
この違いが、以下の3つの差を生む。

### 9.3 理由① 中心差分のほうが正確

**数値例で確かめられる。** 位置が `x(t) = t²` で動く物体を考える
（だんだん速くなる運動。真の速度は `2t` なので、t = 1 での正解は **2.0**）。

h = 0.1 として計算すると、

| 方法 | 計算 | 結果 | 誤差 |
|---|---|---|---|
| 前進差分 | (1.1² − 1.0²) / 0.1 = (1.21 − 1.00) / 0.1 | 2.1 | **+0.1** |
| **中心差分** | (1.1² − 0.9²) / 0.2 = (1.21 − 0.81) / 0.2 | **2.0** | **0** |

**中心差分はぴったり正解を出す。**

理由は「対称に見ているから」。前進差分は「これから速くなる分」だけを拾うので
速度を大きめに見積もる。中心差分は「前は遅かった／後は速い」を両方拾うので、
**ズレが打ち消し合う。**

一般には誤差はこうなる（h を小さくしたときの減り方）。

| 方法 | 誤差 | h を 1/10 にすると |
|---|---|---|
| 前進差分 | h に比例 | 誤差は 1/10 |
| **中心差分** | **h² に比例** | 誤差は **1/100** |

本研究は 250 Hz（h = 0.004 秒）なので、この差はかなり大きい。

### 9.4 理由② 時刻がズレない

前進差分 `(p③ − p②) / h` が本当に表しているのは、
**②と③の「あいだ」の平均速度**である。つまり素直に考えれば
時刻 `t + h/2` の速度であって、②の時刻 `t` の速度ではない。

**つまり前進差分は、速度の波形を半フレーム分うしろにずらす。**

中心差分は①と③の中間＝ちょうど②なので、**ズレない。**

> **これは `filtfilt` を使う理由とまったく同じ考え方。**
> 片道の `filter` だと波形が遅れるので往復させてズレを打ち消している。
> 微分でも同じことをしている。

250 Hz なら半フレーム = 2 ms なので量としては小さいが、
本研究は `TPeakVelTop`（ピークの時刻）や反応時間など**タイミングを測る**ので、
**系統的なズレはタダで避けられるなら避けておく。**

### 9.5 理由③ ノイズの増幅が半分になる

微分はノイズを増幅する操作である（ノイズは「短い時間で大きく変わる」ので、
変化率を取ると目立つ）。そのうえで2つを比べると、

| 方法 | 分子（ノイズ） | 分母 | 速度に出るノイズ |
|---|---|---|---|
| 前進差分 | 2点の差 | h | 大きい |
| **中心差分** | 2点の差（同じ） | **2h** | **ちょうど半分** |

**分子は同じで、分母だけが2倍。** だからノイズの影響が半分になる。

前進差分は「隣どうしの差」なので分母が h、中心差分は「1つ飛ばしの差」なので分母が 2h。
**遠い2点を使うぶん、ノイズが相対的に小さくなる。**

### 9.6 端点はどうするか

中心差分は「前と後ろ」が必要なので、**最初のフレームと最後のフレームには使えない**
（前や後ろが存在しない）。`diff3p` は端点だけ**片側の3点**を使う式に切り替えている。

| フレーム | 使う点 |
|---|---|
| 最初 | 自分・次・その次 |
| 中間 | 前・後（中心差分） |
| 最後 | 前の前・前・自分 |

この片側の式も精度は中心差分と同じ（h² に比例）。
**「3点差分法」という名前は、どの式も3つの点を使うことから来ている。**

### 9.7 正直な話 ― 選定の経緯

上の3つは**数学的な正当化**であって、このプロジェクトで `diff3p` を使っている
直接の理由は違う。**研究室で共有されている標準関数だから**である。

```matlab
% 参考：バイオメカニクス20講 pp. 166
% (2017-05-09, 進矢)
```

つまり複数の手法を比較して選んだのではなく、**教科書に基づく研究室の標準手法を継承している。**
遮断周波数 30 Hz が角速度時代から引き継がれていたのと同じ構造
（ただしそちらは論点1 の感度分析で事後的に根拠がついた）。

**聞かれたときの答え方：**
> バイオメカニクスで標準的に用いられる中心差分（3点差分法）を用いた。
> 前進差分に比べて精度が1桁高く、速度波形に時間的なズレを生じない。
> 出典はバイオメカニクス20講 p.166。

### 9.8 他の選択肢

平滑化と微分を同時に行う手法として **Savitzky-Golay フィルタ**や**スプライン微分**がある。

ただし本研究は 30 Hz のローパスで平滑化を済ませてから微分しているため、
**微分の時点で信号は十分なめらかで、微分法の選択が結果を大きく左右する状況ではない。**

実際、論点1 の感度分析で 30 Hz 以上のピーク値の変化が 0.04 m/s 以内に収まっていたことは、
**微分がノイズを拾って暴れていないことの間接的な証拠**になっている。

## 10. 「何を変更したのか」をどう説明するか

角速度から合成速度・Vx への変更について、聞かれたときの言い方の整理。

### 10.1 変更したのは「操作的定義」

| 階層 | 中身 | 変わったか |
|---|---|---|
| **構成概念**（測りたいもの） | 「スイングの速さ」 | **変わっていない** |
| **操作的定義**（どう測るか） | バット長軸の角速度ピーク → バット先端マーカーの並進速度 | **変わった** |
| 単位 | deg/s → m/s | 変わった |

「定義を変更した」で通じるが、**「操作的定義（operational definition）を変更した」**が正確。
プロジェクト内に `学習用_7_スイングスピード定義決定` というフォルダがあるとおり、
ここは元々「定義」の問題として扱われてきた。

### 10.2 単位の付け替えではない ―― 過去の値と比較できない

**角速度と先端速度は、部分的に違う物理量を測っている。**

| | 測っているもの |
|---|---|
| 角速度 | バットの**向きが変わる**速さ。バット全体が平行移動しても値は増えない |
| 先端の合成速度 | 先端という1点が空間を進む速さ。**回転の寄与＋バット全体の並進の寄与** |

剛体が固定点まわりに純粋回転するなら $v = \omega r$ で換算できるが、
実際のスイングでは手が前に出る（並進する）ため、
**先端速度には角速度が捉えていなかった成分が含まれる。**

→ **過去に deg/s で報告した数値と、今回の m/s の数値は直接比較できない。**
スライド等に角速度の結果が残っている場合は、換算ではなく**置き換え**である点に注意。

### 10.3 「定義が2つある」わけではない

合成速度と Vx を両方出すと「定義が2つあるのはおかしいのでは」と感じるが、
**階層を分ければ解消する。定義は1つで、そこから2つの値を取り出しているだけ。**

```
定義：スイングスピードを「バット先端マーカーの並進速度」で表す   ← 1つだけ
   ↓ この速度ベクトル v(t) から
指標①：合成速度  |v| = √(vx²+vy²+vz²)   ← ノルム
指標②：投手方向成分  vx                   ← X成分
```

コードもそうなっている（`velTop` を1回計算し、そこから2つを導出）。

| 階層 | 用語 | 中身 |
|---|---|---|
| 何を測るか | **定義**（操作的定義） | バット先端マーカーの並進速度 |
| どの値を比較するか | **指標**／**従属変数** | ピーク合成速度、ピーク投手方向速度 |

論文では**従属変数（dependent variable）**と言うのが最もはっきりする。
**「定義は1つ、従属変数は2つ」**なら誤解されない。

### 10.4 説明の例文

> スイングスピードの操作的定義を、バット長軸の角速度から**バット先端マーカーの並進速度**に
> 変更した。この速度ベクトルから、**合成速度のピーク**と**投手方向成分のピーク**の2つを
> 従属変数として算出した。
> なお角速度と先端速度は測っている物理量が異なる（先端速度には並進の寄与が含まれる）ため、
> 以前の deg/s の値とは直接比較できない。

### 10.5 未決 ―― 主要指標をどちらにするか

どちらを**主要指標**とするかを決めておくと、考察が書きやすくなる。

- **主要指標の候補：ピーク合成速度** ―― 一般的な「スイングスピード」に対応し、先行研究と比較できる
- **副次指標の候補：ピーク投手方向速度** ―― 投手方向成分に絞った値

査読では「主要な結果はどれか」を問われる。**解析上の判断なので指導教員に確認すること。**

### 10.6 未決 ―― 変更の理由が明文化されていない

00 には「比較指標を並進速度へ変更する方針としたため」とあるだけで、**なぜ変えたのかが書かれていない。**
考えられる理由は以下だが、**どれが実際の理由だったかを確認して明文化する必要がある。**

- 先行研究の多くが先端の並進速度（m/s）で報告しており、比較可能性が高い
- 野球の文脈で「スイングスピード」と言えば通常は m/s の並進速度を指す
- 角速度は回転しか捉えず、並進の寄与を落としてしまう

論文の方法または考察で問われる部分なので、早めに整理しておくこと。
