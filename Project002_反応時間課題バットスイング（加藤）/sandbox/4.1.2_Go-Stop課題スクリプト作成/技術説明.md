# 4.1.2 Go-Stop課題スクリプト 技術説明

**作成日**: 2026-06-01  
**最終更新日**: 2026-06-01  
**作成者**: 加藤 和郎 (student)

本ドキュメントは、Go-Stop課題実装のための技術的仕様をまとめたものです。
4.1（予備実験用スクリプト）の Go-No Go課題スクリプト（`demo3_4_2_gonogo_pre_regenerate.m`）をベースに作成します。

---

## 1. 概要・目的

野球の打者が投手のリリース後にストライク/ボールを判断するという状況を実験室環境で模擬するため、Go-Stop課題を実装する。

**Go-No Go課題との構造的違い：**

| 課題 | 試行構造 | 認知プロセスの特徴 |
|------|---------|-----------------|
| Go-No Go | Foreperiod後に「Go（緑）」か「Nogo（赤）」のどちらか一方が出る | 動作を「起こすかどうか」の判断 |
| Go-Stop | **全試行で必ずGo（緑）が出る**。Stop試行ではそこから遅れてStop（赤）が追加で出る | 「動き始めた動作を途中でキャンセルできるか」の判断 |

Go-Stop課題の階層構造：
```
Go-NoGo課題の「Go試行」のみを取り出す
        ↓
その一部の試行に、遅れてStop信号を追加する
```

Go-Stop課題は、実際の打者の認知プロセス（スイングを起こし始めた後にボールと判断して中止する）により近い形であり、投手のリリース後の判断状況の模擬として適している。

**位置づけ**: 本プロジェクトの**実験2**として実施予定。

## 2. 課題イメージ

### Go試行
```
白色LED（Ready cue）点灯
  → (Foreperiod: 1.2〜1.8 s)
      → 緑色LED（Go cue）点灯  → スイング実行
```

### Stop試行
```
白色LED（Ready cue）点灯
  → (Foreperiod: 1.2〜1.8 s)
      → 緑色LED（Go cue）点灯  ← ここからスイング開始
          → (SSD: Stop Signal Delay)
              → 赤色LED（Stop cue）点灯  → スイング中止（キャンセル）
```

> **重要**: Stop試行でも必ず緑LED（Go cue）が点灯する。被験者は常に「スイングしようとする」構えを持ち、Stop信号が出たときだけキャンセルを試みる。

---

## 3. ハードウェア構成

4.1（予備実験用スクリプト）と同一のハードウェア構成を使用する。

**AO0**（Qualisysトリガー兼 白色LED）

| 電圧 | 機能 |
|------|------|
| +5V | Qualisysへのトリガー（TTL, positive） |
| -5V | 白色LED点灯（ready cue） |
| 0V  | 消灯 |

**AO1**（緑/赤 LED）

AO1チャンネルに緑と赤のLEDを**正負逆向きに**接続することで、電圧の正負によって点灯色を切り替える。

| 電圧 | 機能 |
|------|------|
| +5V | 緑色LED点灯（go cue） |
| -5V | 赤色LED点灯（stop cue） |
| 0V  | 消灯 |

## 4. タイミング構造

### Go試行（Go-NoGoと同一）

```
AO0  |____|TTTTT|___________|RRRRR|_______________|_____|
AO1  |___________________________________|GGGGG|_____|

     ini  trig  trig_to_ready  ready  Foreperiod   go  off
```

### Stop試行（新規）

```
AO0  |____|TTTTT|___________|RRRRR|___________________________|_____|
AO1  |___________________________________|GGGGG|SSSSS|_____|

     ini  trig  trig_to_ready  ready  Foreperiod  ssd  stop  off

凡例:
  T: +5V トリガー（Qualisys起動）
  R: -5V 白色LED（ready cue）
  G: +5V 緑色LED（go cue）
  S: -5V 赤色LED（stop cue）
  _: 0V 消灯
```

Stop試行は、Go cue（緑）が点灯した後に**SSD（Stop Signal Delay）**だけ遅れてStop cue（赤）が点灯する。AO1は同一チャンネルで電圧を+5V→-5Vと切り替えることで、緑→赤の順に点灯させる。

## 5. タイミングパラメータ

### Go-NoGoから引き継ぐパラメータ（変更なし）

| パラメータ | 変数名 | 値 |
|-----------|--------|-----|
| 最初の消灯時間 | `ini_duration` | 0.1 s |
| トリガー信号幅 | `trig_signal_duration` | 0.1 s |
| トリガー→ready 間隔（初期位置計測用） | `trig_to_ready_interval` | 1.0 s |
| ready cue 提示時間 | `ready_signal_duration` | 0.5 s |
| Foreperiod | `Foreperiod` | **1.2〜1.8 s 可変**（CSV参照） |
| go cue 提示時間（Go試行） | `go_signal_duration` | 0.5 s |
| 最後の消灯時間 | `off_duration` | 0.1 s |
| スイング完了待機時間 | `swing_max_duration` | 5.0 s |

### Go-Stopで新規追加するパラメータ

| パラメータ | 変数名 | 値（暫定） | 備考 |
|-----------|--------|-----------|------|
| Stop Signal Delay | `ssd_duration` | 0.2 s（先行研究参照） | Go cue点灯からStop cue点灯までの遅延 |
| stop cue 提示時間 | `stop_signal_duration` | 0.5 s | |

> **SSDについて**: Stop Signal Delay（SSD）は先行研究を参照して設定する（backlog 4.1.2-a）。実験によっては試行ごとに可変とする場合もある（その場合はCSVに列を追加する）。

## 6. 波形の違い（Go試行 vs Stop試行）

Go-NoGoとの最大の違いは、**waveform1（AO1）の構造が試行タイプによって異なる**点。

### Go試行の waveform1（Go-NoGoと同一）

```
[0V × (ini + trig + trig_to_ready + Foreperiod),  +5V × go_signal,  0V × off]
```

### Stop試行の waveform1（新規）

```
[0V × (ini + trig + trig_to_ready + Foreperiod),  +5V × ssd,  -5V × stop_signal,  0V × off]
```

波形の総出力時間も試行タイプによって異なる：

| 試行タイプ | waveform_duration |
|-----------|------------------|
| Go | `ini + trig + trig_to_ready + Foreperiod + go_signal + off` |
| Stop | `ini + trig + trig_to_ready + Foreperiod + ssd + stop_signal + off` |

---

## 7. プロトコールCSVのフォーマット

Go-No Go課題と同一のフォーマットを使用する（列構成は変わらない）。

| 列名 | 型 | 内容 |
|------|----|------|
| `TrialNum` | 数値 | 試行番号 |
| `Foreperiod` | 数値 | ready cue から go cue までの時間 [秒] |
| `CueText` | 文字列 | `go` または `stop` |

> **SSDをCSVで管理する場合**: Stop試行ごとにSSDを変えたい場合は `SSD` 列を追加し、Go試行は NaN とする。今回のパイロット版はスクリプト内固定パラメータとして扱う。

> **Go : Stop 比率**　→　先行研究を参照して決定予定（backlog 4.1.2-a に追記済み）

## 8. スクリプトの処理フロー

```
① パラメータ設定（Go-NoGoのパラメータ ＋ ssd_duration・stop_signal_duration を追加）
② CSVファイル読み込み（uigetfileでダイアログ選択）
③ DAQ初期化（AO0・AO1）
④ 試行ループ（1試行ずつ手動トリガー）：
     試行番号・CueText・Foreperiodをコンソールに表示
     → Foreperiod検証チェック（> ready_signal_duration）
     → switch文で試行タイプ別に waveform0・waveform1・waveform_duration を生成：
         case 'go'  ：waveform1 = [0V padding, +5V × go_signal, 0V × off]
         case 'stop'：waveform1 = [0V padding, +5V × ssd, -5V × stop_signal, 0V × off]
     → Enterキー待機 → 4秒カウントダウン
     → DAQ出力（preload → start）
     → pause(waveform_duration) → stop(dq) → スイング待機
⑤ エラー時はDAQを0Vに強制リセット（try-catch）
```

## 9. ベーススクリプトからの変更点まとめ

### 9.1 Go-NoGoとの構造比較

| 項目 | Go-NoGo | Go-Stop |
|------|---------|---------|
| Go試行のAO1 | +5V × go_signal → off | 同一 |
| Nogo/Stop試行のAO1 | -5V × nogo_signal → off（1段階） | **+5V × ssd → -5V × stop_signal → off（2段階）** |
| waveform_duration | 全試行同一計算式 | **試行タイプで異なる計算式** |
| switch文の役割 | 電圧値を決めるだけ | **waveform0・waveform1・waveform_durationをまとめて生成** |
| 新規パラメータ | なし | **`ssd_duration`・`stop_signal_duration`** |

### 9.2 変更が不要な箇所

- DAQ初期化・チャンネル設定（`daq`, `addoutput`）
- CSVファイル読み込み（`uigetfile`, `readtable`）
- Foreperiod検証チェック
- Enterキー待機・カウントダウン処理
- `preload` → `start` → `pause` → `stop` の出力フロー
- エラー時の0Vリセット（`try-catch`）
