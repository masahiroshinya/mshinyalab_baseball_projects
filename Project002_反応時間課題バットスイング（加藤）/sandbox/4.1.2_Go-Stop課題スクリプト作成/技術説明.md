# 4.1.2 Go-Stop課題スクリプト 技術説明

**作成日**: 2026-06-01  
**最終更新日**: 2026-06-04  
**作成者**: 加藤 和郎 (student)

本ドキュメントは、Go-Stop課題実装のための技術的仕様をまとめたものです。
4.1（予備実験用スクリプト）の Go-No Go課題スクリプト（`demo3_4_2_gonogo_pre_regenerate.m`）をベースに作成します。

---

## 1. 概要・目的

野球の打者が投手のリリース後にストライク/ボールを判断するという状況を実験室環境で模擬するため、Go-Stop課題を実装する。

**Go-No Go課題との構造的違い：**

| 課題 | 試行構造 | 認知プロセスの特徴 |
|------|---------|-----------------|
| Go-No Go | Foreperiod後に「Go（緑）」か「Nogo（赤）」のどちらか一方が出る | 動作を「起こすかどうか」の判断 |
| Go-Stop | **全試行でまず1回目のGo（緑）が出る**。短い消灯を挟んだ後、Go試行では2回目のGo（緑）、Stop試行ではStop（赤）が出る | 「動き始めた動作を途中で継続/キャンセルできるか」の判断 |

Go-Stop課題の階層構造：
```
Go-NoGo課題の「Go試行」のみを取り出す
        ↓
1回目Go cueで動作開始を促す
        ↓
短い消灯時間を挟む
        ↓
2回目のCueとして Go または Stop を提示する
```

Go-Stop課題は、実際の打者の認知プロセス（スイングを起こし始めた後にボールと判断して中止する）により近い形であり、投手のリリース後の判断状況の模擬として適している。

**位置づけ**: 本プロジェクトの**実験2**として実施予定。

## 2. 課題イメージ

### Go試行
```
白色LED（Ready cue）点灯
  → (Foreperiod: 1.2〜1.8 s)
      → 緑色LED（1回目 Go cue）点灯  → スイング開始
          → 短い消灯
              → 緑色LED（2回目 Go cue）点灯  → スイング継続
```

### Stop試行
```
白色LED（Ready cue）点灯
  → (Foreperiod: 1.2〜1.8 s)
      → 緑色LED（1回目 Go cue）点灯  ← ここからスイング開始
          → 短い消灯
              → 赤色LED（Stop cue）点灯  → スイング中止（キャンセル）
```

> **重要**: Stop試行でも必ず1回目の緑LED（Go cue）が点灯する。被験者はまず「スイングしようとする」構えを持ち、短い消灯後にStop信号が出たときだけキャンセルを試みる。

## 3. ハードウェア構成

4.1（予備実験用スクリプト）と同一のハードウェア構成を使用する。

**AO0**（Qualisysトリガー兼 白色LED）

| 電圧 | 機能 |
|------|------|
| +5V | Qualisysへのトリガー（TTL, positive） |
| -5V | 白色LED点灯（ready cue） |
| 0V  | 消灯 |

**AO1**（緑/赤 LED）

AO1チャンネルに緑と赤のLEDを**正負逆向きに**接続することで、電圧の正負によって点灯色を切り替える。

| 電圧 | 機能 |
|------|------|
| +5V | 緑色LED点灯（go cue） |
| -5V | 赤色LED点灯（stop cue） |
| 0V  | 消灯 |

## 4. タイミング構造

### Go試行

```
AO0  |____|TTTTT|___________|RRRRR|__________________________________|_____|
AO1  |___________________________________|GGGGG|____|GGGGG|_____|

     ini  trig  trig_to_ready  ready  Foreperiod   go1  gap   go2   off
```

### Stop試行

```
AO0  |____|TTTTT|___________|RRRRR|__________________________________|_____|
AO1  |___________________________________|GGGGG|____|SSSSS|_____|

     ini  trig  trig_to_ready  ready  Foreperiod   go1  gap   stop  off

凡例:
  T: +5V トリガー（Qualisys起動）
  R: -5V 白色LED（ready cue）
  G: +5V 緑色LED（go cue）
  S: -5V 赤色LED（stop cue）
  _: 0V 消灯
```

Go-Stop課題では、1回目のGo cue（緑）が点灯した後、わずかな消灯時間を挟んで、2回目のCueを提示する。Go試行では2回目もGo cue（緑）、Stop試行ではStop cue（赤）を提示する。AO1は同一チャンネルで電圧を `+5V → 0V → +5V` または `+5V → 0V → -5V` と切り替える。

## 5. タイミングパラメータ

### Go-NoGoから引き継ぐパラメータ（変更なし）

| パラメータ | 変数名 | 値 |
|-----------|--------|-----|
| 最初の消灯時間 | `ini_duration` | 0.1 s |
| トリガー信号幅 | `trig_signal_duration` | 0.1 s |
| トリガー→ready 間隔（初期位置計測用） | `trig_to_ready_interval` | 1.0 s |
| ready cue 提示時間 | `ready_signal_duration` | 0.5 s |
| Foreperiod | `Foreperiod` | **1.2〜1.8 s 可変**（CSV参照） |
| 1回目 go cue 提示時間 | `first_go_signal_duration` | 0.1 s（暫定） |
| 最後の消灯時間 | `off_duration` | 0.1 s |
| スイング完了待機時間 | `swing_max_duration` | 5.0 s |

### Go-Stopで新規追加するパラメータ

| パラメータ | 変数名 | 値（暫定） | 備考 |
|-----------|--------|-----------|------|
| 1回目Go後の消灯時間 | `go_to_branch_off_duration` | **0.25 s**（2026-06-04 実験で決定） | 1回目Go cueの後、2回目Cueを出す前の短い消灯 |
| 2回目 go cue 提示時間 | `second_go_signal_duration` | 0.5 s | Go試行で提示する2回目Go cue |
| stop cue 提示時間 | `stop_signal_duration` | 0.5 s | Stop試行で提示するStop cue |

> **1回目Goから2回目Cueまでの時間について**: 現在は `first_go_signal_duration + go_to_branch_off_duration` を固定値として扱う。先行研究やパイロット結果に応じて、後から可変化する場合はCSVに列を追加する。

## 6. 波形の違い（Go試行 vs Stop試行）

Go-NoGoとの最大の違いは、**waveform1（AO1）の構造が試行タイプによって異なる**点。

### Go試行の waveform1

```
[0V × (ini + trig + trig_to_ready + Foreperiod),
 +5V × first_go_signal,
  0V × go_to_branch_off,
 +5V × second_go_signal,
  0V × off]
```

### Stop試行の waveform1

```
[0V × (ini + trig + trig_to_ready + Foreperiod),
 +5V × first_go_signal,
  0V × go_to_branch_off,
 -5V × stop_signal,
  0V × off]
```

波形の総出力時間も試行タイプによって異なる：

| 試行タイプ | waveform_duration |
|-----------|------------------|
| Go | `ini + trig + trig_to_ready + Foreperiod + first_go_signal + go_to_branch_off + second_go_signal + off` |
| Stop | `ini + trig + trig_to_ready + Foreperiod + first_go_signal + go_to_branch_off + stop_signal + off` |

Go-No Go課題と同一のフォーマットを使用する（列構成は変わらない）。

|------|----|------|

## 8. スクリプトの処理フロー

```
① パラメータ設定（Go-NoGoのパラメータ ＋ first_go_signal_duration・go_to_branch_off_duration・second_go_signal_duration・stop_signal_duration を追加）
② CSVファイル読み込み（uigetfileでダイアログ選択）
③ DAQ初期化（AO0・AO1）
④ 試行ループ（1試行ずつ手動トリガー）：
     試行番号・CueText・Foreperiodをコンソールに表示
     → Foreperiod検証チェック（> ready_signal_duration）
     → switch文で試行タイプ別に waveform0・waveform1・waveform_duration を生成：
         case 'go'  ：waveform1 = [0V padding, +5V × first_go, 0V × gap, +5V × second_go, 0V × off]
         case 'stop'：waveform1 = [0V padding, +5V × first_go, 0V × gap, -5V × stop, 0V × off]
     → Enterキー待機 → 4秒カウントダウン
     → DAQ出力（preload → start）
     → pause(waveform_duration) → stop(dq) → スイング待機
⑤ エラー時はDAQを0Vに強制リセット（try-catch）
```

## 9. ベーススクリプトからの変更点まとめ

### 9.1 Go-NoGoとの構造比較

| 項目 | Go-NoGo | Go-Stop |
|------|---------|---------|
| Go試行のAO1 | +5V × go_signal → off | **+5V × first_go → 0V × gap → +5V × second_go → off** |
| Nogo/Stop試行のAO1 | -5V × nogo_signal → off（1段階） | **+5V × first_go → 0V × gap → -5V × stop_signal → off** |
| waveform_duration | 全試行同一計算式 | **試行タイプで異なる計算式** |
| switch文の役割 | 電圧値を決めるだけ | **waveform0・waveform1・waveform_durationをまとめて生成** |
| 新規パラメータ | なし | **`first_go_signal_duration`・`go_to_branch_off_duration`・`second_go_signal_duration`・`stop_signal_duration`** |

### 9.2 変更が不要な箇所

- DAQ初期化・チャンネル設定（`daq`, `addoutput`）
- CSVファイル読み込み（`uigetfile`, `readtable`）
- Foreperiod検証チェック
- Enterキー待機・カウントダウン処理
- `preload` → `start` → `pause` → `stop` の出力フロー
- エラー時の0Vリセット（`try-catch`）

### 11.1 uigetfileでCSVファイルを選択できない

#### 事象

STEP 2でプロトコールCSVファイルを選択しようとしても、CSVファイルが表示されない、または選択できない。

#### 原因の分析

`uigetfile` のファイル指定が `'*csv'` になっている場合、CSVファイルの拡張子を表す指定としては不十分な場合がある。CSVファイルを選択対象にする場合は、拡張子の直前にドットを含めて `'*.csv'` と書くのが安全である。

また、MATLABのファイル選択ダイアログが、プロトコールCSVのあるフォルダとは別の場所を開いている場合も、目的のCSVが見つからない。

#### 切り分けの手順

1. `4_4_gostop_pre.m` の `uigetfile` が `uigetfile('*.csv', ...)` になっているか確認する。
2. ファイル選択ダイアログで、`sandbox/4.1.2_Go-Stop課題スクリプト作成/` フォルダを開いているか確認する。
3. そのフォルダ内に `4_4_gostop_pre_protocol_pilot_5trials.csv` が存在するか確認する。

#### 解決策

`uigetfile` の指定を以下のように修正する。

```matlab
[filename, filepath] = uigetfile('*.csv', 'プロトコールファイルを選択してください');
```

その後、ファイル選択ダイアログで以下のCSVを選択する。

```text
4_4_gostop_pre_protocol_pilot_5trials.csv
```

### 11.2 `daq` が認識されない

#### 事象

STEP 3でDAQ初期化を実行した際、以下のエラーが発生した。

```text
関数または変数 'daq' が認識されません。

daq には Data Acquisition Toolbox が必要です。

エラー: 4_4_gostop_pre (行 44)
dq = daq("ni") ;
```

#### 原因の分析

このエラーは、DAQ本体がPCに接続されていないことだけを意味するものではない。より直接的には、MATLABで `daq` 関数を使うために必要な **Data Acquisition Toolbox** が利用できない、またはインストール/ライセンス認識されていないことを示す。

DAQ本体が未接続の場合は、通常は `daq` 関数自体は認識されるが、その後のデバイス検出や `daq("ni")`、チャンネル追加の段階で別のエラーになる可能性が高い。

#### 切り分けの手順

MATLABのコマンドウィンドウで以下を確認する。

```matlab
ver
```

表示された一覧に `Data Acquisition Toolbox` があるか確認する。

次に以下を確認する。

```matlab
which daq
```

`daq` 関数が見つかれば、関数の場所が表示される。見つからない場合は、Data Acquisition Toolbox が現在のMATLAB環境で使えない。

#### 解決策

1. Data Acquisition Toolbox がインストールされているPCで実行する。
2. Toolboxが入っているはずのPCでは、MATLABのアドオン管理またはライセンス状態を確認する。
3. DAQ本体を接続して実験する前に、まず `ver` と `which daq` でToolboxが使えることを確認する。
4. DAQがないPCでコード学習だけ進める場合は、STEP 3以降の実機出力部分は実行せず、波形作成までを確認する。

### 11.3 `go_to_branch_off_duration`（1回目Go後の消灯時間）の適切な値

#### 経緯

2026-06-04 に予備実験（n=2）を実施し、`go_to_branch_off_duration` の値を複数条件で試した。

#### 実験結果

| 設定値 | 被験者の印象 |
|--------|------------|
| 0.1〜0.2 s | 短すぎる（1回目Goと2回目Cueが連続してほぼ区別できない） |
| 0.25 s | 適切（1回目Goから2回目Cueへの切り替えが認識しやすい） |
| 0.3 s | 長すぎる（消灯時間が目立ちすぎて課題の自然さが損なわれる） |

#### 決定値

`go_to_branch_off_duration = 0.25 s`

> **スクリプトへの反映**: 2026-06-04 時点でスクリプト本体（`demo_4_4_gostop_pre.m`）の値は `0.3 s` のまま。次回セッションで `0.25 s` に更新すること。
