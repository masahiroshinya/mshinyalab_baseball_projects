# 4.1 予備実験用スクリプト　技術説明

**作成日**: 2026-05-19  
**最終更新日**: 2026-05-19  
**作成者**: mshinyalab

本ドキュメントは、反応時間課題バットスイング予備実験における刺激呈示スクリプト群の技術的仕様をまとめたものです。
3.4（pre予備実験）からの変更点を中心に記載します。

---

## 1. 実験条件の概要

本予備実験は以下の3条件で構成される。

| 条件 | 内容 | 測定指標 |
|------|------|---------|
| 0. 自由スイング | ready/go cue あり・フォアピリオド固定・自由なスイング動作 | スイングスピード、床反力、バイオメカニクス的指標 |
| 1. 単純選択反応課題 | 緑色LED（Go cue）に反応してスイング | 反応の速さ＋上記指標 |
| 2. Go-No Go課題 | 緑色LED（Go）はスイング、赤色LED（NoGo）は抑制 | 反応の速さ・正確さ＋上記指標 |

## 2. pre予備実験（3.4）からの変更点

### 2.1 Foreperiodの短縮（生態学的妥当性の確保）

**設計方針（A案）：振りかぶり開始〜リリース対応**

| 実験刺激 | 対応する投手動作 |
|---------|---------------|
| 白LED（ready cue）点灯 | 投手が振りかぶりを開始した瞬間 |
| 緑/赤LED（go/nogo cue）点灯 | ボールリリース直前 |

大学・社会人レベルの投手では振りかぶり開始からリリースまでの時間が概ね **1.2〜1.8 s** であることから、この範囲をForePeriodとして採用した。

| パラメータ | pre予備実験（3.4） | 本予備実験（4.1） |
|-----------|------------------|----------------|
| Foreperiod（自由スイング・固定） | 3.0 s | **1.5 s** |
| Foreperiod（単純反応・範囲） | 3.0〜5.0 s | **1.2〜1.8 s** |
| Foreperiod（Go/Nogo・範囲） | 3.5〜5.0 s | **1.2〜1.8 s** |

### 2.2 被験者への指示文の明確化

pre予備実験では口頭での説明のみで統一文がなかったため、本予備実験では各条件の開始前に読み上げる指示文を `予備実験プロトコール.md` に明記した。

## 4. ハードウェア構成

3.3節・3.4節と同じハードウェア構成を使用する。

**AO0**（Qualisysトリガー兼 白色LED）

|------|------|
| +5V | 緑色LED点灯（go cue） |
| -5V | 赤色LED点灯（nogo cue） |
| 0V  | 消灯 |

## 5. 実験プロトコール（タイミング構造）

全3条件で共通のタイミング構造を採用する。

### 5.0 自由スイング

```
Qualisysトリガー → 初期位置計測（1.0s）
→ 白色LED点灯（Ready cue, 0.5s）→（Foreperiod固定: 1.5s）→ 緑色LED点灯（Go cue, 0.5s）
→ バットスイング（自由なスイング動作）
```

### 5.1 単純選択反応課題

```
Qualisysトリガー → 初期位置計測（1.0s）
→ 白色LED点灯（Ready cue, 0.5s）→（Foreperiod: 1.2〜1.8s）→ 緑色LED点灯（Go cue, 0.5s）
→ バットスイング
```

### 5.2 Go-No Go課題

```
Qualisysトリガー → 初期位置計測（1.0s）
→ 白色LED点灯（Ready cue, 0.5s）→（Foreperiod: 1.2〜1.8s）
    → 緑色LED点灯（Go cue, 0.5s）  → バットスイング
    → 赤色LED点灯（NoGo cue, 0.5s）→ スイング抑制
```

## 6. タイミングパラメータ

| パラメータ | 変数名 | 値 |
|-----------|--------|-----|
| 最初の消灯時間 | `ini_duration` | 0.1 s |
| トリガー信号幅 | `trig_signal_duration` | 0.1 s |
| トリガー→ready 間隔（初期位置計測用） | `trig_to_ready_interval` | 1.0 s |
| ready cue 提示時間 | `ready_signal_duration` | 0.5 s |
| Foreperiod（自由スイング） | `foreperiod_fix` | **1.5 s 固定** |
| Foreperiod（単純反応・Go-No Go） | `Foreperiod` | **1.2〜1.8 s 可変**（CSV参照） |
| go/nogo cue 提示時間 | `gonogo_signal_duration` | 0.5 s |
| 最後の消灯時間 | `off_duration` | 0.1 s |
| スイング完了待機時間 | `swing_max_duration` | 5.0 s |

> **`trig_to_ready_interval` の意図：** Qualisysトリガー後の1.0秒間はLEDを消灯したまま静止させ、この期間のモーションデータを**初期位置（分析基準）**として使用する。全3条件で共通の設定。

1試行の波形総出力時間（Foreperiod = F 秒の場合）：

- **自由スイング**：`ini + trig + trig_to_ready + foreperiod_fix + gonogo_signal + off` = **3.3 s**（F=1.5s時）
- **単純反応・Go-No Go**：`ini + trig + trig_to_ready + Foreperiod + gonogo_signal + off` = **1.8 + F 秒**
  - 最短（F=1.2s）：**3.0 s**
  - 最長（F=1.8s）：**3.6 s**

1試行のタイミング図（Foreperiod = F 秒の場合）：

```
AO0  |____|TTTTT|___________|RRRRR|_______________|_____|
AO1  |___________________________________|GGGGG|_____|

     0   0.1  0.2          1.2   1.7        1.2+F  1.7+F

凡例:
  T: +5V トリガー（Qualisys起動）
  R: -5V 白色LED（ready cue）
  G: ±5V 緑/赤LED（go/nogo cue）
  _: 0V 消灯
```

## 8. スクリプトの処理フロー

### 自由スイング（`demo3_4_0_free_pre.m`）

```
① パラメータ設定（電圧値・タイミング・固定Foreperiod = 1.5s）
② DAQ初期化（AO0・AO1）
③ 試行ループ（nTrial = 5）：
     試行番号・Foreperiodをコンソールに表示
     → 波形生成（waveform0・waveform1）
     → Enterキー待機 → 4秒カウントダウン
     → DAQ出力（preload → start）
     → pause(waveform_duration) → stop(dq) → pause(swing_max_duration)
④ エラー時はDAQを0Vに強制リセット（try-catch）
```

### 単純反応・Go-No Go（`demo3_4_1_...` / `demo3_4_2_...`）

```
① パラメータ設定（電圧値・タイミング）
② CSVファイル読み込み（uigetfileでダイアログ選択）
③ DAQ初期化（AO0・AO1）
④ 試行ループ（1試行ずつ手動トリガー）：
     試行番号・CueText・Foreperiodをコンソールに表示
     → Foreperiod検証チェック（> ready_signal_duration = 0.5s）
     → 波形生成（waveform0・waveform1）
     → Enterキー待機 → 4秒カウントダウン
     → DAQ出力（preload → start）
     → pause(waveform_duration) → stop(dq) → pause(swing_max_duration)
⑤ エラー時はDAQを0Vに強制リセット（try-catch）
```

## 10. トラブルシューティング記録

3.4（pre予備実験）で解決済みの内容を引き継ぐ。

### 10.1 Unable to queue additional data while running

**発生状況：** 試行の自動繰り返し実装後、4試行目で発生。

**原因：** `start(dq, 'Finite')` がノンブロッキングで動作するため、次の試行の `preload()` 呼び出し時にDAQが「実行中」状態のままとなりエラーになる。

**解決策：** `pause(waveform_duration)` の後に `stop(dq)` を呼び出してDAQ状態を明示的にリセットする。

---

### 10.2 stop(dq) によるLED点灯なし

**発生状況：** `start(dq, 'Finite')` の直後に `stop(dq)` を追加したところ、LEDが一切点灯しなくなった。

**原因：** `start(dq, 'Finite')` がノンブロッキングの場合、即座に返ってくるため直後の `stop(dq)` が波形出力を強制終了させてしまう。

**解決策：** `stop(dq)` を `pause()` の後に移動し、pause の待ち時間に波形総出力時間を指定する。

```matlab
start(dq, 'Finite');
waveform_duration = ini_duration + trig_signal_duration + trig_to_ready_interval + ...
                    Protocol.Foreperiod(iTrial) + gonogo_signal_duration + off_duration;
pause(waveform_duration);   % 波形完了まで待機
stop(dq);                   % DAQ状態をリセット
```

---

### 10.3 git push 時の non-fast-forward エラー

**発生状況：** コミット後、`git push` を実行した際に `! [rejected] main -> main (non-fast-forward)` というエラーが発生し、プッシュが拒否された。

**原因：** リモートリポジトリ（Github）に、ローカルリポジトリに存在しない新しいコミットが存在するため。他のユーザー（または別PC）のプッシュによってリモートの `main` ブランチが進んでいたことが原因。

**解決策：**
1. リモートの変更をローカルに取り込むために `git fetch` または `git pull` を実行する。
2. 今回は `git pull` のマージ処理が途中で止まっていた（`All conflicts fixed but you are still merging.`）ため、`git commit --no-edit` を実行してマージコミットを完了させた。
3. その後、再度 `git push` を実行することで正常にプッシュが完了した。
