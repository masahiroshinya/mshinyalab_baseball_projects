## 1. 目的

Go/Stop 条件の **Stop 試行を「スイングした（止められなかった）」と「止まった」に分け**、それと各局面の時間（RT・HT・LT・AT）の関係を調べる。

判定には、MLB がマイナーリーグで試験的に使っているハーフスイングの基準を使う。**ノブ（bottom）→ 先端（top）の線が、水平面（X-Y 平面）で 45 度を越えたらスイング**とする。

ここまでの解析（`06_go_vs_stop`）では、Go 試行と Stop 試行の動きが分かれるのは HT の終わりの後だった。今回は、一つ一つの Stop 試行が「止まったか、止まらなかったか」と局面の時間を結びつけて調べる。

## 2. 判定の基準（MLB のハーフスイングの基準）

### 2.1 MLB の定義

- Hawk-Eye でバットを追い、**ノブからバレルを通る線の角度の最大値**で判定する。0 の線は**本塁の前の辺に平行な線**で、**45 度（ファウルラインと同じ角度）を越えたらスイング**、越えなければスイングでない
- 2024 年にアリゾナ・フォールリーグで試され、2025 年に Florida State League（1A）、2026 年に Triple-A で使われている
- 出典：[Baseball America](https://baseballamerica.com/?p=1533517)、[Wikipedia: Check Swing Challenge](https://en.wikipedia.org/wiki/Check_Swing_Challenge)、[MLB.com（2026 年のマイナーのルール）](https://www.mlb.com/news/new-rule-changes-coming-to-minor-leagues-in-2026)。どれも報道や解説で、MLB の規則の原文は見つかっていない。論文で使う前に、原文に近い資料を探す

### 2.2 本実験の座標に当てはめる

本実験の座標：**X+ = 投手方向**、Z+ = 上、Y は本塁の前の辺に平行（右手系なので、捕手から投手を見て Y+ が左）。`m3_analyze_single_trial.m` の 72 行目と同じ。

バットの水平面の向き `b = top − bottom`（x, y だけ）から、次の角度 φ を求める。

```
φ = atan2( b_x , s × b_y )      [deg]

  s = 本塁がある側の Y の向き（右打 −1、左打 +1）
  φ =   0°：バットが本塁の前の辺に平行で、先端が本塁の上
  φ = +45°：先端が投手側へ 45°（ファウルラインと平行）← 判定の線
  φ = +90°：先端が投手方向
  φ = −90°：先端が捕手方向（構えに近い）
```

```
【上から見た図（右打者。左打者は左右が逆）】

                 投手（X+）
                   ↑
          +45° ／  │
             ／    │       ← φ が +45° を越えたら「スイング」
   打者 ●──────────┼──── 0°（本塁の前の辺に平行）
     knob      ＼  │
                  ＼│ −45°
                   ↓
                 捕手（X−）
```

**スイング**：Go cue から 2 s の間で、φ の最大値 ≥ 45°。

### 2.3 右打と左打の s

捕手から見て、右打者は本塁の左（Y+ 側）に立ち、本塁は Y− 側にある。だから右打者は s = −1、左打者は s = +1。

左打は S01・S04・S06・S07・S10（2026-11-11 に、バットの回る向き、骨盤とステップの向き、実験の記録の「打席」の 3 つで確かめた。`01_stride_fxfy` の 3.1 節）。

コードでは、念のため Go 試行のピーク速度の時点（ほぼインパクトの時点で、バットは本塁の前の辺に平行に近い）の `s × b_y` が正になるかを被験者ごとに確かめ、合わなければ警告を出す（9 節の確認 ①）。

### 2.4 使わないフレーム（構えの時の誤判定を防ぐ）

構えやフックの間は、バットが立っている（水平面に投影すると短い）か、先端が本塁と反対側にある。このとき φ の値はあてにならず、45° を越えたように見えることがある。そこで次のフレームは使わない。

- **先端が本塁の側にない**（`s × b_y ≤ 0`）フレーム。この条件で φ は −90°〜+90° に限られる
- **バットが立っている**フレーム：水平面に投影した長さが、3 次元の長さの `MinHorizRatio`（0.5）未満

フォロースルーで先端が本塁の側を越えて回り込むと、そのフレームは使わないことになる。しかし、それより前に +45° を越えているので、判定には影響しない。

### 2.5 4.7 の判定式との違い

`sandbox/4.7_チェックスイング判定基準/技術説明.md` の 3.3 節の式は、本実験の座標とは別の向き（Y+ = 投手方向）を前提にしている。また、「投手方向からの角度 θ > 45°」で判定するので、先端が捕手側を向いた構え（θ ≈ 180°）もスイングと判定されてしまう。このフォルダでは 2.2 節の φ を使う。なお、4.7 の技術説明には git のマージの衝突の印（`<<<<<<< Updated upstream` など）が残っている。直すかどうかはユーザーが判断する。

## 4. 何を比べるか

| | 問い | 方法 |
|---|---|---|
| **0. 確認** | 基準がうまく働いているか | Go 試行はほぼすべて 45° を越えるはず（越えない Go 試行の数を出す）。Go 試行が 45° を越える時刻が、どの局面（HT・LT・AT・ピークの後）にあるかを数える |
| **A. RT** | 止められなかった Stop 試行は、振り始めが早かったか | Stop 試行の RT を、スイングした試行と止まった試行で比べる（被験者ごとの平均の対応のある t 検定。両方の試行がある被験者だけ）。試行単位では、ロジスティックの混合モデル `IsSwing ~ RT + (1|Subject)` も出す |
| **B. 2 回目の刺激のときの局面** | 止められるかどうかは、2 回目の刺激がフックのどこで来たかで決まるか | 「振り始めから 2 回目の刺激までの時間（350 − RT）」を、その被験者の Go 試行の HT の平均で割る（0 = 振り始め、1 = フックの頂点）。スイングした試行と止まった試行で比べる |
| **C. 被験者の戦略** | Go 試行で HT を長くとる被験者ほど、よく止まれるか | 被験者ごとの「止まれた割合」と、Go 試行の RT・HT・LT・AT・HT の終わり（RT + HT）の平均の相関（Spearman、10 名） |
| **D. 止め損ねた試行の局面** | 止め損ねた Stop 試行は、Go 試行より速く進んでいたか | 止め損ねた Stop 試行の RT・HT・LT・AT（x8 の値）を、同じ被験者の Go 試行の平均と比べる（止め損ねた試行がある被験者だけ） |

**感度の確認**：判定の角度を 0°（バットが本塁の前の辺まで来た。昔からの「バットが本塁を横切ったか」に近い）にしたときの、スイングの数も出す（`AngleSensDeg`）。

**予想**：Verbruggen & Logan（2009）の競争モデルでは、止め損ねるのは Go の過程が速かった試行。そうなら、止め損ねた試行は RT が短い（A）、2 回目の刺激が来たときにフックが進んでいる（B）、HT が短い（D）。C で HT の長い被験者ほど止まれるなら、「HT を延ばして判断の時間をかせぐ」（`05_hook_progress`）が止まるのに役立っていることになる。

## 5. 処理の流れ

1. `parameters.m` と `StatTable.mat` を読み、Go/Stop 条件の Go・Stop 試行のうち top を使う試行を選ぶ
2. 被験者ごとに `DataXX.mat` を読む（被験者 1 名ずつ、読み終わったら消す）
3. 各試行で、Go cue から 2 s の窓の bottom の欠損を数える。欠損があれば判定しない
4. top と bottom を、NaN を線形補間して 30 Hz の 2 次 Butterworth で filtfilt する（`06_go_vs_stop` と同じ `prepMarker`）
5. 2.2〜2.4 節の φ を求め、窓の中の最大値（`MaxAngle_deg`）、その時刻、45° を初めて越えた時刻（`TCross_ms`、どれも Go cue から）を記録する
6. 4 節の 0・A〜D を計算して表示し、図と CSV を `output/` に保存する

## 8. コードの説明（段落ごと）

| 段落 | 何をしているか |
|---|---|
| 設定 | 判定の角度（45°）、感度の確認の角度、バットが立っているフレームを除く割合、2 回目の刺激の時刻（350 ms）、左打の被験者。ここを変えれば基準を変えられる |
| パスとデータ | このファイルの場所から Project002 を探し、`parameters.m` と `StatTable.mat` を読む。Go/Stop 条件の Go・Stop 試行で、top を使う試行を選ぶ |
| 試行ごとの角度 | 被験者ごとに x3 を読み、各試行の窓の bottom の欠損を数え、`batAngle` で φ を求め、最大値と 45° を越えた時刻を表に書き込む。φ を Go cue からの共通の時間軸（4 ms ごと）に並べ直して図に使う |
| 判定と確認 | φ の最大値が 45° 以上ならスイング。右打・左打の向きの確認、45° を越えなかった Go 試行、Go 試行が 45° を越える局面、振り始めなしなのにスイングと判定された Stop 試行を表示する |
| A〜D | 4 節の比較。被験者ごとの平均を作ってから検定する（試行の多い被験者に結果が引っぱられないように） |
| 図・保存 | 6 節の図と CSV |
| ローカル関数 | `prepMarker`（補間とフィルタ。06 と同じ）、`batAngle`（φ と使えるフレーム）、`pairedReport`（対応のある t 検定の表示） |

`batAngle` の中身：

```matlab
b    = top - bot ;                % バットのベクトル（knob 側 → 先端）
bx   = b(:,1) ;                   % 投手方向の成分
bl   = side * b(:,2) ;            % 本塁の側の成分（右打は −Y、左打は +Y が本塁の側）
ang  = atan2d(bx, bl) ;           % 0° = 本塁の前の辺に平行、+ = 投手側
ok   = bl > 0 & hypot(b(:,1), b(:,2)) >= minRatio * vecnorm(b, 2, 2) ;
```

- `atan2d(y, x)` は、点 (x, y) の向きを −180°〜180° で返す。ここでは「本塁の側」を横軸、「投手方向」を縦軸にしているので、本塁の側をまっすぐ向くと 0°、投手側へ回るほど大きくなる
- `ok` が false のフレーム（2.4 節）は NaN にしてから最大値をとる

## 9. 実行したら確かめること

1. **右打・左打の向き**：「s × b_y の向きが合わない被験者」の警告が出ないこと。出たら、その被験者の `LeftSubjects` を見直す（S01・S04・S06・S07・S10 が左打）
2. **Go 試行はほぼすべて 45° を越えるか**：越えない Go 試行が多いなら、基準か角度の向きが間違っている。`stop_halfswing_angle_curves.png` で、灰色の線が 45° を越えているかを見る
3. **Go 試行が 45° を越える局面**：AT（ループ最深点 → ピーク速度）かピークの後になるはず。HT の中で越える試行があれば、構えやフックの誤判定（2.4 節）を疑い、その試行の φ を確かめる
4. **振り始めなしなのにスイングと判定された Stop 試行**：あれば誤判定の可能性が高い
5. **Stop 試行の判定を、07_trajectory_viewer の軌道で何本か目で確かめる**（特に φ の最大値が 30〜60° の試行）
6. S03 のデータが再測定の後のものか（`StatTable.mat` の S03 の試行数：Go/Stop 10 試行前後）

## 10. コード案（`stop_halfswing_analysis.m`）

```matlab
% stop_halfswing_analysis.m
%
% Go/Stop 条件の Stop 試行を、MLB のハーフスイングの基準（ノブ → 先端の線が水平面で 45° を越えたらスイング）で
% 「スイングした（止め損ねた）」と「止まった」に分け、局面の時間（RT・HT・LT・AT）との関係を調べる。
%
% 角度 φ = atan2(b_x, s * b_y)、b = top − bottom（水平面）。X+ = 投手方向。
%   s = 本塁の側の Y の向き（右打 −1、左打 +1）
%   φ = 0°：本塁の前の辺に平行（先端が本塁の上）、+45°：ファウルラインと平行（判定の線）、−90°：捕手方向
% 先端が本塁の側にないフレーム、バットが立っているフレームは使わない（構えの誤判定を防ぐ）。
%
% 試行：top を使う試行（x8 と同じ式）のうち、Go cue から 2 s の窓に bottom の欠損がない Go・Stop 試行
% 2026-11-15 作成（未実行の案）。技術説明.md を参照

clear ; clc

%% 設定
AngleThrDeg   = 45 ;          % スイングの判定の角度 [deg]
AngleSensDeg  = [0 45] ;      % 感度の確認に使う角度 [deg]
MinHorizRatio = 0.5 ;         % 水平面の長さ / 3 次元の長さ がこれ未満のフレームは使わない
T2ms          = 350 ;         % 2 回目の刺激（1 回目の Go cue から）[ms]
LeftSubjects  = [1 4 6 7 10] ;% 左打（2026-11-11 に実験の記録と照合）
TAxMs         = (-100 : 4 : 2000)' ;   % 図に使う共通の時間軸（Go cue から）[ms]

scriptFolder   = fileparts(mfilename('fullpath')) ;
projectFolder  = fullfile(scriptFolder, '..', '..', '..', '..') ;   % Project002 のフォルダ
analysisFolder = fullfile(projectFolder, 'Experiments', 'Main experiments', '03_Analysis') ;
outFolder      = fullfile(scriptFolder, 'output') ;
if ~exist(outFolder, 'dir'), mkdir(outFolder) ; end
addpath(analysisFolder) ;
Prm = parameters ;

%% 試行を選ぶ
load(fullfile(analysisFolder, 'x8_StatTable', 'StatTable.mat'), 'TrialTable') ;
T = TrialTable(TrialTable.Condition == "gostop" & ismember(TrialTable.CueText, ["Go" "Stop"]), :) ;
T.UseTop = ~((T.IsBadTop & ~T.KeepTop) | T.IsBadOnset | T.ExclTop) ;
T = T(T.UseTop, :) ;
Subjects = unique(T.Subject)' ;
n = height(T) ;

T.Side          = -ones(n, 1) ;                  % 本塁の側の Y の向き
T.Side(ismember(T.Subject, LeftSubjects)) = 1 ;
T.NNanBottom    = NaN(n, 1) ;
T.BottomOK      = false(n, 1) ;
T.MaxAngle_deg  = NaN(n, 1) ;
T.TMaxAngle_ms  = NaN(n, 1) ;                    % Go cue から
T.TCross_ms     = NaN(n, 1) ;                    % AngleThrDeg を初めて越えた時刻（Go cue から）
T.LatAtPeak     = NaN(n, 1) ;                    % ピーク速度の時点の s * b_y（向きの確認用）
Ang = NaN(n, numel(TAxMs)) ;                     % φ の時間変化（図用）

%% 試行ごとの角度
for iSubject = Subjects
    fprintf('S%02d の x3 を読み込み中...\n', iSubject) ;
    S = load(fullfile(analysisFolder, 'x3_DataChecked', sprintf('Data%02d.mat', iSubject)), 'DataArray') ;
    for r = find(T.Subject == iSubject)'
        Data = S.DataArray(T.Trial(r), 4) ;      % 4 = gostop
        if ~isfield(Data.Markers, 'bottom') || isempty(Data.Markers.bottom), continue, end
        fs   = Data.FrameRate ;
        tCue = T.TCueMarker(r) ;
        nF   = size(Data.Markers.top, 1) ;
        win  = max(1, tCue) : min(nF, tCue + round(Prm.Excl.WinSec * fs)) ;

        T.NNanBottom(r) = sum(any(isnan(Data.Markers.bottom(win, :)), 2)) ;
        T.BottomOK(r)   = T.NNanBottom(r) == 0 ;
        if ~T.BottomOK(r), continue, end

        top = prepMarker(Data.Markers.top,    fs, Prm.Fc) ;
        bot = prepMarker(Data.Markers.bottom, fs, Prm.Fc) ;
        [ang, ok, lat] = batAngle(top, bot, T.Side(r), MinHorizRatio) ;
        ang(~ok) = NaN ;

        tMs = ((1:nF)' - tCue) / fs * 1000 ;      % 各フレームの Go cue からの時刻 [ms]
        a   = ang(win) ;  tw = tMs(win) ;
        [mx, k] = max(a) ;                        % NaN は無視される
        if ~isnan(mx)
            T.MaxAngle_deg(r) = mx ;
            T.TMaxAngle_ms(r) = tw(k) ;
        end

%% ローカル関数
function x = prepMarker(x, fs, fc)
% NaN を線形補間して、2 次 Butterworth で filtfilt する（06_go_vs_stop と同じ。角度だけなので mm のまま）
t = (1:size(x, 1))' ;
for col = 1:3
    nanIdx = isnan(x(:, col)) ;
    if any(nanIdx) && any(~nanIdx)
        x(nanIdx, col) = interp1(t(~nanIdx), x(~nanIdx, col), t(nanIdx), 'linear', 'extrap') ;
    end
end
[b, a] = butter(2, fc / (fs/2)) ;
x = filtfilt(b, a, x) ;
end

function [ang, ok, bl] = batAngle(top, bot, side, minRatio)
% バットの水平面の角度 φ [deg]（0 = 本塁の前の辺に平行、+ = 投手側）と、使えるフレーム
b   = top - bot ;                       % knob 側 → 先端
bx  = b(:, 1) ;                         % 投手方向の成分
bl  = side * b(:, 2) ;                  % 本塁の側の成分
ang = atan2d(bx, bl) ;
ok  = bl > 0 & hypot(b(:, 1), b(:, 2)) >= minRatio * vecnorm(b, 2, 2) ;
end

function pairedReport(name, y1, y2, lab1, lab2)
% 被験者ごとの値の対応のある t 検定（両方そろう被験者だけ）
k = ~isnan(y1) & ~isnan(y2) ;
if sum(k) < 3
    fprintf('  %s：両方の値がある被験者が %d 名しかないので検定しない\n', name, sum(k)) ;
    return
end
[~, p, ~, st] = ttest(y1(k), y2(k)) ;
fprintf('  %s：%s %.3g、%s %.3g（差 %+.3g、t(%d) = %.2f、p = %.3f、%d 名）\n', ...
    name, lab1, mean(y1(k)), lab2, mean(y2(k)), mean(y1(k) - y2(k)), st.df, st.tstat, p, sum(k)) ;
end
```

- **未実行**。列名や `DataArray` の中身は、`x6_analyze_multi_trial.m`・`m3_analyze_single_trial.m`・`06_go_vs_stop/compare_go_stop.m` と、7.2 の技術説明から確かめて書いたが、動かしてはいない。エラーが出たら、内容と対処をこの節に追記する

- 止まった Stop 試行の `HookTime_ms` などは、ピーク速度が「本当のスイングのピーク」でないため意味がない。D では止め損ねた（スイングした）試行の値だけを使う
- 止め損ねた Stop 試行の HT・LT・AT は、2 回目の刺激を見て途中でゆるめた動きも含んでいる可能性がある。Go 試行と同じ動きだったとは限らない
- bottom の基準（窓の中の欠損 0 フレーム）は厳しい。S01・S04・S02 で外れる試行が多い（`7.2` の 6 節）。Stop 試行が少ない被験者が出るなら、基準をゆるめるか検討する
- p 値は MATLAB で出した確認用の値で、本番の統計（JASP など）ではない
