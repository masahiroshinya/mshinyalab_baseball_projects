# Fx の波形で Onset を見直すツール（技術説明）

作成：2026-10-29　加藤 和太郎（student）、Claude Code

## 1. 目的

スイング開始（Onset）の検出をやり直すにあたり、検出に使っている前後方向の合成床反力 Fx を試行ごとに描いて比べる。[top_trajectory_3d](../../2026-10-28/top_trajectory_3d/技術説明.md) と同じように、被験者と条件を出し入れでき、条件または被験者で色分けする。

## 2. 今の Onset の検出（m3_analyze_single_trial、03_Analysis/技術説明.md §12）

| 手順             | 内容                                                                                                                    |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Fx               | `Force1(:,1) + Force2(:,1)`（2 枚のプレートの前後方向の和）を 50 Hz（`Prm.RT.FxFc`）の 2 次 Butterworth で filtfilt |
| 基準値           | キュー前 0.5 s（`Prm.RT.BaseSec`）の Fx の中央値                                                                      |
| 踏み込み足の接地 | キュー後に Fz2 が「キュー前 0.5 s の中央値 + 50 N（`Prm.RT.FootContactN`）」を初めて超えた点。Onset を探す窓の終わり  |
| 閾値             | 基準値 + 0.20（`Prm.RT.FxRatio`）×（キュー〜接地の Fx のピーク − 基準値）                                           |
| Onset            | キュー〜接地で、Fx が下から閾値を跨ぎ、20 ms（`Prm.RT.DurMs`）続けて超えた最初の点                                    |

## 3. データ

| 何に使うか      | ファイル                                                     |
| --------------- | ------------------------------------------------------------ |
| 描く試行の選別  | `03_Analysis/x8_StatTable/StatTable.mat` の `TrialTable` |
| Fx・Fz2・キュー | `03_Analysis/x3_DataChecked/DataNN.mat`                    |

x4・x5 の結果には Fx の波形（`FxFilt`）はあるが、キューと接地の時刻が保存されていない。そこで、x3 から 2 節の計算をやり直す。初回の実行で、計算し直した Onset が x8 の `SwingOnsetForce` と一致するかを確かめ、結果を表示する（2026-10-29 の実行では、441 試行すべてで一致した）。

### 描く試行（除外基準を当てたあと）

画面の「試行の選び方」で 2 通りから選ぶ。

| 選び方                  | 試行                                                                                                            | 数（Go 試行 500 のうち） |
| ----------------------- | --------------------------------------------------------------------------------------------------------------- | ------------------------ |
| RT の除外のあと（既定） | x8 で `RTForce_ms` が残った試行。onset 未検出（除外基準③）、RT < 150 ms（④）、目視の RT の除外を外したもの  | 441                      |
| すべての除外のあと      | 上に加えて、top（①）・床反力（②）の除外で `PeakVelTop`・`MT_ms`・`PeakFz2_BW` が NaN になった試行も外す | 画面の凡例に出る         |

Onset の見直しには RT の除外だけで足りる（Fx は床反力のゼロ点ずれの影響を受けない、03_Analysis/技術説明.md §18）。同じ試行で MT やピーク速度も比べるときは「すべての除外のあと」を使う。

**注意**：onset 未検出（31 試行）と RT < 150 ms（27 試行）の試行は、どちらの選び方でも描かれない。今の検出がうまくいかない試行そのものなので、検出をやり直すときは別に見る必要がある。

抜き出す区間はキューの −500〜+1500 ms（`WinMs`）。記録の外は NaN。

1. 7 節のコードを、このフォルダ（`sandbox/7.1_解析結果/2026-10-29/fx_onset_viewer/`）に `fx_onset_viewer.m` という名前で保存する

## 6. 結果を見て気づいたこと（2026-10-29）

全被験者・全条件（RT の除外のあと、441 試行）の Fx を描き、試行ごとに数値も出して確かめた。値は条件ごとの中央値。

| | Free | Simple | Go/No-go | Go/Stop |
| --- | --- | --- | --- | --- |
| RT（キュー → Onset）(ms) | 275 | 202 | 206 | 240 |
| Onset → 接地 (ms) | 459 | 326 | 338 | 378 |
| Onset 後 50 ms の Fx の傾き (BW/s) | 0.47 | 1.14 | 1.04 | 0.97 |
| Onset からピークの 50% まで (ms) | 87 | 36 | 39 | 41 |
| 閾値（基準値からの高さ）(N) | 18 | 21 | 20 | 20 |
| キュー前の Fx の揺れ（SD）(N) | 6.7 | 8.7 | 7.1 | 8.7 |

1. **Free は Onset のあとの Fx の立ち上がりがゆっくり**。反応課題では Onset から約 150 ms で Fx が一気に約 0.12 BW まで上がるが、Free は傾きが半分以下で、同じ高さに届くのに約 300 ms かかる。接地も Onset から 130 ms ほど遅い。Free の MT の延長（2026-10-28 の ① フックの延長）は、この「ゆっくり体重を移す時間」と対応していそう
2. **S01・S06 の Free は特に遅い**（傾き 0.11・0.22 BW/s、ピークの 50% まで 376・195 ms。S06 の Free は RT の中央値も 506 ms）。Fx が閾値のあたりで長く横ばいになり、その後に本当の立ち上がりが来る試行がある。Onset が、スイングの開始ではなく、小さな体重の移動を拾っている可能性がある
3. **閾値はキュー前の揺れに近い**。閾値（約 20 N）は、キュー前の Fx の揺れ（SD 約 7〜9 N）の 2〜3 倍しかない。別の決め方（キュー後に初めて基準値 ± 3 SD を外れた点）と比べると、中央値はほぼ同じ（差 0 ms 前後）だが、30 ms 以上ずれる試行が 37〜50%、別の決め方の方が 100 ms 以上早い試行が 58 ある。平均の RT は安定しているが、試行ごとの Onset は決め方に敏感
4. **反応課題では、Onset の前に Fx が小さく負に振れる**（平均の波形で約 −0.015 BW、Onset の約 100 ms 前から）。Free にはほとんどない。−3 SD を超える谷がある試行は 8〜17% と少ないが、動き出し（反対向きの小さな動き）が今の Onset より早く始まっている可能性がある。ただし、filtfilt によるわずかな振れの可能性もあるので、生の Fx や他の信号（体のマーカー）で確かめる必要がある
5. **キュー前から踏み込み足が乗っている試行は少ない**：Fz2 の基準値が 50 N を超えるのは 4 試行（S08 の Simple 1、S09 の Simple 3）だけ。前回の「S09 は Onset の前から Fz2 が下がる」はこの 3 試行のことで、S09 全体ではない

Onset の見直しで検討すること：
- Free の Onset を、Fx の「速い立ち上がり」で決めるか、今のように「最初の小さな上がり」で決めるか（何をスイングの開始とするかの定義の問題）
- 閾値をキュー前の揺れ（SD）と比べてどう決めるか
- 4 の「先行する小さな負の振れ」を動き出しに含めるか

### 6.1 閾値を変えると条件差は変わるか（感度の確認、2026-10-29）

閾値の決め方を変えて Onset を検出し直し、RT と MT の条件差が変わるかを確かめた（作業用フォルダ、このツールのキャッシュを使う）。

- 方法：ピークに対する比率を 10・20（今）・30・50% にしたものと、「基準値 + キュー前の揺れの 3 SD・5 SD」。ほかの手順（20 ms 続けて超える、探索窓はキュー〜接地）は同じ。比率 20% で x8 の Onset を 441/441 試行で再現できることを先に確かめた
- MT = （x8 の RT + MT、つまりキュー → ピーク速度）− 新しい RT。試行は RT の除外のあとの 441 試行に固定した（除外された試行は見直していない。新しい RT で 150 ms 未満になった試行も残している）
- 統計は、被験者平均（10 名）の Simple との対応のある t 検定。条件差が残るかを見るための目安で、本番の統計（x9）ではない

| 方法 | 検出できない / RT < 150 ms | RT：Free − Simple | RT：Go/No-go − Simple | RT：Go/Stop − Simple | MT：Free − Simple | MT：Go/No-go − Simple | MT：Go/Stop − Simple |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 20%（今） | 0 / 0 | +112 (p=.007) | +7 (p=.45) | +39 (p<.001) | +154 (p<.001) | +23 (p=.043) | +50 (p=.001) |
| 10% | 2 / 46 | +80 (p=.023) | +8 (p=.56) | +42 (p<.001) | +190 (p<.001) | +23 (p=.064) | +49 (p=.003) |
| 30% | 0 / 1 | +147 (p=.004) | +6 (p=.42) | +42 (p=.002) | +119 (p<.001) | +23 (p=.079) | +46 (p=.007) |
| 50% | 0 / 0 | +196 (p=.003) | +13 (p=.14) | +55 (p<.001) | +71 (p=.007) | +16 (p=.11) | +31 (p=.018) |
| 3 SD | 10 / 24 | +116 (p=.008) | +12 (p=.18) | +50 (p=.002) | +147 (p<.001) | +18 (p=.26) | +38 (p=.013) |
| 5 SD | 59 / 5 | +182 (p=.002) | +29 (p=.015) | +96 (p<.001) | +96 (p=.002) | +5 (p=.83) | −3 (p=.91) |

試行ごとの RT の変化（今との差の中央値）：10% −17 ms、30% +14 ms、50% +44 ms、3 SD +1 ms、5 SD +16 ms。

読み取り：
- **変わらない結果**：Go/Stop の RT・MT の延長、Free の RT・MT の延長、Go/No-go の RT が Simple と同じこと。10〜50% と 3 SD のどれでも同じ向きで、差が残る。5 SD は 59 試行で検出できず、信頼できない
- **閾値に左右される結果**：
  - Go/No-go の MT の延長（+23 ms）。今の閾値では p = .043 だが、他の方法では p = .06〜.26。「Go/No-go でも MT が延びた」と強く言うのは避けた方がよい
  - Free の MT の延長の大きさ（10% で +190 ms、50% で +71 ms）。Free は Fx の立ち上がりがゆっくりなので、閾値を上げるほど Onset が遅れ、延長分が MT から RT に移る。向きは変わらないが、大きさ（と 2026-10-28 の ① フックの延長の大きさ）は Onset の定義に依存する
- **閾値の範囲**：10% はキュー前の揺れで早く検出されやすい（RT < 150 ms が 46 試行）。5 SD は検出できない試行が多い。今の 20%（と 30%、3 SD）は、どちらの問題も小さい

### 6.2 閾値を変えたときの ① フック・② 引き・③ 振り出し（2026-10-29）

2026-10-28 の局面分け（[top_phase_viewer](../../2026-10-28/top_phase_viewer/技術説明.md)）は Onset を起点にしているので、6.1 節と同じ方法で Onset を変え、x3 の top の X から ① ② ③ を計算し直した。試行は x8 で MT が残る 404 試行（S03・S04 は Mark = k の試行を含む。x8 への追加の修正案と同じ）。20%（今）で、修正案の値（① Free 419・Simple 273・Go/No-go 301・Go/Stop 347 ms）を再現した。

| 方法 | ①：Free − Simple | ①：Go/No-go − Simple | ①：Go/Stop − Simple | ②：Free / Go/No-go / Go/Stop − Simple | ③：同じ |
| --- | --- | --- | --- | --- | --- |
| 20%（今） | +146 (p<.001, 10/10) | +28 (p=.019, 9/10) | +74 (p=.003, 10/10) | +4 / −7 / −23 | +4 / +2 / −1 |
| 10% | +183 (p<.001, 10/10) | +27 (p=.045, 8/10) | +73 (p=.005, 10/10) | +4 / −7 / −23 | +4 / +2 / −1 |
| 30% | +111 (p=.001, 10/10) | +28 (p=.032, 9/10) | +69 (p=.008, 9/10) | +5 / −7 / −22 | +4 / +2 / −1 |
| 50% | +62 (p=.034, 8/10) | +23 (p=.019, 9/10) | +53 (p=.019, 9/10) | +5 / −9 / −21 | +4 / +2 / −1 |
| 3 SD | +138 (p<.001, 10/10) | +22 (p=.14, 5/10) | +62 (p=.007, 8/10) | +5 / −6 / −23 | +4 / +2 / −1 |

（ms。被験者平均の平均の差、Simple との対応のある t 検定、Simple より長い被験者の数。②③ はどの方法でも有意差なし。目安の検定で、多重比較の補正はしていない）

読み取り：
- **② 引き・③ 振り出しは、閾値に関係なく同じ**。この 2 つは「引き始め」「最も捕手側」「ピーク速度」というバットの出来事どうしの間隔なので、Onset に依存しない。「延長は ②③ にはない」は Onset の決め方に左右されない
- **① の延長は、どの方法でも Free と Go/Stop で残る**。延長がスイングの前半（引き始めより前）にあることは確か
- **① の延長の大きさは、Free で閾値に大きく依存する**（+62〜+183 ms）。Go/Stop は +53〜+74 ms と比較的安定。Go/No-go（+22〜+28 ms）は 3 SD で有意でなくなる
- 注意：① は「Onset（床反力の出来事）→ 引き始め（バットの出来事）」で、キュー → 引き始めの時間から RT を引いたものと同じ。Free は合図に反応する課題ではないので、Free の ① の長さには「どこからをスイングと呼ぶか」が含まれる

## 7. コード（fx_onset_viewer.m）

- **本体**：設定、データの読み込み（キャッシュ）、画面の部品を作る
- **入れ子関数**：`redraw` が上下の図を描き直す。`selectedTrials` が描く試行を選び、`alignedWaves` が縦軸・時間軸の設定に合わせて波形を変換し、`meanWaves` が平均を求める。`pickTrial` はクリックした試行の情報を出す
- **ローカル関数** `extractFx`：3 節の処理（x3 から 2 節の計算をやり直し、x8 の Onset と照合して、キュー起点で抜き出す）

```matlab
function fx_onset_viewer()
% fx_onset_viewer.m
%
% スイング開始（Onset）の検出に使う前後方向の合成床反力 Fx を、試行ごとに描いて比べるツール。
% 被験者と条件を出し入れし、条件または被験者で色分けする。下段に踏み込み足の Fz（Fz2）を描き、
% Onset の探索窓の終わり（踏み込み足の接地）も見られるようにする。
%
% データ：
%   試行の選別        x8_StatTable/StatTable.mat の TrialTable（Go 試行、x8 の除外を当てたあと）
%   Fx・Fz2・キュー   x3_DataChecked/DataNN.mat から、m3_analyze_single_trial と同じ計算をやり直す
%                    （x4・x5 には Fx の波形はあるが、キューと接地の時刻が保存されていないため）
%   Onset の検出（m3 と同じ）
%     Fx   = Force1(:,1) + Force2(:,1) を 50 Hz（Prm.RT.FxFc）の 2 次 Butterworth で filtfilt
%     基準値 = キュー前 0.5 s の Fx の中央値
%     接地 = キュー後に Fz2 が「キュー前 0.5 s の中央値 + 50 N」を初めて超えた点
%     閾値 = 基準値 + 0.20 ×（キュー〜接地の Fx のピーク − 基準値）
%     Onset = キュー〜接地で、Fx が下から閾値を跨ぎ、20 ms 続けて超えた最初の点
%   抜き出した Onset が x8 の SwingOnsetForce と一致するかを、初回に確かめて表示する。
%
% 使い方：このフォルダで fx_onset_viewer を実行する。
%   初回は x3 を読むので時間がかかる。抜き出した波形は cache/ に保存し、2 回目からはそれを読む。
%   x3・x8 を作り直したとき、または WinMs を変えたときは cache/fx_onset_cache.mat を消してから実行する。
%
% 2026-10-29

%% 設定
WinMs = [-500, 1500] ;   % 抜き出す区間（キュー起点）[ms]

ConditionNameArray = {'free', 'simple', 'gonogo', 'gostop'} ;   % x4 の DataArray の列の並び
ConditionLabel     = {'Free', 'Simple', 'Go/No-go', 'Go/Stop'} ;
ConditionColor     = [0.40 0.40 0.40 ;    % free    灰
                      0.00 0.45 0.70 ;    % simple  青
                      0.90 0.62 0.00 ;    % gonogo  橙
                      0.80 0.20 0.20] ;   % gostop  赤
SubjectColor       = [0.000 0.447 0.698 ; 0.835 0.369 0.000 ; 0.000 0.620 0.451 ; 0.800 0.475 0.655 ; ...
                      0.902 0.624 0.000 ; 0.337 0.706 0.914 ; 0.941 0.894 0.259 ; 0.000 0.000 0.000 ; ...
                      0.500 0.500 0.500 ; 0.600 0.300 0.100] ;   % S01〜S10（x10_plot_by_condition と同じ）

scriptFolder   = fileparts(mfilename('fullpath')) ;
projectFolder  = fullfile(scriptFolder, '..', '..', '..', '..') ;   % Project002 のフォルダ
analysisFolder = fullfile(projectFolder, 'Experiments', 'Main experiments', '03_Analysis') ;
cacheFolder    = fullfile(scriptFolder, 'cache') ;
cachePath      = fullfile(cacheFolder, 'fx_onset_cache.mat') ;
outFolder      = fullfile(scriptFolder, 'output') ;

%% データ（キャッシュがあれば読む）
if exist(cachePath, 'file')
    load(cachePath, 'Tr', 'CacheWinMs') ;
    if ~isequal(CacheWinMs, WinMs)
        error('キャッシュの WinMs が設定と違います。%s を消してから実行してください。', cachePath) ;
    end
    fprintf('キャッシュを読みました：%d 試行\n', numel(Tr)) ;
else
    Tr = extractFx(analysisFolder, ConditionNameArray, WinMs) ;
    CacheWinMs = WinMs ;
    if ~exist(cacheFolder, 'dir'), mkdir(cacheFolder) ; end
    save(cachePath, 'Tr', 'CacheWinMs') ;
    fprintf('キャッシュを保存しました：%s\n', cachePath) ;
end

% Onset・接地の時刻を整数 [ms] にする。配列の番号に使うので、(サンプル − キュー) / 1000 × 1000 の
% 丸め誤差（例：538.99999…）があると「インデックスが無効です」で止まる（技術説明 9.2）
IOn = num2cell(round([Tr.IOnset])) ;  [Tr.IOnset] = IOn{:} ;
IFC = num2cell(round([Tr.IFC])) ;     [Tr.IFC]    = IFC{:} ;

SubjectArray = unique([Tr.Subject]) ;

    function [FxA, FzA, t0] = alignedWaves(kk)
        % 縦軸の設定に合わせた波形（列 = 試行）と、時間軸の 0 にする時刻 t0 [ms]
        FxA = [Tr(kk).Fx] ;
        FzA = [Tr(kk).Fz2] ;
        switch ddY.Value
            case '基準値を引く (N)'
                FxA = FxA - [Tr(kk).FxBase] ;
                FzA = FzA - [Tr(kk).Fz2Base] ;
            case '基準値を引いて体重で割る (BW)'
                FxA = (FxA - [Tr(kk).FxBase])  ./ [Tr(kk).BW] ;
                FzA = (FzA - [Tr(kk).Fz2Base]) ./ [Tr(kk).BW] ;

        switch ddTime.Value
            case 'キュー',           t0 = zeros(1, numel(kk)) ;
            case 'Onset',            t0 = [Tr(kk).IOnset] ;
            case '踏み込み足の接地', t0 = [Tr(kk).IFC] ;
        end
    end

    function [tm, FxM, FzM] = meanWaves(FxA, FzA, t0)

        FzM = mean(FzS, 2, 'omitnan') ;

%% ローカル関数
function Tr = extractFx(analysisFolder, ConditionNameArray, WinMs)
% x8 で RT が残った Go 試行について、x3 から Fx・Fz2 を m3 と同じ手順で計算し、キュー起点で抜き出す

addpath(analysisFolder) ;   % parameters.m
Prm = parameters ;

load(fullfile(analysisFolder, 'x8_StatTable', 'StatTable.mat'), 'TrialTable') ;
T = TrialTable(TrialTable.IsGo & ~isnan(TrialTable.RTForce_ms), :) ;   % RT の除外のあと
% すべての除外のあと：top・床反力の指標も x8 で残っている試行
T.KeepAll = ~isnan(T.PeakVelTop) & ~isnan(T.MT_ms) & ~isnan(T.PeakFz2_BW) ;

Tr = struct('Subject', {}, 'Condition', {}, 'Trial', {}, 'Fx', {}, 'Fz2', {}, 'FxBase', {}, 'FxThr', {}, ...
    'Fz2Base', {}, 'IOnset', {}, 'IFC', {}, 'BW', {}, 'KeepAll', {}) ;
nMismatch = 0 ;

for iSubject = unique(T.Subject)'
    fprintf('S%02d の x3 を読み込み中...\n', iSubject) ;
    S  = load(fullfile(analysisFolder, 'x3_DataChecked', sprintf('Data%02d.mat', iSubject)), 'DataArray') ;
    Ts = T(T.Subject == iSubject, :) ;

    for r = 1:height(Ts)
        iCondition = find(strcmp(ConditionNameArray, Ts.Condition(r))) ;
        Data = S.DataArray(Ts.Trial(r), iCondition) ;
        fsA  = Data.AnalogFs ;

        % キュー（Go 試行は正のパルスが先）
        tCue = find(Data.LEDData(:,2) > Prm.Cue.GoThresholdV, 1, 'first') ;

        % m3 と同じ前処理：末尾の NaN を切り、50 Hz でローパス
        lastValid = find(~any(isnan(Data.Force1), 2) & ~any(isnan(Data.Force2), 2), 1, 'last') ;
        [bR, aR] = butter(2, Prm.RT.FxFc/(fsA/2)) ;
        F1f = filtfilt(bR, aR, Data.Force1(1:lastValid, :)) ;
        F2f = filtfilt(bR, aR, Data.Force2(1:lastValid, :)) ;
        fx  = F1f(:,1) + F2f(:,1) ;
        fz2 = F2f(:,3) ;

        nBase   = round(Prm.RT.BaseSec * fsA) ;
        fxBase  = median(fx( max(1, tCue-nBase) : tCue-1)) ;
        fz2Base = median(fz2(max(1, tCue-nBase) : tCue-1)) ;
        tFC     = find(fz2(tCue:end) > fz2Base + Prm.RT.FootContactN, 1, 'first') + tCue - 1 ;
        fxThr   = fxBase + Prm.RT.FxRatio * max(fx(tCue:tFC) - fxBase) ;

        % x8 の Onset と一致するか（一致しなければ注意を出す。描く Onset は x8 の値）
        tOnset = Ts.SwingOnsetForce(r) ;
        isOver = fx > fxThr ;
        nDur   = round(Prm.RT.DurMs/1000 * fsA) ;
        tCheck = NaN ;
        for k = tCue+1 : (tFC - nDur + 1)
            if ~isOver(k-1) && all(isOver(k : k+nDur-1)), tCheck = k ; break, end
        end
        if tCheck ~= tOnset
            nMismatch = nMismatch + 1 ;
            fprintf(2, '  （注意）S%02d %s Trial %d：計算し直した Onset %g と x8 の %g が違います\n', ...
                iSubject, Ts.Condition(r), Ts.Trial(r), tCheck, tOnset) ;
        end

        % キュー起点で抜き出す（記録の外は NaN）
        ii    = tCue + (WinMs(1):WinMs(2))' ;
        isIn  = ii >= 1 & ii <= numel(fx) ;
        fxW   = NaN(numel(ii), 1) ;  fxW(isIn)  = fx(ii(isIn)) ;
        fz2W  = NaN(numel(ii), 1) ;  fz2W(isIn) = fz2(ii(isIn)) ;

        Tr(end+1).Subject = iSubject ; %#ok<AGROW>
        Tr(end).Condition = char(Ts.Condition(r)) ;
        Tr(end).Trial     = Ts.Trial(r) ;
        Tr(end).Fx        = fxW ;
        Tr(end).Fz2       = fz2W ;
        Tr(end).FxBase    = fxBase ;
        Tr(end).FxThr     = fxThr ;
        Tr(end).Fz2Base   = fz2Base ;
        Tr(end).IOnset    = (tOnset - tCue) / fsA * 1000 ;   % キューからの時刻 [ms]（= RT）
        Tr(end).IFC       = (tFC    - tCue) / fsA * 1000 ;   % キューからの時刻 [ms]
        Tr(end).BW        = Ts.BWest_N(r) ;
        Tr(end).KeepAll   = Ts.KeepAll(r) ;
    end
    clear S
end
fprintf('Onset の照合：%d 試行中 %d 試行が x8 と違う\n', numel(Tr), nMismatch) ;
end
```

## 9. トラブルシューティング

### 9.1 閾値が描かれない・技術説明の更新が消えた（2026-10-29）

- **症状**：閾値の描画を加えたあとも、ツールに閾値が出なかった。技術説明.md からも、閾値の説明と 7 節の新しいコードが消えていた
- **原因**：
  1. 保存していた `fx_onset_viewer.m` が、閾値を加える前の版のままだった
  2. 技術説明.md が、AI が更新したあとに、更新前の内容で上書き保存されていた。表の列幅がそろえられていたので、エディタで開いていた古い内容が、保存時の自動整形とともに保存されたと考えられる
- **切り分け**：保存した .m と、技術説明の 7 節のコードを、AI の最新版と比べた（`diff`）。.m と 7 節は一致していて、どちらも閾値を加える前の版だった。技術説明のファイルの更新時刻（14:17）は AI の更新より後だった
- **対処**：技術説明を更新し直した。.m は 7 節のコードと丸ごと入れ替える
- **予防**：AI が技術説明を更新している間は、エディタで同じファイルを開いたまま保存しない。AI の更新のあとは、エディタでファイルを開き直す（ディスクから再読み込みする）

### 9.2 全員を選んで「接地」にそろえ、平均を描くと止まる（2026-10-29）

- **症状**：全被験者を選び、時間軸の 0 を「踏み込み足の接地」にして平均を描くと、「位置 1 のインデックスが無効です。配列インデックスは正の整数または logical 値でなければなりません」で止まった（`meanWaves` の `FxS(:,j) = FxA(ii, j)`）
- **原因**：接地の時刻 `IFC` を `(サンプル番号 − キュー) / 1000 × 1000` で ms に直していたため、S06 の Free Trial 1 だけ 1001.0000000000（表示上）が、内部では 1000.9999… のような整数でない値になっていた。この時刻を配列の番号に使うところで止まる。この試行を含む表示（S06 の Free を選んで接地か Onset にそろえる、など）でだけ起きる
- **切り分け**：キャッシュの `IFC`・`IOnset` が整数かどうかを調べ、`IFC` の 1 試行だけが整数でないことを確かめた
- **対処**：キャッシュを読んだあと（または作ったあと）に、`IOnset`・`IFC` を `round` で整数にする（7 節のコードの「Onset・接地の時刻を整数 [ms] にする」）。キャッシュは消さなくてよい
- **確認**：被験者（全員と 1 名ずつ）× 時間軸の 0 × 縦軸 × 試行の選び方 × 色分け × 平均の表示の 1188 通りすべてで、止まらずに描けることを確かめた
