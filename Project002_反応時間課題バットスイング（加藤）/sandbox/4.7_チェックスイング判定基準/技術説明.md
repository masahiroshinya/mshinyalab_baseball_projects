## 1. フォルダの目的

本実験における「スイングした / しなかった」の二値判定基準を確立する。

MLBがアリゾナ・フォールリーグ（2024年〜）で試験運用中のチェックスイング自動判定システム（Hawk-Eye使用）の定義を採用し、実験室環境で再現可能な形に実装する。

---

## 2. MLB チェックスイング判定システムの定義

### 判定基準

> **バットヘッドがバットノブより45度以上前方に出た場合 → スイング（Strike）**
> **45度未満で止まった場合 → ノースイング（No swing）**

「前方45度」とは、投手方向（0°）を基準に、右打者では一塁ファールライン方向、左打者では三塁ファールライン方向に相当する。

```
【水平面上の角度定義（右打者・上面図）】

           投手方向 (0°)
                │
   ─────────────┼───────────── 打者に対する垂直線
                │
   三塁方向     │     一塁方向
  (135°)        │        (45°) ← スイング判定閾値
                │
           捕手方向 (180°)

バットヘッドの水平方向角度 > 45° → SWING
バットヘッドの水平方向角度 ≤ 45° → NO SWING
```

### 測定の考え方

- 角度は「バットノブを起点とした、バットヘッドの水平方向ベクトル」と「投手方向ベクトル」のなす角で定義する
- Hawk-Eyeシステムでは複数カメラでバット位置をリアルタイムトラッキングし、最大到達角度を記録する

### 参照

- MLB公式発表（2024年10月）: [mlb.com](https://www.mlb.com/news/mlb-testing-check-swing-challenge-in-arizona-fall-league)
- Wikipedia: [Check Swing Challenge](https://en.wikipedia.org/wiki/Check_Swing_Challenge)

## 3. 実験室環境への実装

### 3.0 実験室座標系（確定）

Qualisysのグローバル座標系は以下の通り確定している。

```
【実験室座標系（上面図）】

           Y+ （投手方向）
            ↑
            │
 X-         │         X+
 三塁側 ←───┼───→ 一塁側（投手から見て右）
（左打者スイング方向）  （右打者スイング方向）
            │
           Y- （捕手方向）

Z+ = 鉛直上方
```

この座標系において：

- **投手方向 = Y+ 方向** と定義されているため、基準方向ベクトルは `[0, 1]` 固定
- **追加の基準マーカーは不要**（座標系自体が基準を与える）
- 打者がキャプチャ体積内のどこに立っていても判定式は同一

> **重要（2026-07-28 追記）：この Y+ は「本実験でこれから校正する向き」であって、予備実験の実測値ではない。**
> 予備実験（2026-0604）のデータは `s3b_check_velocity_components.m` により
> **X+ = 投手方向**（両被験者 40/40）と確定している。
> したがって本節の `ref_vec_h = [0, 1]` を予備実験データにそのまま適用すると**判定軸が 90 度ずれる**。
> 実装では軸の割り当てを `parameters.m` の設定値（`Prm.CS.AxisFwd`）として外出しし、
> どちらの校正でも同じ判定式が使えるようにする。
> 詳細と実装案：[02_チェックスイング判定.md](<../../Experiments/Preliminary%20experiments/2026-0604/MATLAB/予備実験解析し直し/02_チェックスイング判定.md>)
>
> あわせて、**左右どちら側がスイング側か（水平軸の符号）は s3b でも未確認**であり、
> 実測で確定させる必要がある（同文書 §2・§5.3 の `s4a`）。

### 3.1 必要なマーカー構成

確定した座標系により、基準マーカーは不要となった。

| マーカー種別                       | 具体的な配置                  | 役割                                              |
| ---------------------------------- | ----------------------------- | ------------------------------------------------- |
| バット剛体マーカー（既存）         | バット本体に複数貼付          | バットの位置・姿勢の追跡                          |
| **ノブマーカー**             | バットグリップ端（最下部）    | 角度計算の原点（既存の`bottom` マーカーが相当） |
| **ヘッド（バレル）マーカー** | バット先端                    | 角度計算の先端点                                  |
| ~~ホームベース基準マーカー~~      | ~~打者の足元~~               | **不要**（座標系で代替）                    |
| ~~投手方向基準マーカー~~          | ~~ホームベースから投手方向~~ | **不要**（Y+軸が投手方向）                  |

### 3.3 判定アルゴリズム

#### ステップ1：バットベクトルの算出（水平面に投影）

```matlab
head_pos  = Data.Markers.top;          % ヘッド（バレル先端）マーカー
knob_pos  = Data.Markers.bottom;       % ノブ（グリップ端）マーカー
bat_vec   = head_pos - knob_pos;       % 3次元ベクトル
bat_vec_h = bat_vec(1:2);              % [x, y] のみ抽出（Z除去）
```

#### ステップ2：基準方向ベクトル（固定値）

座標系確定により、投手方向は常に Y+ = `[0, 1]` で固定。

```matlab
ref_vec_h = [0, 1];
```

#### ステップ3：水平面上の角度を計算

```matlab
cos_theta = dot(bat_vec_h, ref_vec_h) / norm(bat_vec_h);
theta = acosd(cos_theta);   % 0〜180° の値を返す
```

#### ステップ4：スイング方向の符号確認と判定

`acosd` は常に正の値を返すため、バットがどちら側（一塁側／三塁側）に振られたかを X 成分の符号で区別する。

```matlab
% 右打者（スイング方向 = X+ = 一塁側）
if strcmp(batter_handedness, 'right')
    is_swing_direction = (bat_vec_h(1) > 0);   % X+ 側に振れているか
% 左打者（スイング方向 = X- = 三塁側）
else
    is_swing_direction = (bat_vec_h(1) < 0);   % X- 側に振れているか
end

% 最終判定
if theta > 45 && is_swing_direction
    result = 'SWING';
else
    result = 'NO SWING';
end
```

> **補足**：`is_swing_direction` のチェックは、バットがまだローディング（構え）の位置にある時刻フレームを誤ってSWINGと判定することを防ぐ。MLBシステムと同様、**試行全体の時系列データにおける最大到達角度**を判定に使用すること。

#### アルゴリズム全体のまとめ（1試行分）

```matlab
% 入力: head_pos_ts, knob_pos_ts（各フレームの3D座標、Nx3行列）
% 入力: batter_handedness ('right' or 'left')

max_theta = 0;

for i = 1:size(head_pos_ts, 1)
    bat_vec_h = head_pos_ts(i,1:2) - knob_pos_ts(i,1:2);
    ref_vec_h = [0, 1];
    theta = acosd( dot(bat_vec_h, ref_vec_h) / norm(bat_vec_h) );

    if strcmp(batter_handedness, 'right') && bat_vec_h(1) > 0
        max_theta = max(max_theta, theta);
    elseif strcmp(batter_handedness, 'left') && bat_vec_h(1) < 0
        max_theta = max(max_theta, theta);
    end
end

if max_theta > 45
    result = 'SWING';
else
    result = 'NO SWING';
end
```

### 3.4 ノブマーカーとヘッドマーカーについて（確定）

バット剛体のマーカー構成を実データで確認した結果、以下の5マーカーが定義されている（グリップ端からバレル先端に向かって配置）。

```matlab
batMarkerNameArray = {'top', 'first', 'second', 'third', 'bottom'};
```

参照：[step3_forstudy_visualize_all_bat_markers.m](<../../Preliminary%20experiments/2026-0604/MATLAB/分析学習/学習用_4_全バットマーカー追跡/step3_forstudy_visualize_all_bat_markers.m>)（24行目）

チェックスイング判定に必要な2点は、このマーカーセットからそのまま取得できる。

| 役割                           | マーカー名 | 備考                                               |
| ------------------------------ | ---------- | -------------------------------------------------- |
| **ヘッド（バレル先端）** | `top`    | バット先端。ヘッドマーカーが実在することを確認済み |
| **ノブ（グリップ端）**   | `bottom` | 技術説明3.4で既に定義済み                          |

**ヘッドマーカー（`top`）が実在するため、バット長を事前計測してノブからヘッド位置を推定する代替手段は不要。** `top` と `bottom` の実測座標を判定式へ直接投入できる。

```matlab
head_pos = Data.Markers.top;      % ヘッド（バレル先端）
knob_pos = Data.Markers.bottom;   % ノブ（グリップ端）
```

> **残る確認事項**：`top` がバレルの「最先端」か、先端寄りの中間点かによって角度がわずかに変わる。マーカー貼付位置の実測（4.6_AIM貼付位置）と照合しておくと精度が担保される。

## 4. 実装上の注意点

| 項目                              | 注意内容                                                                                                              |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **水平面への投影**          | この基準は水平面上の角度のみを使用する。打ち下ろし・打ち上げ方向（仰角）は判定に含まれない                            |
| **最大角度の使用**          | MLBのシステムはスイング中の最大到達角度で判定する。したがって、1試行分の時系列データ全体のピーク値を使用する          |
| **左右打者の対応**          | 右打者は一塁側（+45°）、左打者は三塁側（−45°）に対して同様の判定を行う                                             |
| ~~**バット長の計測**~~     | ~~ヘッドマーカーがない場合は事前にバット長を計測しておく~~　→ `top`（ヘッド）マーカーが実在するため**不要** |
| ~~**基準マーカーの固定**~~ | ~~キャリブレーション中に基準マーカーが動かないよう、重りや固定テープを使用する~~                                     |
