## 3. 段階1：疑似的な1試行を作る（`d1_fake_trial.m`）

**狙い**：実験データの構造（250 Hz のマーカー系、キューがあり、その後にスイングが起こる）を最小限で真似る。サンプル番号と時刻の対応を体で覚える。

```matlab
% d1_fake_trial.m
% 疑似的な1試行の速度波形を作って描く

clear ; close all

fs      = 250 ;              % サンプリング周波数 [Hz]
dur     = 3 ;                % 記録長 [s]
nSample = dur * fs ;         % 総サンプル数 = 750

idx = (1:nSample)' ;         % サンプル番号 1〜750（列ベクトル）
t   = (idx - 1) / fs ;       % 時刻 [s] 0〜2.996

% ---- 正解として決めておく値 ----
tCue   = 1.0 ;               % キュー呈示の時刻 [s]
rtTrue = 0.45 ;              % 真の反応時間 [s]
tOnset = tCue + rtTrue ;     % 動作開始の時刻 = 1.45 s

% ---- 速度波形（動作開始からピークまで立ち上がるガウス波形）----
peakVel = 5 ;                                       % ピーク速度 [m/s]
tPeak   = tOnset + 0.20 ;                           % ピークの時刻
vel     = peakVel * exp( -(t - tPeak).^2 / (2*0.08^2) ) ;

% ---- ノイズを足す（実データのベースラインの揺らぎを模す）----
rng(0)                                              % 乱数を固定（毎回同じ図になる）
vel = vel + 0.02 * randn(nSample, 1) ;

figure
plot(t, vel)
xlabel('Time [s]')
ylabel('Velocity [m/s]')
title('疑似1試行データ')
```

### 3-2. 速度波形の式の意味（ガウス関数）

```matlab
vel = peakVel * exp( -(t - tPeak).^2 / (2*0.08^2) ) ;
```

この1行は**ガウス関数（釣鐘型の山）**です。数学の書き方に直すと次の形です。

$$v(t) = A \cdot \exp\left(-\frac{(t - \mu)^2}{2\sigma^2}\right)$$

| 記号 | コード | 値 | 役割 |
| --- | --- | --- | --- |
| $A$ | `peakVel` | 5 | 山の**高さ**＝ピーク速度 [m/s] |
| $\mu$ | `tPeak` | 1.65 s | 山の**中心**＝ピークの時刻 |
| $\sigma$ | `0.08` | 0.08 s | 山の**幅**（標準偏差）。大きいほど間延びしたスイングになる |

**なぜこの形か**：実際のスイングの速度波形は「静止 → 加速 → ピーク → 減速 → 静止」という山型です。これを最小の部品で作れるのがガウス関数です。式が滑らかで微分しても連続なので、後で加速度を計算しても破綻しません。

**なぜ山型になるか**：指数の中身 $-(t-\mu)^2 / (2\sigma^2)$ に注目します。

- $t = \mu$（ピークの瞬間）は分子が 0 なので `exp(0) = 1`。よって `vel = peakVel × 1 = 5`
- $t$ が $\mu$ から離れると $(t-\mu)^2$ は必ず**正**になり、頭のマイナスで**負**の指数になる
- 負の指数の `exp` は 0 に向かって急速に小さくなる

| ピークからの隔たり | 指数の中身 | `exp(…)` | `vel` [m/s] |
| --- | --- | --- | --- |
| 0 s | 0 | 1.000 | 5.00 |
| 0.08 s（= 1σ） | −0.5 | 0.607 | 3.03 |
| 0.16 s（= 2σ） | −2.0 | 0.135 | 0.68 |
| 0.20 s | −3.125 | 0.044 | **0.22** |
| 0.24 s（= 3σ） | −4.5 | 0.011 | 0.06 |

山の幅の目安は**半値全幅** $2.355\sigma \approx 0.19$ 秒。「速度がピークの半分以上ある時間」が約 190 ms のスイングになります。

**`.^` である理由**：`t` は 750 個並んだ列ベクトルです。`.^2` は**要素ごとの2乗**で、750 個それぞれを2乗します。ドットなしの `^2` は行列のべき乗を意味するので `[750×1]` では次元が合わずエラーになります。`exp()` はもともと要素ごとに働くのでドットは不要です。

**`0.20` と `0.08` は仕込みである**：`tOnset = tPeak - 0.20` としたので、**動作開始の瞬間の速度は 0.22 m/s**（上表の4行目）です。一方ノイズは `0.02 * randn` なのでベースラインの SD は 0.02 m/s。

$$\text{閾値} = 10\,\text{SD} = 0.2 \text{ m/s}$$

実データと同じ「ベースラインの 10 SD」という基準（`Prm.RT.FzK = 10`）で検出すると、ちょうど `tOnset` 付近で閾値を横切ります。段階3 で正解 0.45 s に近い RT が出るよう、あらかじめ辻褄を合わせてあります。

`0.08` を `0.15` に変えると山が緩やかになり、閾値を横切る時刻が**早まって** RT が短く出ます。段階3 でここを動かすと、「立ち上がりの緩急で RT が変わる」という実データの本質的な問題を体験できます。

### 3-3. 確認すること

1. `idx` と `t` の対応。`idx = 1` が `t = 0`、`idx = 251` が `t = 1.0` になる（`(251-1)/250`）。**これが `time_from_cue.m` の式そのもの**（§6-2）。
2. `size(t)` と `size(vel)` が両方 `750 1` であること。`plot(t, y)` は x と y の長さが同じでないと描けない。
3. `rng(0)` をコメントアウトして2回実行し、ノイズの形が毎回変わることを見る。

### 3-4. 使っている命令

| 命令                 | 意味                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------------ |
| `(1:nSample)'`     | 1 から nSample までの連番。`'` は転置（横→縦の列ベクトルにする）                                          |
| `.^` `.*` `./` | 要素ごとの演算。ベクトルの各要素に対して計算する（`^` だと行列のべき乗になり、エラーまたは別の結果になる） |
| `exp()`            | 指数関数。ここではガウス（釣鐘）形の山を作るために使う                                                       |
| `randn(n,1)`       | 平均0・標準偏差1の正規乱数を n 個。実測ノイズの代用                                                          |
| `rng(0)`           | 乱数の種を固定する。毎回同じ乱数列になるので、図を人と共有できる                                             |

### 4-1. 段階2：`d2_plot_basic.m`（2026-08-25 着手）

**狙い**：波形の上に、意味のある線（イベントの縦線・閾値の横線）を重ねる。`d1` の合成データを使う。

```matlab
% d2_plot_basic.m
% 疑似1試行データに、イベント縦線と閾値横線を重ねて描く

clear ; close all

%% ---- 1. 疑似データ（d1 と同じ）----
fs      = 250 ;
dur     = 3 ;
nSample = dur * fs ;

idx = (1:nSample)' ;
t   = (idx - 1) / fs ;

tCue   = 1.0 ;
rtTrue = 0.45 ;
tOnset = tCue + rtTrue ;

peakVel = 5 ;
tPeak   = tOnset + 0.20 ;
vel     = peakVel * exp( -(t - tPeak).^2 / (2*0.08^2) ) ;

rng(0)
vel = vel + 0.02 * randn(nSample, 1) ;

%% ---- 2. 時間軸をキュー基準に直す ----
tRel = t - tCue ;            % キューが 0 になる。d1 の t は試行先頭が 0 だった

%% ---- 3. ベースライン統計と閾値 ----
isBase = tRel >= -0.5 & tRel < 0 ;      % キュー直前 0.5 秒（論理インデックス）
baseMean = mean( vel(isBase) ) ;
baseSD   = std(  vel(isBase) ) ;

k   = 10 ;                              % 実データの Prm.RT.FzK と同じ値
thr = baseMean + k * baseSD ;

fprintf('baseMean = %.4f, baseSD = %.4f, thr = %.4f m/s\n', baseMean, baseSD, thr)

%% ---- 4. 描画 ----
figure
ax = axes ;

plot(tRel, vel, 'k', 'LineWidth', 1.0, 'DisplayName', 'Hand velocity')
hold on

set(ax, 'XLim', [-0.5 1.5])             % ★ 線を引く前に表示範囲を確定させる

xline(0,      'b--', 'LineWidth', 1.5, 'DisplayName', 'Cue')
xline(rtTrue, 'r--', 'LineWidth', 1.5, 'DisplayName', 'True onset')
yline(thr,    'm:',  'LineWidth', 1.2, 'DisplayName', 'Threshold (mean+10SD)')

xlabel('Time from cue [s]')
ylabel('Velocity [m/s]')
title('段階2：波形＋イベント縦線＋閾値横線')
legend('Location', 'northwest')
```

**確認すること**

1. **青の破線が x = 0 に立っていること。** `tRel` を作らず `t` のまま描くとキューは x = 1.0 に来る。実データでこれをやると、RT が「キューからの時間」でなくなる。
2. **`XLim` を `[-1 2]` に変えても、縦線・横線が図の端まで伸びること。** `xline`/`yline` は軸範囲に追従する無限直線なので伸びる。
3. **紫の閾値線と波形が交わる点が、赤の破線（真の onset = 0.45 s）とほぼ同じ位置にあること。** ここが段階3 で自動検出する点。目で見て「どこを検出すべきか」を先に把握しておく。

**★ の行（軸範囲を先に確定させる）について**

実データで使う `lineplot.m` への布石。`lineplot` は `xline` と違い、**呼ばれた時点の `XLim`/`YLim` を読んで、その範囲ぶんの線分を `plot` で描く**実装である（`lineplot.m` 38〜39行目で `XLim`/`YLim` を取得し、最後に元へ戻している）。線を引いた後で軸範囲を広げると、線が途中で切れて見える。

したがって実データでは必ず「**波形 → 軸範囲の設定 → 縦線・横線**」の順序を守ること（§6-3）。合成データの段階からこの順序に慣れておく。余裕があれば `addpath` で `03_Analysis` にパスを通し、`xline(0,'b--')` を `lineplot(0,'v','b--')` に置き換えて、軸範囲を後から変えたときの挙動の違いを見る。

**完了判定**：キュー線が x = 0 に立ち、`XLim` を変えても縦線・横線が図の端まで伸びる。`baseSD` が 0.02 付近（合成時に与えたノイズの SD）になっている。


### 4-2. 段階3：`d3_detect_onset.m`

**狙い**：閾値を超えた最初の点を探す＝RT 検出のミニチュア。

- ベースライン区間（キュー直前 0.5 秒）の平均と SD を出す
- `find(abs(vel - mu) > k*sd, 1)` で最初の逸脱サンプルを探す
- サンプル番号を秒に直し、`rtTrue`（正解 0.45 s）と比べる

**完了判定**：検出された RT が `rtTrue` の ±20 ms 程度に収まる。ノイズの大きさ（`0.02` の係数）や `k` を変えると、検出が早まったり失敗したりすることを確認する。

> ここで体験する「ノイズを一瞬拾って RT が極端に短くなる」現象は、実データで実際に起きている問題そのものです（§8 の `gostop` 行10：RTForce = 107 ms）。

### 4-3. 段階4：`d4_subplot_link.m`

| `addpath`          | MATLAB が関数ファイルを探しに行くフォルダを追加する                                                                                                       |
| `fullfile`         | フォルダ名をつないでパスを作る。OS ごとの区切り文字の違いを吸収する                                                                                       |
| `'omitnan'`        | 平均などの計算で NaN を無視するオプション。付けないと結果が NaN になる                                                                                    |
| `linkaxes`         | 複数の axes の軸を連動させる。1枚を拡大すると他も同じ範囲になる                                                                                           |

### B. この研究・このデータの言葉

| 用語                        | 意味                                                                                                                     |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| サンプリング周波数          | 1秒あたり何回記録したか [Hz]。250 Hz なら1秒に250個。本書では`fs`                                                      |
| フレーム番号 / サンプル番号 | 記録の「何個目か」を表す整数。1から始まる。**秒に直すには fs で割る**                                              |
| マーカー系 / アナログ系     | 本データは記録の速さが2種類（§6-1）。マーカー系＝反射マーカーの座標（250 Hz）、アナログ系＝電圧（LED・床反力、1000 Hz） |
| キュー（cue）               | 被験者への合図。本実験では LED の点灯                                                                                    |
| Go / NoGo / Stop            | 試行の種類。Go＝振ってよい、NoGo＝振ってはいけない、Stop＝Go の後に「やめろ」が出る                                      |
| onset                       | 動作開始。動き出した瞬間の時刻                                                                                           |
| RT                          | Reaction Time（反応時間）。**キューから onset までの時間**                                                         |
| 閾値（しきいち）            | 「これを超えたら動き出したとみなす」境目の値                                                                             |
| ベースライン                | 静止しているときの基準値。本実験ではキュー直前 0.5 秒の平均                                                              |
| SD                          | 標準偏差。ばらつきの大きさ。「10 SD 逸脱」＝平常時のばらつきの10倍ぶん外れた                                             |
| 床反力（GRF）               | 床が身体を押し返す力。`Fz` は鉛直成分 [N]                                                                              |
| BW                          | body weight。力を体重で割って無次元化したもの                                                                            |
| 目視確認                    | 図を目で見て、計算結果が妥当かを人が判断すること                                                                         |

## 6. 実データの前提（合成データを卒業したら読む）

ここから先は、`Experiments/Main experiments/03_Analysis/` の実データに適用するための情報です。**段階4 が終わるまでは読まなくて構いません。**

### 6-1. データは2つのサンプリング周波数を持つ

| 系統       | 周波数の取得元     | 実測値（S01） | 何が入っているか                                                                      |
| ---------- | ------------------ | ------------- | ------------------------------------------------------------------------------------- |
| マーカー系 | `Data.FrameRate` | 250 Hz        | マーカー座標、そこから作った速度（`VelHandX`, `NetVelTop`, `VelTopX`）          |
| アナログ系 | `Data.AnalogFs`  | 1000 Hz       | LED 信号（`Data.LEDData`）、床反力（`Data.Force1/2`, `Result.Fz1Filt/Fz2Filt`） |

**同じ「時刻」でも、系統が違えば番号が違います。** 「試行開始から1秒後」はマーカー系で 251 個目、アナログ系で 1001 個目です。一方の番号をもう一方に直す計算は次の1行です。

```matlab
tCueAnalog = round(Result.TCueMarker / Data.FrameRate * Data.AnalogFs) ;
```

> ⚠️ **最大の罠**：`SwingOnsetHand` は 250 Hz のフレーム番号、`SwingOnsetForce` は 1000 Hz のサンプル番号です（`03_Analysis/技術説明.md` §5.3）。同じ数値でも指す時刻が4倍違います。`Result.SwingOnset`（`Prm.RT.PrimaryMethod` による別名）はどちらの単位か分からないため、**可視化では別名を使わず、必ず `SwingOnsetHand` / `SwingOnsetForce` を明示的に扱うこと。**

### 6-2. 描きたい信号・イベント・閾値の所在

**信号（波形）**

| 信号                               | 変数                                      | 系統     | 単位                                               |
| ---------------------------------- | ----------------------------------------- | -------- | -------------------------------------------------- |
| 手部の投手方向速度                 | `Result.VelHandX`                       | マーカー | m/s                                                |
| 後ろ足の鉛直床反力                 | `Result.Fz1Filt`                        | アナログ | N                                                  |
| 踏み込み足の鉛直床反力             | `Result.Fz2Filt`                        | アナログ | N                                                  |
| LED 信号                           | `Data.LEDData(:,2)`                     | アナログ | V（ch2 = cue、正=Go／負=NoGo・Stop。ch1 は ready） |
| バット先端の合成速度／投手方向速度 | `Result.NetVelTop` / `Result.VelTopX` | マーカー | m/s（応用先）                                      |

**イベント（縦線）**

| イベント               | 変数                       | 系統                            |
| ---------------------- | -------------------------- | ------------------------------- |
| LED キュー             | `Result.TCueMarker`      | マーカー（これを時刻 0 にする） |
| 動作開始（Nasu 方式）  | `Result.SwingOnsetHand`  | **マーカー**              |
| 動作開始（床反力方式） | `Result.SwingOnsetForce` | **アナログ**              |
| 手部速度のピーク       | `Result.TPeakVelHandX`   | マーカー                        |
| バット先端速度のピーク | `Result.TPeakVelTop`     | マーカー（応用先）              |

**閾値（横線）**

| 方式       | 閾値の値                                                       | どこから取るか                        |
| ---------- | -------------------------------------------------------------- | ------------------------------------- |
| 床反力方式 | `Fz1BaseMean ± Prm.RT.FzK * Fz1BaseSD`（**上下2本**） | `Result` に保存済み。試行ごとに違う |
| Nasu 方式  | `Prm.RT.HandThrRatio × 全試行の平均ピーク速度`（1本）       | `Result.ThrVelHandX`（§6-4）       |

床反力方式の判定式 `abs(Fz1 - mu) > k*sd` は「Fz1 が平常時の平均から、上にでも下にでも、平常時のばらつきの k 倍より大きく外れたら」という意味です。上下どちらも拾うので閾値線は2本になります。片側だけ描くと「線を超えていないのに onset が立っている」ように見えます。

### 6-3. 既存コードから引き継ぐ描画の作法

- **波形は全体を渡し、表示範囲は `XLim` で決める。** 固定長で切り出すと、データ長を超えた試行が除外されて図が空になります（実際に起きた事故：`03_Analysis/技術説明.md` §3.3）。
- **値の再計算をしない。** `m3` が計算済みの波形（`Fz1Filt` など）をそのまま描きます。生データから描き直すとフィルタの有無で統計値と食い違います。
- **縦線・横線は既存の `lineplot.m` を使う。** `lineplot(0,'v','k--')` で `XLim`/`YLim` を保ったまま端から端まで線を引けます。
- 凡例は重ね描きの1本目にだけ `DisplayName` を付け、2本目以降は `'HandleVisibility','off'` にします。

### 6-4. 決着済みの論点：Nasu 方式の閾値の取得方法（案B・実装済み）

Nasu 方式の閾値 `thrVelHand` は `x4_analyze_single_trial.m` の第2パスで計算されますが、当初はローカル変数のまま捨てられており、可視化側が「検出に使われた閾値」を知る手段がありませんでした。

**採用（2026-08-20・案B）**：`x4` 側で全要素に保存する。

```matlab
[SingleTrialResultArray.ThrVelHandX] = deal(thrVelHand) ;
```

**採用理由**：可視化側で再計算する案（案A）では、母集団の定義（NoGo / Stop の除外・free を含めるか）が2か所に散らばり、片方だけ変更したとき**図の閾値と実際の閾値がエラーを出さずに静かにずれます**。図は「それらしく」見えるため発見が遅れます。

**実装状況**：`x4_analyze_single_trial.m` の100行目に実装済み（2026-08-25 確認）。閾値は `Result.ThrVelHandX` から読めるため、**呼び出し側に閾値を計算するコードは一切不要です。**

## 7. 関数の設計（3層構造）

実データ用の3本は、役割ごとに段違いに分けます。

| 層               | ファイル                | やること                                               | たとえるなら               |
| ---------------- | ----------------------- | ------------------------------------------------------ | -------------------------- |
| **指標層** | `plot_rt_detection.m` | 「反応時間を見るとは、どの信号を並べることか」を決める | 献立を決める人             |
| **汎用層** | `plot_time_series.m`  | 渡されたものを、ただ描く。指標名を一切持たない         | 言われたとおりに調理する人 |
| **変換層** | `time_from_cue.m`     | サンプル番号を秒に直す                                 | 単位を換算する道具         |

```
x5_check_single_trial_results.m      ← 試行ループ・保存の判断
        │  Data, Result, Prm を渡す
        ▼
plot_rt_detection.m                  ← どの信号を並べるかを定義
        │  波形・縦線・横線を秒単位で組み立てる
        ▼
plot_time_series.m ← time_from_cue.m ← 「描く」だけ
        │
        ▼
lineplot.m（既存）                    ← 縦線・横線の実描画
```

3層に分ける理由は、**「どの信号か」と「どう描くか」を分離する**ためです。他指標に応用するときに書き足すのは指標層だけで、汎用層・変換層は触らずに済みます。

### 要件（実データ適用時に満たすべき条件）

- [ ] R1. キューを時刻 0 とする秒単位の時間軸で波形を描ける
- [ ] R2. 任意の位置に縦線（イベント）を、ラベル付きで引ける
- [ ] R3. 任意の高さに横線（閾値）を、ラベル付きで引ける
- [ ] R4. サンプリング周波数の違う波形を同じ図に並べて、時間軸が揃う
- [ ] R5. 検出に失敗した試行（`TCueMarker` が NaN、`Fz1Filt` が空）でもエラーにならず、描けるものだけ描く
- [ ] R6. 波形・縦線・横線の中身を引数で差し替えられる（関数の中に「Fz1」「VelHandX」と書かない）
- [ ] R7. 複数の波形を1つの axes に重ねられる
- [ ] R8. 時刻 0 の基準を選べる（キュー基準／試行先頭基準／動作開始基準）
