## 4. 提案B：動作戦略・質の変化を捉える項目（研究の独自性が出る層）

### 4.1 試行間変動性（SD・変動係数）

- RT・バットスピード・ピークGRFそれぞれの**被験者内SD（またはCV）**を条件間比較する。
- 平均値が変わらなくても、認知負荷下では動作のばらつきが増えることが多い。
- 各条件10試行と少ないため、平均値より変動性の方がむしろ感度が高い可能性もある。

### 4.2 運動時間（Movement Time; MT）

- スイング開始→ピーク速度到達までの時間。
- RTとMTを分離することで、「反応は遅いがスイング自体は同じ」なのか「スイング自体も慎重になる」のかを区別できる。反応時間パラダイムの定番指標。

### 4.3 体重移動のタイミング

- 軸足Fzと踏み込み足Fzが交差する時刻（LED基準）。
- 条件によって「先に踏み込んで待つ」構えに変わるかを検出できる。フォースプレート2枚構成の強みを最大限使える項目。

### 4.4 CoP軌跡（範囲・移動速度）

- `Moment1`/`Moment2` データから計算可能。既にデータは取得済みのため追加コストが低い。

### 9.1 後方GRF・合成GRFのピーク値

**アルゴリズム**：実験室座標系は Y+ = 投手方向（`4.7_チェックスイング判定基準`で確定済み）。
「後方GRF」は床反力の捕手方向（Y−）成分、すなわち**踏み込み足で減速・ブレーキするときに床から返ってくる力**を指す。
Fyの負の成分の最大絶対値として取り出す。合成GRFは3軸のベクトル合成。

```matlab
% ---- 後方GRF（Backward GRF）----
Fy1 = Data.Force1(:, 2) ;    % 前後方向分力 [N]（列2 = Y成分）
Fy2 = Data.Force2(:, 2) ;

% Y+ = 投手方向なので、後方（捕手方向）成分は Fy < 0 の部分
% 負のピークの「大きさ」を正の値として記録する
peakFyBack1 = max(-Fy1(swingRange)) / bw ;   % [BW]
peakFyBack2 = max(-Fy2(swingRange)) / bw ;

% ---- 合成GRF（Resultant GRF）----
Fres1 = sqrt(sum(Data.Force1.^2, 2)) ;       % 3軸合成 [N]（samples×1）
Fres2 = sqrt(sum(Data.Force2.^2, 2)) ;

peakFres1 = max(Fres1(swingRange)) / bw ;    % [BW]
peakFres2 = max(Fres2(swingRange)) / bw ;
```

**注意点**：
- `load_qualisys_mat.m` 内で力の符号が反転されている（`force1 = -Data.Force(1).Force'`）。
  「Fy > 0 が本当に投手方向か」は、**静止した打者に前後へ体重をかけてもらう試技で必ず確認**すること。
- 文献によって「後方GRF」の定義（軸足の蹴り戻しか、踏み込み足のブレーキか）が異なるため、
  参照文献の定義確定後にどちらのプレートを主指標にするか決める。

### 9.2 力積（インパルス）とRFD

**アルゴリズム**：
- **力積** = 力の時間積分。数値積分には台形則（`trapz`）を使う。単位は BW·s。
- **RFD**（Rate of Force Development）= 力の時間微分の最大値。微分はノイズを増幅するため、
  **微分の前にローパスフィルタ（例：50Hz）をかける**。微分は既存の `diff3p`（3点中心差分）を流用。

```matlab
% ---- 前処理：GRFのローパスフィルタ（微分前に必須）----
fcGRF  = 50 ;                                  % カットオフ [Hz]（要検討）
[bF, aF] = butter(2, fcGRF/(fsAnalog/2)) ;
Fz2_filt = filtfilt(bF, aF, Fz2) ;

% ---- 力積：踏み込み足Fzのスイング窓内積分 ----
% 静止分（構え時の荷重）を引いた「増加分」の力積にすると条件間比較しやすい
Fz2_static  = mean(Fz2(1 : tCueAnalog-1)) ;                        % 静止期の荷重 [N]
dFz2        = Fz2_filt(swingRange) - Fz2_static ;                  % 増加分 [N]
impulseFz2  = trapz(dFz2) / fsAnalog / bw ;                        % [BW·s]

% ---- RFD：立ち上がり速度の最大値 ----
dFz2dt  = diff3p(Fz2_filt, 1/fsAnalog) ;                           % [N/s]
peakRFD = max(dFz2dt(swingRange)) / bw ;                           % [BW/s]
```

**解説（なぜ静止分を引くのか）**：構えの時点で既に踏み込み足に荷重がある被験者と、
軸足に荷重を残す被験者がいる。生のFzを積分すると「構えの荷重量」が力積に混入するため、
LED前の静止値を基準にした**変化量**で積分するほうが「スイングで新たに発揮した力」を表す。

### 9.3 体重移動タイミング（荷重交差時刻）

**アルゴリズム**：軸足Fz（プレート1）と踏み込み足Fz（プレート2）の大小が入れ替わる時刻を、
LED点灯を0として求める。1サンプルだけの瞬間的な交差（ノイズ）を拾わないよう、
**交差後50ms以上その状態が続く**ことを条件にする（デバウンス）。

```matlab
% ---- Fz1とFz2の交差検出 ----
minHold   = round(0.05 * fsAnalog) ;          % 50ms 継続を要求
isFront   = Fz2(swingRange) > Fz1(swingRange) ;   % 前足荷重が上回っているか

tCross = NaN ;
idx    = find(isFront, 1, 'first') ;
while ~isnan(idx) & ~isempty(idx)
    holdEnd = min(idx + minHold - 1, length(isFront)) ;
    if all(isFront(idx : holdEnd))
        tCross = idx ;                        % 条件を満たす交差点
        break
    end
    nextIdx = find(isFront(holdEnd+1 : end), 1, 'first') ;
    idx     = holdEnd + nextIdx ;
end

% LED基準の時刻 [ms]（負なら「LEDより前に踏み込んでいた」）
if ~isnan(tCross)
    tWeightTransfer = (swingRange(tCross) - tCueAnalog) / fsAnalog * 1000 ;
else
    tWeightTransfer = NaN ;
end
```

**解釈のポイント**：この値が条件間で変わる（例：Go/Nogoで遅くなる／自由スイングで
LED前に済んでいる）なら、「認知負荷が準備動作の戦略を変えた」ことの直接的な証拠になる。
自由スイング条件では、窓の始点をLEDではなくReady cueにするなどの調整が必要か検討すること。

### 9.4 バットヘッド線速度 [m/s]

**アルゴリズム**：既存の `PeakOmegaDeg` は角速度（バット長軸単位ベクトルの回転速度）。
現場・先行研究との比較には**ヘッドマーカー位置の並進速度**が使いやすい。
`m3_analyze_single_trial.m` と同じ前処理（NaN補間→フィルタ）の後、`top` マーカーを3点微分する。

```matlab
% （m3と同じ手順でM = filt_all_fields(...)まで済んでいる前提）
fs     = Data.FrameRate ;
r_top  = M.top ;                               % ヘッド側マーカー [nFrames × 3]

v_top     = diff3p(r_top, 1/fs) ;              % 速度ベクトル [nFrames × 3]
speed_top = sqrt(sum(v_top.^2, 2)) ;           % 速さ（スカラー）

% Qualisysの座標単位はmmが既定 → m/s に換算（要確認）
speed_top_ms = speed_top / 1000 ;

% スイング窓（マーカーフレーム基準）でのピーク
searchRange     = Result.TCueMarker : min(Result.TCueMarker + 2*fs, length(speed_top_ms)) ;
peakHeadSpeed   = max(speed_top_ms(searchRange)) ;                 % [m/s]
[~, iPeakLocal] = max(speed_top_ms(searchRange)) ;
tPeakSpeed      = searchRange(1) + iPeakLocal - 1 ;                % ピーク到達フレーム（9.5で使う）
```

**注意点**：`top` マーカーはバット先端そのものではないため、真のヘッドスピードより小さく出る。
剛体としての角速度×（回転中心からヘッドまでの距離）で補正する方法もあるが、
まずはマーカー位置の速度で条件間の**相対比較**をするのが安全。

### 9.5 運動時間（Movement Time; MT）

**アルゴリズム**：スイング開始（既存の `SwingOnset`、300 deg/s閾値）から
ピーク速度到達（9.4の `tPeakSpeed`）までの時間。RTと分離することで
「反応が遅い」のか「スイング自体が遅い」のかを区別する。

```matlab
if ~isnan(Result.SwingOnset) && ~isnan(tPeakSpeed)
    MT = (tPeakSpeed - Result.SwingOnset) / fs * 1000 ;            % [ms]
else
    MT = NaN ;
end
```

実装としては、`m3_analyze_single_trial.m` に `Result.TPeakSpeed` と `Result.MT` を
追加するのが最小変更で済む（x4→x6の流れにそのまま乗る）。

### 9.6 試行間変動性（SD・CV）

**アルゴリズム**：被験者×条件ごとに、試行方向の標準偏差（SD）と変動係数（CV = SD/平均）を計算する。
既存の `SingleTrialResultArray` から直接計算できるため実装コストが最も低い。

```matlab
% RTの例（PeakOmegaDeg・peakFz2なども同じパターン）
RT_sd = nan(1, nCondition) ;
RT_cv = nan(1, nCondition) ;

for iCondition = 1:nCondition
    rtAll = [SingleTrialResultArray(:, iCondition).RT] ;           % [1 × nTrial]
    rtOK  = rtAll(~isnan(rtAll)) ;
    if length(rtOK) >= 3                       % 有効試行が少なすぎる場合は算出しない
        RT_sd(iCondition) = std(rtOK) ;
        RT_cv(iCondition) = std(rtOK) / mean(rtOK) ;
    end
end
```

**統計上の注意**：SD・CVも被験者ごとに1値×4条件になるため、平均値と同じRM-ANOVAの枠組みで
検定できる。ただしSDは右に歪みやすいため、対数変換（`log(SD)`）してから検定することを推奨。

### 9.7 CoP軌跡（範囲・移動速度）

**アルゴリズム**：CoP（圧力中心）はモーメントと力から求まる。プレート表面（z=0）では
`CoPx = -My/Fz`、`CoPy = Mx/Fz`。Fzが小さいときは数値が発散するため、
**Fz > 閾値（例：体重の5%）のサンプルのみ**計算する。

```matlab
Mx1 = Data.Moment1(:, 1) ;   My1 = Data.Moment1(:, 2) ;

validIdx = Fz1 > 0.05 * bw ;                   % Fzが小さい区間は除外
copX = nan(size(Fz1)) ;
copY = nan(size(Fz1)) ;
copX(validIdx) = -My1(validIdx) ./ Fz1(validIdx) ;   % [m]（単位はモーメント次第・要確認）
copY(validIdx) =  Mx1(validIdx) ./ Fz1(validIdx) ;

% ---- スイング窓内の指標 ----
copXw = copX(swingRange) ;   copYw = copY(swingRange) ;

copRangeX = max(copXw) - min(copXw) ;          % 前後方向の移動範囲
copRangeY = max(copYw) - min(copYw) ;
copPath   = nansum(sqrt(diff(copXw).^2 + diff(copYw).^2)) ;        % 総軌跡長
copSpeed  = copPath / (length(swingRange) / fsAnalog) ;            % 平均移動速度
```

**注意点**：
- モーメントの単位（N·m か N·mm か）と、モーメントの基準点（プレート原点の高さオフセット）は
  **Bertecの仕様とQTMのエクスポート設定に依存する**ため、静止立位のCoPが足の位置と
  一致するかで必ず検証すること。
- 2枚のプレートをまたぐ「合成CoP」を出す場合は、各プレートのCoPを
  グローバル座標に変換してFzで重み付け平均する（プレート位置の座標が必要）。

### 9.8 抑制課題の指標（エラー率・停止時最大バット角度・post-error slowing）

#### (a) エラー率

**アルゴリズム**：既存の `CueText`（'Go'/'NoGo'）と `SwingOnset` を使う。
Nogo/Stop試行なのに `SwingOnset` が検出された（＝300 deg/s を超えた）試行をエラーと数える。

```matlab
nNogo      = 0 ;   % Nogo試行数
nNogoError = 0 ;   % うちスイングしてしまった数（commission error）

iCondition = 3 ;   % gonogo
for iTrial = 1:nTrial
    R = SingleTrialResultArray(iTrial, iCondition) ;
    if strcmp(R.CueText, 'NoGo')
        nNogo = nNogo + 1 ;
        if ~isnan(R.SwingOnset)
            nNogoError = nNogoError + 1 ;
        end
    end
end
errorRate = nNogoError / nNogo ;
```

> **精緻化**：単なる「動いたか」ではなく、(b)の最大バット角度が45°を超えたかで
> 判定するほうがMLB基準（4.7）と整合する。300 deg/s閾値は「動き始めたか」の検出であり、
> チェックスイング（途中で止めた）をエラーに数えるかどうかで結果が変わる点に注意。

#### (b) 停止時最大バット角度（連続量としてのチェックスイング指標）

**アルゴリズム**：`4.7_チェックスイング判定基準` のアルゴリズムをNogo/Stop試行に適用し、
二値判定ではなく**最大到達角度**そのものを従属変数にする。

```matlab
% 水平面バット角度：投手方向 [0,1] と バットベクトル(ノブ→ヘッド)のなす角
bat_vec_h = M.top(:, 1:2) - M.bottom(:, 1:2) ;                     % [nFrames × 2]
cosTheta  = bat_vec_h(:,2) ./ sqrt(sum(bat_vec_h.^2, 2)) ;         % 投手方向[0,1]との内積
batAngle  = acosd(cosTheta) ;                                      % [deg] 0°=投手方向

% Nogo/Stop試行のスイング窓内での最大角度…ではなく「最大どこまでバットが出たか」
% 4.7の定義では角度が小さいほど前に出ている（0°=完全に投手方向）ため、
% 「45°を下回った最小角度」を指標にする
minBatAngle = min(batAngle(searchRange)) ;     % [deg] 小さいほどバットが前に出た
isSwingByMLB = minBatAngle < 45 ;              % MLB基準でのスイング判定
```

**注意**：構え（バットが捕手側・上方）では角度が180°近くから始まる。
角度の基準・符号は `4.7_チェックスイング判定基準/技術説明.md` の座標系定義と
突き合わせて検証すること（特に左右打者の違い）。

#### (c) post-error slowing

**アルゴリズム**：エラー試行の**直後のGo試行**のRTと、正答試行の直後のGo試行のRTを比べる。

```matlab
rtAfterError   = [] ;
rtAfterCorrect = [] ;

for iTrial = 2:nTrial                          % 2試行目から（直前試行が必要）
    Rprev = SingleTrialResultArray(iTrial-1, iCondition) ;
    Rcurr = SingleTrialResultArray(iTrial,   iCondition) ;

    if ~strcmp(Rcurr.CueText, 'Go') || isnan(Rcurr.RT)
        continue                               % 現試行がGoでなければ対象外
    end

    prevWasError = strcmp(Rprev.CueText, 'NoGo') && ~isnan(Rprev.SwingOnset) ;
    if prevWasError
        rtAfterError   = [rtAfterError,   Rcurr.RT] ;
    else
        rtAfterCorrect = [rtAfterCorrect, Rcurr.RT] ;
    end
end

postErrorSlowing = mean(rtAfterError) - mean(rtAfterCorrect) ;     % [ms] 正なら減速
```

**制約**：各条件10試行・Nogo3試行ではエラー数自体が少なく、被験者単位では
算出できないことが多い。**全被験者をプールした探索的解析**と割り切ること。

### 9.9 実装時の共通注意事項（まとめ）

| # | 確認事項 | 確認方法 |
|---|---|---|
| 1 | マーカー座標の単位（mm/m） | 静止時のバット長（`norm(top-bottom)`）が実測値と合うか |
| 2 | Fyの符号（Y+ = 投手方向か） | 静止した被験者に前後へ体重をかけてもらう試技 |
| 3 | モーメントの単位・基準点 | 静止立位のCoPが足部の位置と一致するか |
| 4 | 自由スイング条件の窓の始点 | LEDでなくReady cue基準にすべきか要検討 |
| 5 | GRF微分前のフィルタ遮断周波数 | 残差分析または先行研究に合わせて決定 |

> これらのコードを実際にパイプラインへ組み込む際は、`m3_analyze_single_trial.m` への
> フィールド追加（TPeakSpeed・MTなど）→ x4〜x6 の再実行、という既存の流れに乗せるのが
> 最小変更で済む。組み込み作業を行う場合は改めて相談すること。
