## 3. RT 検出閾値の検証（2026-08-26）

本フォルダで最も時間をかけた検討。**結論から言うと、`dFx/dt` にピーク相対の閾値をかける当初の方式は破綻しており、`Fx` そのものに閾値をかける方式へ変更した。**

### 3-1. 当初の方式と、その結果

```matlab
jx = diff3p(fx, 1/analogFs) ;                  % Fx の時間微分
peakJx = max(jx(tGoStim:tFootContact)) ;
thresholdJx = peakJx * 0.2 ;                   % ピークの20%
% キュー直後から、最初に閾値を跨いだ点を onset とする（持続条件なし）
```

全300試行に適用した結果：

| 状態 | 試行数 |
| --- | --- |
| OK | 258 |
| NoLED（`ledData(:,2)>1` が空） | 25 |
| `filtfilt` が `mustBeFinite` で停止 | 15 |
| 空要素 | 2 |

OK の 258試行の RT 分布：**中央値 142 ms、150 ms 未満が 59%、50 ms 未満が 44試行。** ヒトの反応時間としてあり得ない。

### 3-2. 原因の切り分け

**(a) 閾値がベースラインノイズに埋もれている。** S05・simple・trial 7 で確認：

```
jx ベースライン(-0.5〜0s): mean = -100.1, SD = 229.2
thresholdJx = 311.7   ← ベースライン SD の 1.36 倍
ベースライン中に既に 32/499 サンプル (6.4%) が閾値超え
```

キュー前の「何も起きていない」区間ですら常時この閾値を跨いでいる。つまりループは動作開始ではなく**キュー後で最初に来たノイズの山**を拾っている。

**(b) `peakJx` が基準として不安定。符号すら一定しない。**

```
peakJx の範囲: -35 〜 5547
  S02: 被験者内 4.4倍   S01: 15.8倍   S03・S04: 符号をまたぐ
閾値 0.4×peakJx がキュー前ノイズSDの3倍に届かない試行: 84/258 (32.6%)
```

**★ 探索窓内で `jx` が一度も正にならない試行がある。** そのとき `thresholdJx` が負になり、`jx(k-1) < thr && jx(k) > thr` はキュー直後のノイズで即座に成立する。**これが RT < 50 ms が44試行出ていた主犯。**

**(c) 根本原因は「微分してから閾値をかけている」こと。** 微分はノイズの高周波成分を増幅する一方、スイング開始時の力の立ち上がりは緩やかなので `dFx/dt` のピークが小さい。結果として信号対雑音比が生の力より悪化する。本番解析（`03_Analysis`）が `Fz1` そのものを閾値判定に使っているのはこの理由。`Fz1` のベースライン SD は 17.6 N で、10SD でも 176 N の余裕がある。

### 3-3. グリッド探索の結果

比率4水準 × 持続窓4水準 × 探索方向2種で総当たりした。数値は RT 中央値、括弧内は RT<150ms の割合。

| --- | --- | --- | --- | --- |

| 0.3 | 162.0 (34.1%) | 169.0 (29.4%) | 170.0 (24.4%) | 172.5 (23.0%) |
| 0.4 | 176.0 (24.7%) | 179.0 (20.5%) | 181.5 (18.0%) | 182.0 (17.4%) |

### 3-4. 採用したパラメータと根拠

**Fx 基準・比率 0.20・持続 20 ms。**

1. **RT < 150 ms が 4.9%** — jx 最良（11.0%）の半分以下
2. **被験者内 SD が最小（48.8 ms）** — 比率を上げても下げても悪化する明確な谷
3. **条件順序が単調**（simple 190 < gonogo 199 < gostop 207.5）— 課題の複雑さの順と一致
4. **負ピークの試行がゼロ** — 符号の破綻が起きない

**★ 持続窓は 10/20/30 ms で結果がほぼ変わらない**（比率 0.20 では全て 210.0 ms）。Fx が滑らかで閾値を何度も跨がないため。jx では持続窓が結果を大きく動かしていたので、**この鈍感さ自体が Fx 基準の安定性の証拠**である。安全側として 20 ms を採用した。

**`|Fx - base|`（両方向）は不採用。** ベースラインのドリフトを拾って悪化した（RT<150 が 16.3%、被験者内SD 61.2 ms、条件順序も崩壊）。**正方向のみが正解。**

## 4. 採用案のコード

**2026-08-26 に `untitled.m` へ適用済み。** 以下は検出部の中核。

```matlab
%% ---- RT 検出：Fx のピーク相対閾値（20ms 持続）----
ratioFx = 0.20 ;
durMs   = 20 ;
nDur    = round(durMs/1000 * analogFs) ;

isBase  = tAnalog >= -0.5 & tAnalog < 0 ;
baseFx  = median( fx(isBase) ) ;              % SD は使わない
peakFx  = max( fx(tGoStim:tFootContact) - baseFx ) ;

if peakFx <= 0
    error('探索窓内で Fx が baseline を上回りません（要目視確認）') ;
end

thresholdFx = baseFx + peakFx * ratioFx ;
isOver = fx > thresholdFx ;

tOnsetFx = NaN ;
for k = tGoStim+1 : (tFootContact - nDur + 1)
    if ~isOver(k-1) && all( isOver(k : k+nDur-1) )
        tOnsetFx = k ; break
    end
end

if isnan(tOnsetFx)
    warning('RT onset 未検出（要目視確認）') ;
end
```

元コードからの変更点は3つ。

1. **`jx` ではなく `fx` を見る**（微分によるノイズ増幅を避ける）
2. **閾値を `baseFx` からの相対にする**（元コードは 0 からの相対だったので Fx のオフセットぶんずれていた）
3. **未検出時に `1` ではなく `NaN` を返す**（`1` だと RT が「試行先頭 − キュー」= 大きな負値になり、警告なしで結果に混ざる）

## 8. free と simple の onset は同じ局面か（2026-08-26、`check_onset_phase.m`）

§5 で「free は MT・Slope も他条件から大きく外れるため、onset が別の意味に
なっている可能性がある」と書いた点を検証した。**結論：同じ局面を捉えている。**
free は同じ形の運動を、単に遅いテンポでたどっているだけである。

### 8-1. 検証の方法

onset を時刻 0 にそろえて波形を重ねる。同じ局面を捉えているなら重なるはず。
さらに、時間を MT で正規化（0 = onset、1 = 最大速度）して重ね直す。
ここで重なれば「同じ局面を、違うテンポで」たどっていることになる。

### 8-2. onset 時点の状態

| 条件 | n | RT [ms] | onset時の速度 | ピーク比 | MT [ms] |
| --- | --- | --- | --- | --- | --- |
| free | 67 | 258.0 | 0.23 m/s | 0.8% | 710.0 |
| simple | 61 | 190.0 | 0.18 m/s | 0.6% | 553.0 |

**両条件とも、onset の時点でバットは実質的に静止している**（最大速度の 1% 未満）。
検出点が「動き出す前」を捉えている点で一致している。

### 8-3. 正規化波形のずれ

縦軸を 0〜1 に正規化したうえでの、条件間の中央値波形のずれ。

| 波形 | 区間 | 平均ずれ | 最大ずれ |
| --- | --- | --- | --- |
| バット先端速度 | onset近傍 (0〜0.5) | **0.003** | 0.007 |
| バット先端速度 | 立ち上がり (0〜1.0) | **0.032** | 0.155 |
| Fx | onset近傍 (0〜0.5) | 0.163 | 0.331 |
| Fx | 立ち上がり (0〜1.0) | 0.413 | 1.523 |

**バット先端速度は、時間を MT で正規化するとほぼ完全に重なる**（onset 近傍で 0.3%、
立ち上がり全体でも 3.2%）。free は simple の時間軸を引き伸ばしただけの形をしている。

Fx の onset 近傍のずれ 16% は、free の方が正規化後の水準がやや低いことによる。
0.7 以降の 0.413 という大きな値は、体重移動と前足接地による負の振れが `peakFx`
（接地前の立ち上がり幅）よりはるかに大きく、正規化が意味を失うために出るもので、
局面の一致・不一致の判断には使えない。

### 8-4. 結論と含意

- **onset の検出は条件によらず同じ局面を捉えている。** free の RT 258 ms・MT 710 ms・
  Slope 43.2 m/s² は検出のアーティファクトではなく、**実際に運動が遅い**ことを表す。
- したがって **MT と Slope は free を含めて条件間で比較してよい。**
- 一方 **RT は依然として free では意味を持たない。** 自己ペース条件でキューからの
  時間を測っているだけであり、「同じ局面を捉えている」こととは別の問題である。
