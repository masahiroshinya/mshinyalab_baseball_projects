## 1. まず解決すべき問題 ― 座標系が資料とデータで食い違っている

技術説明 4.7 は §3.0 で「**投手方向 = Y+**」を確定として、基準ベクトルを `[0, 1]` 固定にしている。
しかし予備実験（2026-0604）データで実測確認された座標系はこうなっている。

| 出典 | 投手方向 |
| --- | --- |
| `sandbox/4.7_チェックスイング判定基準/技術説明.md` §3.0 | **Y+** |
| `01_スイングスピード解析し直し.md` §8.5（s3b で両被験者 40/40 実測） | **X+** |
| `m3_analyze_single_trial.m` L32 のコメント | **X+** |

**技術説明のコードをそのまま予備実験データに流すと、判定軸が 90 度ずれる。**
つまり `ref_vec_h = [0, 1]` は予備実験データでは使えない。

### なぜ食い違うのか（推定）

技術説明 §3.0 の「Y+ = 投手方向」は、**本実験でこれからそう校正する**という取り決めであって、
予備実験のときの校正結果ではない。§3.2 に「キャリブレーション時に L 字フレームの Y 軸が
投手方向を向くように設置することが唯一の条件」とあるのがその証拠で、**未来の指示**として書かれている。
一方 s3b は 2026-0604 に実際に取れたデータを検算したもの。両方とも正しく、指している時点が違う。

### この文書での方針

**軸の割り当てをコードに直書きせず、`parameters.m` の設定値にする。**
そうすれば予備実験（X+ = 投手）でも本実験（Y+ = 投手）でも、判定式を一切書き換えずに済む。

```matlab
Prm.CS.AxisFwd = 1 ;   % 予備実験 2026-0604 は 1(=X)。本実験で Y+ 校正なら 2 に変えるだけ
```

## 2. もうひとつの未確定事項 ― 左右どちら側がスイング側か

技術説明 §3.3 ステップ4 は、右打者のスイング側を X+（一塁側）としている。
これは「Y+ = 投手方向」の座標系での話なので、予備実験（X+ = 投手方向）では
**左右方向は Y 軸**になり、しかも **Y+ と Y− のどちらが一塁側かは、まだ誰も確認していない。**

s3b が確認したのは「投手–捕手方向の軸と符号」だけで、左右の符号は手つかず。
`sandbox/5.3_解析項目提案/予備実験検証用_新規指標コード.md` L736 で
「9.8(b) 停止時最大バット角度は、4.7 の座標系の符号を確定してから追加するのが安全」
として保留されているのも、まさにこの点。

→ **最初に書くべきスクリプトは判定本体ではなく、左右符号を実測で決める `s4a`。**

### 予備実験には打者の左右打の記録がない

`Experiments/Main experiments/Protocol/技術説明.md` L80 で、本実験では基礎情報として
利き手を記録する手順になっているが、**予備実験（2026-0604）には被験者 S01/S02 の左右打の記録が見当たらない。**

ただし予備実験の目的は判定式の検証なので、**利き手そのものは要らない。**
「その被験者がどちら側に振ったか」をデータから決めれば、閾値 45° の妥当性は検証できる。
利き手の a priori な記録が必須になるのは本実験から（→ §7 の申し送り）。

## 3. 判定式 ― 技術説明の実装を1本の符号付き角度にまとめる

技術説明 §3.3 は「角度 θ（常に正）」と「スイング方向フラグ `is_swing_direction`」の
2つを組み合わせて判定している。これは **符号付き角度 1 本**にまとめられる。

```matlab
thetaSwing = atan2d( sSwing * vLat , vFwd ) ;
```

| 記号 | 意味 |
| --- | --- |
| `vFwd` | バットベクトル（ノブ→ヘッド）の**投手方向成分** |
| `vLat` | 同じく**打者の左右方向成分** |
| `sSwing` | スイング側が `vLat` の +1 側か −1 側か（§2 で実測して決める） |

`atan2d` の返り値がそのまま「投手方向を 0°、スイング側を正」とした角度になる。

- 反スイング側に倒れている（構え・ローディング）→ **負の角度**になるので、
  `max` を取れば自然に除外される。技術説明の `is_swing_direction` チェックが不要になる。
- 判定は `max(thetaSwing) > 45` の一行で済む。

> **技術説明のコードにあった細かい点：**
> `cos_theta = dot(bat_vec_h, ref_vec_h) / norm(bat_vec_h)` は、`ref_vec_h` が単位ベクトル
> （`[0,1]`）だから成り立っている式で、本来は `norm(ref_vec_h)` でも割る必要がある。
> `atan2d` 方式ならこの落とし穴自体が無くなる。

### 探索範囲は試行全体ではなくキュー後の窓にする

技術説明 §4 は「1試行分の時系列データ全体のピーク値を使用する」としているが、
予備実験データは**試行の前後に構え直しや素振りが入り得る**。
RT 検出（`Prm.RT.WinSec = 2.0`）と揃えて、**キューから 2 秒**の窓に限定する。

## 5. コード案

### 5.1 `parameters.m` への追記

```matlab
%% m3_analyze_single_trial: チェックスイング判定（4.7 の 45度基準）
% 軸の割り当ては計測ごとの校正で変わるため、ここで設定する（02 §1）。
Prm.CS.AxisFwd   = 1 ;      % 投手方向の軸番号  1=X, 2=Y。2026-0604 は X+（s3b 実測）
Prm.CS.AxisLat   = 2 ;      % 打者の左右方向の軸番号（AxisFwd と直交する水平軸）
Prm.CS.SignSwing = NaN ;    % スイング側が AxisLat の +1 側か -1 側か。★s4a で実測して埋める
Prm.CS.ThetaDeg  = 45 ;     % スイング判定の閾値 [deg]（MLB 準拠）
Prm.CS.WinSec    = 2.0 ;    % キュー起点の探索窓 [s]（RT.WinSec と揃える）
```

> `SignSwing` を `NaN` のままにしておくと、s4a を通す前に m3 を回したときに
> 判定結果が NaN になり、**確定前の値をうっかり使ってしまう事故を防げる。**

### 5.2 `check_swing_angle.m`（共通関数）

```matlab
function thetaSwing = check_swing_angle(headPos, knobPos, Prm)
% バットの水平面角度を「投手方向 = 0°、スイング側 = 正」で返す。
%
%   headPos, knobPos : Nx3 のマーカー座標（top / bottom）。単位は問わない（方向のみ使用）
%   thetaSwing       : Nx1 [deg]。-180〜180。45 を超えたフレームがあれば SWING
%
% 4.7_チェックスイング判定基準/技術説明.md の判定式を、符号付き角度 1 本にまとめたもの（02 §3）。

f = Prm.CS.AxisFwd ;
l = Prm.CS.AxisLat ;

vFwd = headPos(:, f) - knobPos(:, f) ;   % 投手方向成分
vLat = headPos(:, l) - knobPos(:, l) ;   % 左右方向成分（スイング側が正になるよう符号を掛ける）

thetaSwing = atan2d(Prm.CS.SignSwing * vLat, vFwd) ;

end
```

### 5.3 `s4a_check_bat_lateral_axis.m` ― 左右符号を実測で決める

s3b（投手方向の符号確定）と同じ考え方で、**互いに独立な手がかり**を突き合わせる。

```matlab
% s4a_check_bat_lateral_axis.m
% 目的：バットの「スイング側」が横軸(AxisLat)の +1 側か -1 側かを実データで確定する。
%       確定した値は parameters.m の Prm.CS.SignSwing に書き込む。
% カレントは 2026-0604/MATLAB にすること。

clear ; close all ; clc

CONDITIONS = [1 2] ;              % free / simple。確実にフルスイングする条件だけ使う
ConditionNameArray = {'free','simple','gonogo'} ;
Prm = parameters ;
f = Prm.CS.AxisFwd ;
l = Prm.CS.AxisLat ;

for iSubject = 1:2
    load(sprintf('x3_DataChecked/Data%02d', iSubject))
    load(sprintf('x4_SingleTrialAnalysisResults/SingleTrialAnalysisResults%02d', iSubject))

    nTrial = size(DataArray, 1) ;
    cue1 = [] ;   % 手がかり1：ピーク速度時の vLat の符号
    cue2 = [] ;   % 手がかり2：スイング中の回転方向

    for iCondition = CONDITIONS
        for iTrial = 1:nTrial
            D = DataArray(iTrial, iCondition) ;
            R = SingleTrialResultArray(iTrial, iCondition) ;
            if ~isfield(D,'Markers') || isnan(R.TPeakVelTop), continue, end

            vFwd = D.Markers.top(:, f) - D.Markers.bottom(:, f) ;
            vLat = D.Markers.top(:, l) - D.Markers.bottom(:, l) ;
            k    = R.TPeakVelTop ;                    % 合成速度ピークのフレーム

            % ---- 手がかり1：ピーク速度の瞬間、ヘッドは体の前方＝スイング側に出ている ----
            cue1(end+1) = sign(vLat(k)) ;             %#ok<SAGROW>

            % ---- 手がかり2：スイング中は角度が一方向に回り続ける。その回転の向き ----
            %  生の角度（符号補正なし）をアンラップして、ピーク前後 100 ms の変化量を見る
            phi  = unwrap(atan2(vLat, vFwd)) ;
            nWin = round(0.1 * D.FrameRate) ;
            a = max(k-nWin, 1) ;  b = min(k+nWin, numel(phi)) ;
            cue2(end+1) = sign(phi(b) - phi(a)) ;     %#ok<SAGROW>
        end
    end

    fprintf('\n===== Subject %02d （free + simple, n=%d 試行）=====\n', iSubject, numel(cue1)) ;
    fprintf('手がかり1  ピーク速度時の vLat 符号 : +1 が %2d / -1 が %2d\n', ...
        sum(cue1>0), sum(cue1<0)) ;
    fprintf('手がかり2  スイング中の回転の向き   : +1 が %2d / -1 が %2d\n', ...
        sum(cue2>0), sum(cue2<0)) ;
    fprintf('→ 一致していれば、その符号が Prm.CS.SignSwing\n') ;
end
```

**読み方**

- 2つの手がかりが**同じ符号に揃い、かつ試行のほぼ全部でその符号**なら、それが `SignSwing`。
- 手がかり1と2が食い違う、あるいは被験者間で符号が逆になる場合：
  - **被験者間で逆になるのは異常ではない**（右打者と左打者が混在していればそうなる）。
    その場合は `Prm.CS.SignSwing` を被験者ごとに持たせる必要がある（→ §7）。
  - 同一被験者内で割れる場合は、`AxisLat` の指定か `TPeakVelTop` の妥当性を疑う。

> **s3b の教訓：** 「構えではバットは捕手側に倒れている」という思い込みが実測で外れた（01 §[2026-07-16]）。
> ここでも**構えの姿勢を手がかりに使わない**のはそのため。使うのはスイング動作そのものだけ。

### 5.4 `s4b_check_swing_angle.m` ― 角度波形の目視と最大角度の分布

`SignSwing` が確定してから実行する。

```matlab
% s4b_check_swing_angle.m
% 目的：① 角度の時系列にキュー・45度線・最大点を重ねて目視する
%       ② 全試行の最大角度を条件別に並べ、45度で二値化したときの分離を見る
% カレントは 2026-0604/MATLAB にすること。

clear ; close all ; clc

SUBJECT = 1 ;
TRIALS  = [1 5 10 15] ;           % 目視する試行
ConditionNameArray = {'free','simple','gonogo'} ;
Prm = parameters ;

if isnan(Prm.CS.SignSwing)
    error('Prm.CS.SignSwing が未確定です。先に s4a を実行してください。') ;
end

load(sprintf('x3_DataChecked/Data%02d', SUBJECT))

% ---------- ① 角度波形の目視（gonogo 条件）----------
iCondition = 3 ;
figure('Name', 'バット水平角度と 45 度線')
for i = 1:numel(TRIALS)
    iTrial = TRIALS(i) ;
    D = DataArray(iTrial, iCondition) ;

    theta = check_swing_angle(D.Markers.top, D.Markers.bottom, Prm) ;

    % キューをマーカーのフレーム番号に直す（m3 と同じ換算）
    tCueA = find(D.LEDData(:,2) > 2, 1, 'first') ;
    if isempty(tCueA), tCueA = find(D.LEDData(:,2) < -1, 1, 'first') ; end
    if isempty(tCueA), continue, end
    tCue = round(tCueA / D.AnalogFs * D.FrameRate) ;

    t = ((1:numel(theta))' - tCue) / D.FrameRate * 1000 ;   % キューを 0 ms とする

    subplot(numel(TRIALS), 1, i)
    plot(t, theta, 'k') ; hold on
    yline(Prm.CS.ThetaDeg, 'r--', '45°') ;
    yline(0, 'b:', '投手方向') ;
    xline(0, 'g-', 'LineWidth', 1.5) ;

    w = tCue : min(tCue + round(Prm.CS.WinSec * D.FrameRate), numel(theta)) ;
    [maxTheta, k] = max(theta(w)) ;
    plot(t(w(k)), maxTheta, 'mo', 'MarkerFaceColor', 'm') ;

    xlim([-500 2000]) ; ylabel('角度 [deg]') ; grid on
    title(sprintf('Trial %d : 最大 %.0f° → %s', iTrial, maxTheta, ...
        ternary(maxTheta > Prm.CS.ThetaDeg, 'SWING', 'NO SWING'))) ;
end
xlabel('キューからの時間 [ms]') ;

% ---------- ② 全試行の最大角度の分布 ----------
nTrial = size(DataArray, 1) ;
maxAll = nan(nTrial, 3) ;
cueAll = cell(nTrial, 3) ;

for iCondition = 1:3
    for iTrial = 1:nTrial
        D = DataArray(iTrial, iCondition) ;
        if ~isfield(D,'Markers') || isempty(D.Markers), continue, end

        theta = check_swing_angle(D.Markers.top, D.Markers.bottom, Prm) ;

        tCueA = find(D.LEDData(:,2) > 2, 1, 'first') ;
        cueAll{iTrial, iCondition} = 'Go' ;
        if isempty(tCueA)
            tCueA = find(D.LEDData(:,2) < -1, 1, 'first') ;
            cueAll{iTrial, iCondition} = 'NoGo' ;
        end
        if isempty(tCueA), cueAll{iTrial, iCondition} = '' ; continue, end

        tCue = round(tCueA / D.AnalogFs * D.FrameRate) ;
        w    = tCue : min(tCue + round(Prm.CS.WinSec * D.FrameRate), numel(theta)) ;
        maxAll(iTrial, iCondition) = max(theta(w)) ;
    end
end

figure('Name', '最大角度の分布')
hold on
for iCondition = 1:3
    isNoGo = strcmp(cueAll(:, iCondition), 'NoGo') ;
    plot(iCondition * ones(sum(~isNoGo),1), maxAll(~isNoGo, iCondition), 'ko') ;
    plot(iCondition * ones(sum( isNoGo),1), maxAll( isNoGo, iCondition), 'r^', ...
        'MarkerFaceColor', 'r') ;
end
yline(Prm.CS.ThetaDeg, 'r--', '45°') ;
xlim([0.5 3.5]) ; xticks(1:3) ; xticklabels(ConditionNameArray) ;
ylabel('キュー後 2 秒の最大角度 [deg]') ; grid on
title(sprintf('Subject %02d：○ = Go, ▲ = NoGo', SUBJECT)) ;

function out = ternary(cond, a, b)
if cond, out = a ; else, out = b ; end
end
```

**この図で確認すること**

| 見るところ | 期待 | 外れたときに疑うこと |
| --- | --- | --- |
| Go 試行（○）の最大角度 | **全部 45° を大きく超える**（フルスイングなので 90°以上に達するはず） | `SignSwing` の符号、`AxisFwd/AxisLat` の割り当て |
| NoGo 試行（▲）の最大角度 | **抑制成功なら 45° 未満**に落ちる | 予備実験の NoGo は 5 試行/被験者と少ない（5.3 §5）ので、外れ値の解釈は慎重に |
| 45° 付近に試行が集まるか | 集まっていなければ、**閾値の位置は結論を左右しない**＝頑健 | 集まっている場合は §6 の感度分析が必須 |

## 6. m3 への組み込み案

`m3_analyze_single_trial.m` の `tCueMarker` を求めた直後（現行 L77 の後）に挿入する。
Go / NoGo どちらでも判定するので、RT 検出（Go 限定）より前に置く。

```matlab
% ---- チェックスイング判定（4.7 の 45 度基準。02 §3）----
%  バットの水平面角度を「投手方向 = 0°、スイング側 = 正」で表し、
%  キュー後 WinSec 秒の最大角度が閾値を超えたらスイングとみなす。
%  Go/NoGo 双方で算出する（NoGo での抑制失敗＝commission error の判定に使う）。
Result.MaxSwingAngle = NaN ;   % [deg] キュー後の最大角度
Result.TMaxSwingAngle = NaN ;  % そのフレーム番号（試行先頭から）
Result.IsSwing        = NaN ;  % 1 = SWING, 0 = NO SWING

if ~isnan(Prm.CS.SignSwing)
    theta = check_swing_angle(M.top, M.bottom, Prm) ;
    w     = tCueMarker : min(tCueMarker + round(Prm.CS.WinSec*fs), numel(theta)) ;
    [maxTheta, k] = max(theta(w)) ;

    Result.MaxSwingAngle  = maxTheta ;
    Result.TMaxSwingAngle = w(k) ;
    Result.IsSwing        = double(maxTheta > Prm.CS.ThetaDeg) ;
end
```

- **フィルタ後の `M` を使う**（生の `Data.Markers` ではなく）。m3 は L23 で NaN 補間 + 30 Hz
  ローパス済みの `M` を作っているので、それに乗る。
- `SignSwing` が未確定なら全部 NaN で通過する。s4a を通す前に誤った値が下流に流れない。

## 9. 作業記録

### [2026-07-28] 実装環境の設計（本文書の作成）

技術説明 4.7 を実データに落とすにあたり、**座標系が資料（Y+ = 投手）と予備実験データ
（X+ = 投手、s3b 実測）で食い違っている**ことが判明した。技術説明の `ref_vec_h = [0,1]` を
そのまま使うと判定軸が 90 度ずれる。

対応として、軸の割り当てを `Prm.CS.AxisFwd` / `Prm.CS.AxisLat` の設定値に外出しし、
予備実験・本実験のどちらでも同じ判定式が使えるようにした。

あわせて、**左右どちら側がスイング側かは s3b でも確認されていない**ことが分かった。
これは 5.3 §5 L736 で「9.8(b) を保留」とした理由そのもの。実測で決める `s4a` を最優先とする。

判定式は、技術説明の「正の角度 θ ＋ 方向フラグ」を **符号付き角度 1 本（`atan2d`）** に
まとめ直した。反スイング側が負になるため方向フラグが不要になり、
技術説明のコードにあった `norm(ref_vec_h)` で割り忘れる形の式も回避できる。
