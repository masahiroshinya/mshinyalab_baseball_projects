## 1. 実験概要_被験者募集用 の作り方

`IC書類.pdf` の記載（研究者連絡先・リスク・個人情報の取扱い・撤回・問い合わせ先）を土台に、募集段階向けに再構成したもの。構成は次の9章。

1. 研究名 / 2. 研究者 / 3. 研究目的 / 4. 実験の方法（4.1 概要・4.2 場所・4.3 実験条件4条件・4.4 試行数・4.5 プロトコールと所要時間）/ 5. 想定されるリスク / 6. 個人情報の取扱い / 7. 参加およびデータ利用の撤回 / 8. 謝礼 / 9. 問い合わせ先

docx は Word で直接編集したものではなく、**python-docx のスクリプト（`make_recruit_docx.py`）で生成している。** 文面を直すときは docx を手で直すよりスクリプトを直して再生成するほうが、レイアウトが崩れず確実。

> **注意（2026-07-30 時点）**：生成スクリプトはセッション用スクラッチパッドに置いたままで、このリポジトリには保存していない。docx 本体もフォルダに残っていない（PDF のみ）。文面を修正する予定があるなら、スクリプトをこのフォルダか `Script/` に保存し直すこと。

### レイアウト設定（最終版）

| 項目 | 値 |
| --- | --- |
| 用紙余白 | 上下 1.8 cm、左右 1.9 cm |
| 本文フォント | 游明朝 10.5 pt（`w:ascii` / `w:hAnsi` / `w:eastAsia` の3つを設定する必要がある） |
| 見出しフォント | 游ゴシック（H1 14 pt / H2 11.5 pt / H3 10.5 pt、太字） |
| 行間 | 1.05（本文・箇条書き共通） |
| 段落後のアキ | 本文 3 pt、箇条書き 1 pt |
| 見出し前後のアキ | H1 11/4 pt、H2 8/3 pt、H3 6/2 pt |
| 表 | `Table Grid`、フォント 9.5 pt、ヘッダ行は網掛け `E8EDF5` |
| 改ページ | 表紙の後、および「5. 想定されるリスク」の前 |
| 目次 | なし（2026-07-30 に削除） |

この設定で全8ページ（表紙1＋本文7）。

### 日本語フォント指定の注意

python-docx で `style.font.name` を設定するだけでは日本語（East Asian）文字にフォントが適用されない。`rPr` の `w:rFonts` に `w:eastAsia` を明示的にセットする必要がある。

```python
rpr = style.element.get_or_add_rPr()
rfonts = rpr.find(qn("w:rFonts"))
if rfonts is None:
    rfonts = OxmlElement("w:rFonts")
    rpr.append(rfonts)
for attr in ("w:ascii", "w:hAnsi", "w:eastAsia"):
    rfonts.set(qn(attr), "游明朝")
```

## 2. docx → PDF 変換

**この環境に LibreOffice（`soffice`）は入っていない。** Microsoft Word を AppleScript で駆動して変換する。

```bash
osascript -e 'with timeout of 540 seconds
tell application "Microsoft Word"
  set inPath to "…/実験概要_被験者募集用.docx"
  set outPath to "…/実験概要_被験者募集用.pdf"
  open (POSIX file inPath)
  set theDoc to active document
  save as theDoc file format format PDF file name outPath
  close theDoc saving no
end tell
end timeout'
```

### 変換後の確認方法

PyMuPDF（`fitz`）が使える。ページ数・各ページの本文範囲を確認できるので、レイアウトの詰め具合を数値で判断できる。

```python
import fitz
d = fitz.open("実験概要_被験者募集用.pdf")
print(d.page_count)
for i, p in enumerate(d, 1):
    blocks = [b for b in p.get_text("blocks") if b[3] < 740]   # ページ番号を除外
    print(i, max(b[3] for b in blocks), "/ 792")               # 本文終端y / 用紙高
```

1ページ目の見た目だけを素早く確認したいときは `qlmanage -t -s 1200 -o . file.pdf` でサムネイル画像が作れる（1ページ目のみ）。

## 3. トラブルシューティング

### AppleEvent タイムアウト（-1712）

**症状**：2回目以降の変換で `Microsoft Wordでエラーが起きました: AppleEventがタイムアウトしました。 (-1712)` が返る。PDF は出力されない。

**原因**：
1. AppleEvent の既定タイムアウトが60秒で、Word の起動＋ページ描画＋PDF 書き出しがこれを超えることがある。
2. 前回の変換で Word のプロセスが残っており、文書が開いたままだと `active document` の取得やダイアログ待ちで処理が止まる。

**対処**：Word を一度終了させ、`with timeout of ... seconds` で囲んで再実行する。

```bash
osascript -e 'tell application "Microsoft Word" to quit saving no'
# その後、上記の with timeout 付きスクリプトを実行
```

なお、初回実行時は macOS の自動化（Automation）許可ダイアログが出ることがある。許可しないと以降の `osascript` はすべて失敗する。

### 行間・余白を詰めてもページ数が減らない場合

段落設定を詰めても、改ページ指定と表の分割位置で決まってしまうことがある。上記の PyMuPDF スクリプトで各ページの本文終端 y を見て、**どのページに余裕があるのか**を確認してから手を入れる。最終ページにわずかな残りしか載っていない場合は、段落の詰めよりも「不要なページ（目次など）を削る」「表が分割されないようにする」ほうが効く。
